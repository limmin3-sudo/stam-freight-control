# STAM FREIGHT CONTROL

Star Citizen 비공식 비영리 운송 관제입니다. 게임에서 받은 계약을 읽어 **방문 순서와 배송지별 적재 계획**을 준비합니다.

[운송 관제](https://limmin3-sudo.github.io/stam-freight-control/) · [Windows 앱](https://limmin3-sudo.github.io/stam-freight-control/download.html) · [단계별 이용안내](https://limmin3-sudo.github.io/stam-freight-control/guide.html) · [패치노트](https://limmin3-sudo.github.io/stam-freight-control/patch-notes.html)

## 처음 실행하기

1. Windows 앱 ZIP을 새 폴더에 **전부** 풀고 `STAM.exe`를 실행하세요. Windows 10/11 x64용이며 Node 설치나 관리자 권한은 필요하지 않습니다.
2. 앱 오른쪽 위에서 **한국어 / English**를 고르고 `StarCitizen/LIVE/Game.log`를 선택하세요. 파일 확장명이 숨겨져 있으면 **Game**으로 보입니다.
3. 열린 관제에서 파트너를 고르고 함선·출발지·Quantum Drive를 확인하세요.
4. 게임에서 운송 계약을 받으세요. 현재 로그에 남아 있는 기존 계약도 처음 연결할 때 읽습니다.
5. **항로 계산·안내 시작**을 누르세요. 양쪽 사이드바에서 계약과 방문 순서를, 가운데 지도와 아래 적재 3D에서 항로와 화물을 확인합니다.

연결 앱은 최소화해 두세요. 닫으면 로그 수신이 종료됩니다. 연결 주소의 임시 키는 공유하지 마세요. 웹사이트만 열어 선택한 로그 파일은 한 번 재생하며, 실시간 연동에는 앱을 사용합니다.

## 운송 중

- **브리지 오퍼레이터**는 가까운 계약 완료를, **수석 항해사**는 묶음 수거와 재방문 감소를 우선합니다.
- 미션이 달라도 같은 배송지의 화물을 가까이 모읍니다. 계약·품목·상자의 귀속은 유지합니다.
- 크기별 개수가 없으면 **적재 공간 가이드**를 표시합니다. 66 SCU는 32+32+2처럼 공간을 잡을 수 있지만, 실물 상자 세 개라는 뜻은 아닙니다.
- 정확한 구성은 화물 확인에서 입력하세요. 같은 유형·게임 버전에서 직접 확인했던 구성은 불러와 적용할 수 있습니다.
- 냉동포드는 개당 1 SCU, 반 높이와 긴 바닥면을 유지합니다. 같은 총량이어도 실제 형태가 들어가지 않으면 적재 가능으로 계산하지 않습니다.
- 새 계약은 **현재 항로에 추가 / 다음 계획으로 보관** 중 선택합니다. 제외할 때는 남은 화물을 확인하며, 이미 실린 자리는 재계산해도 유지합니다.
- 부분 적재·배송과 잘못 기록한 배송의 되돌리기를 지원합니다. STAM에서 기록한 조작은 게임을 대신 조작하지 않습니다.

부족한 계약 정보는 **계약 보완 · 직접 추가**에서 해당 계약을 골라 보완하세요. 이미 확인된 품목·총량·거점은 채워 두며, 스크린샷·텍스트도 보조 입력으로 사용할 수 있습니다. OCR 화면 감시는 직접 켰을 때만 선택 영역을 읽습니다.

## 저장과 업데이트

로그인하면 함선 설정·계약 보완·상자 구성·실린 화물·잔여 화물·선택 계약·안내 구간·완료 및 지급 기록을 계정에 보관합니다. 다른 PC에서는 로그를 연결하고 동일 계약을 다시 읽어 이어갑니다. 두 기기에서 수정한 기록은 선택 없이 덮어쓰지 않습니다. 로그인하지 않으면 현재 브라우저에 저장합니다.

**운항 기록**에서 완료 계약과 연결된 지급을 확인할 수 있습니다. ID가 없는 지급은 완료 계약을 직접 골라 연결하며, 예전 수동 운항의 입력 보상과 중복 합산하지 않습니다. 원문 로그·연결 키·플레이어 식별자는 계정으로 전송하지 않습니다.

상단 **백업·복원**으로 구조화된 기록을 파일에 보관할 수 있습니다. 복원 전 현재 기록을 백업하세요. 사이트와 로컬 관제는 브라우저 저장 공간이 서로 다르므로 계정이나 백업으로 옮깁니다.

**사이트와 앱은 따로 업데이트합니다.** 화면·경로·적재 기능은 앱이 검증한 사이트 자원을 받아 다음 실행부터 적용합니다. 운송 도중 화면을 강제로 바꾸지 않습니다. 연결 앱 자체 업데이트가 필요한 경우에만 새 ZIP을 받으세요. 다운로드 실패 시 기존 관제를 유지합니다.

## 확인 범위

공개 미션 목록과 실행 계약 ID는 다릅니다. 로그가 남기지 않은 품목·배분·배송지를 ID 하나로 만들어 내지 않습니다. 확인된 정보로 자동 계획하고, 상자 구성만 없으면 공간 가이드를 쓰며, 필요한 항목은 해당 계약에서 보완합니다. 과거 파일에만 있거나 게임에서 기록하지 않은 계약은 현재 로그만으로 복원할 수 없습니다.

자동 검사·브라우저·Windows 실행 검사와 실제 게임 검증을 구분합니다. 실제 PC에서의 연속 수락·파티 계약·게임 재접속·성능은 [최종 확인 목록](docs/FINAL-GAME-VALIDATION.md)에 정리합니다.

## 개발

Node.js 22 이상에서:

```sh
node scripts/prepare.mjs
npm test
node scripts/log-link.mjs --help
```

Windows 소스 실행은 `start-log-link.cmd`, 앱 ZIP 사용자는 `STAM.exe`를 사용합니다.
