# 계약 수량의 확인 범위

2026-11-06 사용자 결정: OCR로 수량을 보완하거나, 지난 계약의 수량·상자 구성을 새 계약에 재사용하지 않는다. 직접 입력은 선택사항이다.

- **상자 구성 확인**: 실제 총 SCU와 상자 크기별 개수가 있다. 해당 구성으로 적재한다.
- **총수량 확인**: 실제 총 SCU만 있다. 명세의 상자 한도 또는 기존 가정값으로 상자 배치를 예상한다.
- **최대치 기준**: 실제 수량은 없다. 사용자가 수신함의 최대치 옵션을 허용하면 공개 명세의 각 운송 행 상한을 공간 예약에 사용한다. `_scuEstimated:true`를 유지하며 카드·계약·계산 상태·3D 제목에 예상 상태를 표시한다. 확정 수량을 최대치로 덮어쓰지 않는다.

예: 알루미늄 픽업 3곳, 각 2–10 SCU이면 상한 예약은 30 SCU다. 이는 실제 30 SCU를 받았다는 뜻이 아니며, 정확한 상자 분포나 실제 선내 배치를 보장하지 않는다. 데이터에 상한이 없거나 물품 개수를 SCU로 변환할 규격이 없으면 임의의 SCU를 만들지 않는다. 위치가 확인되면 방문 순서만 별도로 미리 볼 수 있다. 이 미리보기는 현재 운송 계획이나 진행을 변경하지 않는다.

2026-11-07 사용자 최종 결정에 따라 미션 자료는 SCMDB만 사용한다. 최초 LIVE12913470 묶음의 화물 정의864개에 있는 일반 자원 운송 행1,622개에는 모두 고정 쿼터 또는 양의 SCU 상한이 있다. 개수 단위 물품 행443개는 일반 SCU와 구별한다. 이 숫자는 해당 묶음 기준이며 모든 새 계약·향후 패치의 상한을 보장하지 않는다. SCMDB에 명세가 없거나 규격이 모호하면 실제 입력을 받고, 다른 Wiki 정의로 채우지 않는다. 자동 갱신은 [미션 자료 안내](MISSION-DATA-RECONCILIATION.md)를 따른다.

## OCR 없이 실제 가변 수량을 얻는 경로

우선순위는 같은 **계약 인스턴스 ID와 목표 ID**에 연결된 실제 `New Objective … SCU` 기록이다. 다른 계약의 동일 목표 ID, 과거 같은 제목의 수량, 목록의 최댓값은 실제 수량의 증거로 사용하지 않는다. 관측이 나중에 도착해도 이미 저장한 계획을 자동으로 덮어쓰지 않는다. 수신 카드를 다시 선택해 계산할 때 잠정값을 갱신하며, 기존 직접 입력은 유지한다.

[SC Hauling Tools의 개발자 안내](https://sc-hauling.tools/)는 기존 계약의 추적을 해제한 뒤 다음 계약을 수락해야 목표 문장이 기록된다고 설명한다. [SC Tracker의 개발자 문서](https://github.com/verdantnebula/sc-tracker#known-caveat--intermittent-new-objective-suppression)는 같은 종류에서도 수량 알림이 간헐적으로 누락되며 그 경우 SCU 대체 로그가 없다고 명시한다. 두 설명은 재현성의 강도에 차이가 있다. 따라서 추적 해제는 실게임에서 확인할 재현 절차이며, 이미 수락한 계약을 추적 전환하는 것만으로 누락 수량이 반드시 복구된다고 안내하지 않는다. 현재 제공 로그의 문제 계약에는 위치 마커가 있으나 수량 기록은 없었다. 게임 실행 환경이 제공되지 않았으므로 추적 전환 실험은 수행하지 않았다.

RSI의 [로그 안내](https://support.robertsspaceindustries.com/hc/en-us/articles/360000065688-Send-In-Game-Files-for-RSI-Support)에 따르면 이전 세션 로그는 `logbackups`에 남을 수 있다. 백업을 쓰더라도 동일한 계약 인스턴스의 관측이어야 한다. 별도로 받은 새 계약의 임의 수량에 과거 값을 재사용하는 기능은 제거했다.

수동 상자 입력은 해당 계약의 픽업·배송 그룹 또는 분배 미확인 배송지 예약 그룹에만 적용한다. 기존 운항·적재 진행과 저장된 계약 자체는 보존한다. 이전 `vh-recipes` 데이터가 남아 있어도 신규 계약에 읽거나 쓰지 않는다.

## 배송지별 총량의 빠른 입력

최대치 포함은 기본 켜짐이며 계약 체크 자체는 사용자가 한다. 최대치 카드는 배송지별 총 SCU를 직접 입력할 수 있다. 한 화물 행이거나 나머지 행의 수량이 모두 확인돼 한 값이 유일하게 정해지면 그 실제 수량을 반영한다. 여러 품목·픽업의 분배가 남아 있으면 `_deliveryTotals`에 해당 계약·배송지 합계만 저장하고 운송 행에 임의 배분하지 않는다. 예를 들어 3픽업의 각 상한10에서 배송 합계22를 입력해도 픽업별 10·10·2로 만들지 않으며, 적재 계획은 확인한22 SCU를 한 번만 예약한다. 첫 픽업에서 계약ID×배송지 총량만큼 예약하고, 모든 픽업 방문 후 배송지에서 해제한다. 어느 픽업에 몇 SCU가 있는지는 표시하거나 지어내지 않는다. 카드·확인창·상자 요약·방문 순서·3D·운항이 같은 총량을 사용하며, 3D는 실제 상자가 아닌 예상 예약 공간으로 표시한다. 한 번에 전량 예약할 수 없는 함선은 실제 픽업별 분배를 입력하거나 함선 공간을 조정해야 한다. 입력은 카드의 반영 또는 선택 계약 경로 계산 시 반영되며, 그 자체로 계약을 체크하거나 계획에 등록하지 않는다.
