# 이용안내 단일화 / 250ms 점등 / 하위 화면 구성안

브랜치 `cinematic/guide-library-20261113`, 기준 main beta 2.7.0 `fa647d0`. 별도 연출 PR이며 기능 담당이 최종 통합한다. 복귀 축소 PR #28과는 별도 변경이다.

## 이번에 실제 반영한 부분

- 서비스센터의 중복 이용안내 카드를 제거하고 정보실의 운송 이용안내 한 곳으로 모았다.
- 서비스센터는 계정/운송기록 및 피드백/업데이트 카드로 구성한다. 아래 두 카드는 반씩 채워 빈 칸을 남기지 않는다. 라운지 표식 설명도 '계정 · 운송기록 · 고객지원'으로 맞췄다.
- 사용자가 최종 확정한 **250ms**로 전류 PNG/스캔과 점등음 버퍼를 맞췄다. 시작 지연 80ms + 효과 250ms = 330ms로 기존 도착 333ms 안에 들어간다. 전체 기본 1030ms 예산을 유지한다. 기본 무음도 유지한다. 메뉴 확인음은 바꾸지 않았다.
- `SpaceExperience.tsx`, `space-config.ts`, `content-optics.css`, `console-arrival.css`, 실제 자산의 `record.json` 변경. 기존 계산/계정/운항/자료 API 로직은 수정하지 않는다.

TypeScript/Vite 빌드, 앱 테스트 14개 파일 통과. 실제 production preview Chromium에서 ko/en × 1366/390px의 단일 안내 위치, 서비스센터 계정/기록 유지, 두 지원 카드 균등 배치, 가로 넘침/저장값 불변을 확인했다. CSS 전류 길이 0.25s, 음소거 시 없음, 소리 켜짐 시 한 번의 0.25초 버퍼와 브라우저 오류 없음을 확인했다.

## 요청된 하위 화면 — 구성 확정 사항 / 아직 연결 전

현재 코드의 자료 링크는 아직 기존 방식이다. 다음 구조는 화면/콘텐츠 구성안이며 하위 라우트·내부 자료 페이지·기존 계정 기능의 본문 연결이 완료되었다고 보고하지 않는다. 기능 담당 소유의 자료/계정/저장 연결을 임의 변경하지 않고 아래 계약으로 맞춘다.

| 공간 | 사이드바에서 바로 아래 펼칠 메뉴 |
| --- | --- |
| 서비스센터 | 계정 / 운송기록 / 피드백·오류 신고 / 업데이트 기록 |
| 정보실 | 운송 이용안내 / 미션 자료 / 원본 자료 |
| 영상관 | 소개 영상 (현재 연결된 영상 기준; 제공되지 않은 영상 목록은 만들지 않음) |

부모 공간을 열면 그 항목 아래 하위 메뉴가 슬라이드하며 다음 항목을 아래로 민다. 선택 항목은 금빛으로 표시한다. 고정 상단바·사이드바는 유지하고 본문만 바뀐다. 공용 Barlow Medium 500 + SUIT 500 및 투사 유리 프레임 자산을 사용한다.

라운지→정보실은 기존 확대 이동, 정보실→미션 자료 또는 하위 항목 간 이동은 본문에 기존 전류 자산을 **250ms 한 번** 사용한다. 하위 메뉴마다 전체 공간 확대나 1초 이동을 반복하지 않는다. 본문 내용이 준비되면 전환하고, 오류·빈 결과에서도 메뉴와 출처/이전 화면에 접근할 수 있게 한다.

SCMDB 등 외부 자료는 기존 앱의 검증된 자료를 우리 화면으로 구성하고 원본 출처 링크를 제공한다. 외부 사이트 자체를 무리하게 iframe으로 꾸미거나, 새로운 별도 수집/계산 기준을 만들지 않는다. 자료 버전·출처와 실제 수주 값은 구분한다.

기능 담당 연결 요청: 각 공간과 하위 항목을 주소/새로고침/뒤로가기에 유지하는 유효 하위 경로, 기존 미션 자료 조회/필터의 읽기 전용 본문 연결, 계정/기록/피드백 동작의 본문 표시. 계약/운항 상태를 이동 중 초기화하지 않는다. 현재의 외부 링크 기능을 제거하기 전에 동등한 내부 기능이 실제로 연결됐는지 검증한다.

## 현재 기준 이용안내 — 원고 구성안

정보실 > 운송 이용안내 한 곳에서 제공한다. 본문 상단에 빠른 시작, 전체 안내, 문제 해결을 두고 한 개의 본문 스크롤로 읽는다. 사이드바를 장별로 계속 깊게 중첩하지 않는다. 각 절에는 최신 실제 화면, 눌러야 할 항목, 확인할 결과를 함께 넣는다. 기존 구형 도구의 왼쪽 준비 패널/지도 아래 배치를 새 콘솔 설명으로 재사용하지 않는다.

### 처음 운송하는 사람의 빠른 시작

1. 관제센터에서 운항 파트너를 고른다. 경로 안내 중심이면 브리지 오퍼레이터, 경로와 적재를 함께 준비하면 수석 항해사를 선택한다.
2. 미션 콘솔에서 사용할 함선과 출발지를 확인한다.
3. 로그 수신, 스크린샷 인식 또는 직접 입력으로 계약을 준비한다.
4. 검토 화면에서 픽업지·배송지·수량을 확인하고 계약에 추가한다. 실제 수주 보상과 자료집의 참고 보상을 구분한다.
5. 항로와 방문 순서를 확인한다. 항해사는 적재 공간과 상자 구성이 확인/예상 중 어느 상태인지도 확인한다.
6. 관제 콘솔에서 현재 목적지와 작업을 따라가며 실제 픽업·배송이 끝난 뒤 완료를 반영한다.

### 1. 공간과 화면 찾기

라운지는 안내데스크·서비스센터·정보실·영상관으로 연결된다. 관제센터는 미션·항로 지도·관제 콘솔로 연결된다. 사이드바와 장소명/표식은 같은 목적지다. 상단바·사이드바는 본문 이동 중에도 유지한다. 세부 페이지가 같은 창 안에서 열리는 설명은 내부 페이지 연결이 완료된 뒤 공개 안내에 반영한다.

### 2. 운항 파트너 선택

브리지 오퍼레이터는 사용자가 적재를 처리하고 픽업/배송 경로 안내를 받는 역할이다. 적재 3D를 필수 입력이나 화면으로 요구하지 않는다. 수석 항해사는 확인된 배송 총 SCU를 바탕으로 경로와 적재 공간을 함께 준비한다. 총 SCU가 미확인이고 입력 없이 계속하면 오퍼레이터 경로로 진행한다. 보상이나 설명 누락만으로 역할을 바꾸지 않는다. 플라이트 디렉터는 안내 담당이며 운항 파트너 선택과 구분한다.

### 3. 함선·출발지와 수량 준비

선택한 함선과 실제 출발지를 먼저 확인한다. 실제 총 SCU, 확인한 상자 구성, 자료의 최대치를 구분해 입력한다. 여러 픽업에 대한 배송 총량을 픽업마다 중복해서 더하지 않는다. 확인되지 않은 픽업별 수량을 확정된 것으로 표시하지 않는다.

### 4. 계약 가져오기와 검토

로그 연결 상태와 선택한 파일을 확인한다. 스크린샷 인식 결과는 계약명·픽업지·배송지·SCU를 검토하고 틀린 값을 수정한 뒤 확인한다. 인식 실패나 로그에 없는 항목은 직접 입력으로 보완한다. 수신/인식과 계약 확정을 같은 단계로 취급하지 않는다.

### 5. 항로 지도 읽기

지도와 방문 순서를 함께 확인한다. 방문 항목을 선택해 픽업/배송 작업을 펼친다. 지도의 표시와 현재 작업 위치를 구분하고, 전체 순서는 항로 지도에서 확인한다. SCMDB 우선 자료와 동일 정의의 Wiki 누락 보충이라는 출처 정책, 버전 표시를 설명한다.

### 6. 관제에서 실제 운항 진행

현재 목적지와 그곳에서 해야 할 작업을 중심으로 읽는다. 오퍼레이터는 지도/경로와 방문 작업을 사용한다. 항해사는 지도와 적재 3D가 함께 표시되고 현재 목적지의 픽업/배송을 확인한다. 실제 게임에서 작업을 마친 뒤 완료 조작을 한다. 미리보기로 다음 작업을 살펴보는 행동이 실제 픽업·배송 완료를 뜻하지 않는다.

### 7. 항해사의 적재 확인

계획/미리보기와 실제 선적 상태를 구분한다. 상자 선택으로 배송지·계약을 확인하고 시점 변경/확대로 공간을 살펴본다. 출입구·선수 방향과 활성 적재 구역을 확인한다. 크라이오포드는 1개 1 SCU이며 일반 상자와 다른 지지 조건을 사용한다. 예측 상자 구성을 실제 확인된 구성이라고 부르지 않는다.

### 8. 저장·운송기록·도움받기

같은 브라우저의 운항 저장과 서비스센터의 완료 운송기록을 구분한다. 계정과 기록 확인은 서비스센터로 안내한다. 예시 계약은 운송기록에 포함하지 않는다. 오류 신고에는 문제 발생 화면과 재현 순서, 선택한 파트너·함선 등을 설명하도록 안내하며 비밀번호/인증정보를 첨부하지 않게 한다.

### 자주 막히는 상황

계약이 안 보임 → 수신 상태/선택 파일/검토 여부 확인. 수량이 없음 → 미확인과 0, 실제 총량과 자료 최대치 구분. 적재가 안 보임 → 파트너 역할 확인. 화면에서 본 계획과 실제 작업이 다름 → 예상/실제 선적 상태 구분. 인식 결과가 틀림 → 검토에서 수정 후 확인. 새 UI의 정확한 버튼 문구와 캡처는 최종 본문 연결 시 대조한다.

전체 가이드 동행 영상과 최종 2.5D 인물 클릭 선택은 아직 후속 작업이므로 지금 가능한 절차처럼 원고에 쓰지 않는다.
