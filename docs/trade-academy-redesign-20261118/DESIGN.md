## 사용자 결정

- 최신 사용자 정정: **시세·검색이 첫 화면 → 그 정보로 내 함선·보유금액에 맞는 최적 경로 → 거래 기록**. 앞서 함선·자금 입력을 우선시한 제안은 폐기한다.
- 예비금 기능 자체를 제외한다. 토글·설정·자동 차감 모두 제거 대상으로 확정. 이번 시안에는 제거했으며 제품 코드는 아직 미변경이다.
- ‘티타늄 | 위치 | 가격 | 수량’은 필수 열 명세가 아니다. 읽기·검색·비교가 쉬워야 한다는 예시다. 화면별 목적에 맞게 추천한다.
- 기존 로비의 방 개수·역할부터 재설계 가능. 기존 세 방에 기능을 억지로 끼워 넣지 않는다.
- UEX의 작은 종목 시세판 같은 주식 단말기 구성을 원한다. 영어는 확인된 약자, 한국어는 한글패치 명칭. 약자와 한글·영문 정식명 모두 검색한다.
- 기능은 보존하되 보기 편하게 정리한다. 기존 취소5개와 과금 불허를 유지한다.

## 추천 공간 구조

### 무역센터

로비는 무역 현장 분위기와 파트너 접점이다. 사용자가 원한 공간 이동·직접 클릭 연출·사이드바 빠른 이동을 유지한다.

사용자가 **두 방**으로 확정했다.

1. **무역관제실**: 시세 검색→최적 경로→거래 진행. 시세와 경로는 한 방의 두 작업 보기다. 품목·검색·선택 거래를 유지하며 바로 오간다. 첫 화면은 시세와 검색이며 함선/금액 입력을 요구하지 않는다.
2. **거래기록실**: 실제 매입·판매 내역, 남은 화물, 손익, 정산·내보내기. 개인/함대 원장은 기존대로 분리한다.

별도 계획실·시장정보실을 추가하지 않는다. 기존 시장/계획/관제 링크는 관제실의 해당 보기로, 기록/정산 링크는 거래기록실로 이어지게 한다. 파트너와 게시판은 기존 기능의 진입점으로 보존하며 방을 추가하지 않는다. 로비는 이 두 출입구에 맞춰 추후 연출을 제작한다.

- 수석 무역관: 행성계 내부 추천 조건을 제안.
- 링 가문 중개인: 행성계 간 추천 조건을 제안.
- 파트너 대화는 같은 계획으로 연결. 선택만으로 기존 계획·실제 장부를 바꾸지 않는다.
- 파트너 전신·지도·적재 그래픽이 가격표 자리를 항상 차지하지 않는다. 필요할 때 보조 보기를 연다.

### 아카데미

세 가지 사용자 목적은 분명히 다르므로 **교육실 / 운송정보실 / 사례연구실**을 추천한다. 공간 개수는 확정이 아니며 핵심은 목적별 구분이다.

- 교육실: 첫 운송, 초반 평판, 미션 조합, 첫 무역, 부분 판매·위험 판단.
- 운송정보실: 미션·함선/모듈·화물·거점·패치·출처 찾아보기.
- 사례연구실: 실제 Hull B6계약363SCU 등 확인된 기록의 선택 이유·경로·적재 비교.
- 로비와 각 방에 공통 검색. 방 이름을 몰라도 ‘평판’, ‘갤럭시’, ‘수요 부족’으로 결과를 찾는다.
- 교수는 학습 순서와 관련 자료로 연결한다. 설명을 읽기 위해 반드시 대화할 필요는 없다.
- 새 통합 둘러보기/운송·무역 튜토리얼은 구조 확정 후 제작. 현재#40 연습 기능과 저장 분리를 보존한다.

## 무역 화면 배치

1. 무역센터 방 선택: 무역관제실 / 거래기록실. 관제실 내부 보기: **시세·검색 / 최적 경로**.
2. 첫 화면은 품목·매입처·판매처 검색과 종목 시세판, 매입·판매 쌍을 한눈에 보여주는 표. 함선·자금·로그인·현재 위치를 미리 요구하지 않는다.
3. 품목을 고른 뒤 비교하는 경로 표: 품목 / 매입처·매입가 / 판매처·판매가 / SCU당 차익 / 내 조건으로 계산. 재고·수요·양쪽 보고 시점은 해당 가격 아래 보조 줄. 가격과 장소를 확인하기 위해 먼저 행을 누르지 않아도 된다.
4. 품목·지역·코드로 검색, 매입가/판매가/차익 정렬. 관심/전체 품목 탐색도 유지한다. 영어 코드는 확인된 약자, 한국어는 한글패치 명칭. 검색 바로 아래에 조건에 맞는 품목 버튼을 격자로 펼친다. 품목을 누르면 거래소별 매입·판매가와 재고·수요가 나타난다.
5. 표의 거래 또는 검색 결과를 경로 계산으로 전달한 뒤 함선(모듈 포함)·보유금액·출발 조건을 사용한다. 보유금액 전액을 매입 한도로 사용하며 예비금 차감은 없다. 실제 비용은 손익에 반영하며 별도 실제 사전 비용 제약을 예비금으로 재도입하지 않는다.
6. 경유·왕복·연속·직접 경로·혼합품목·보유 화물 판매·비교·저장·위험/위법 조건은 최적 경로 보기의 관련 보조 영역에 유지.
7. 그래프와 상세는 선택 후 보조 표시. 첫 화면의 주된 면적은 품목 시세판에 쓴다. 모바일에서는 가격쌍을 함께 묶어 읽게 하며 숫자를 작은 글씨로 압축하지 않는다.

### 종목 시세판 의미

- 기본은 평균 판매가와 최대 차익률의 순차 자동 전환이다. 최저 매입가·평균 판매가·최대 차익률을 수동 고정할 수 있다. 평균은 현재 조회 조건을 통과한 거래소 판매가의 산술평균이다. 동작 줄이기 환경에서는 판매가를 고정한다.
- UEX 공개 품목 시세판의 Alternate / Sell Price / ROI를 브라우저에서 확인했다. ROI 색상 구간은 5% 미만 빨강, 5% 이상 20% 미만 중립, 20% 이상 파랑이다. STAM의 매입가와 판매가는 각각 산호색과 파랑으로 구분한다. [UEX Commodities](https://uexcorp.space/commodities)
- 반드시 범위(선택 지역/전체), 단위(aUEC/SCU), 보고 시각·패치를 함께 노출. 서로 다른 거래소의 매입·판매 극값임을 표시한다.
- 차익률=(판매가−매입가)/매입가. 운송·상하역 비용 전 가격 차이며, 주가 등락률이나 실제 순수익률이 아니다. 계산 조건이 부족하면 미확인.
- 종목 선택→그 품목의 거래소별 표→행/후보 선택→계획 검토. 선택해도 실제 거래는 기록되지 않는다.
- 가격 업데이트 때 무의미한 깜빡임·자동 스크롤·정보 재정렬 금지. 변동률은 동일 조건의 실제 과거 관측이 있을 때만 표시한다.

### 서로 다른 표가 필요한 이유

| 사용자의 질문 | 기본 비교 단위 | 먼저 보여줄 것 |
| --- | --- | --- |
| 지금 어떤 거래를 할까? | 매입→판매 거래 한 건 | 품목·양끝 거점, 예상 가능량, 필요자금, 비용 포함 예상 손익, 자료 시점 |
| 티타늄은 어디가 싼가? | 품목×거래소 | 내가 살 가격·보고 재고 또는 내가 팔 가격·보고 수요, 지역, 자료 시점 |
| 이미 실은 것을 어디에 팔까? | 보유 화물×판매처 | 보고 수요, 판매 가능량 추정, 기존 원가 대비 손익, 미판매 잔량 |

기본 시세표는 매입처·매입가와 판매처·판매가를 **동시에** 보여준다. 개별 거래소 시세 상세는 보조 보기다. 확인 시점·지역은 감추지 않는다. 좁은 화면에서 글씨를 줄이지 말고 행의 보조 줄로 옮긴다.

### 선택 세부와 그래프

- 가격/수량/매입원금/예상판매액/비용/예상손익을 분리.
- 작은 수량 비교 막대: 빈 적재공간·자금 한도·보고 재고·보고 수요. 가장 작은 값과 ‘왜 이 수량인가’ 설명. 실제 실행 가능 판단에는 상자/함선/설비/소유권 제약도 포함.
- 지역별 가격은 정렬된 수평 비교. 가격 숫자가 주정보이며 그래프는 위치 비교를 보조.
- 실제 가격 이력은 펼쳤을 때만. 관측이 적으면 점과 보고 시각을 표시. 주간최저/최고로 가짜 시계열을 만들지 않는다.
- 경로는 작은 순서 띠. 지도·3D 적재·세부 상자 배치는 필요할 때 확장. 기능을 없애는 것이 아니다.
- 최대3후보 비교, 비용/수요 변화 시나리오, 저장한 계획은 결과 근처의 보조 작업.

### 실제 무역 진행

매입 현장 확인→실제 매입 기록→운반→실제 판매 기록→비용·잔량 확인→마감. 가격 조회·계획 확정·로그 수신만으로 실제 거래를 자동 기록하지 않는다. 부분 판매 후 남은 화물/원가는 유지한다. 지연된 가격 갱신이 진행 중 원장을 다시 계산해 덮어쓰면 안 된다.

함대 모드는 기존 초대·참여 승인·담당 배정·보고·함장 승인·정산·지급/수령 확인을 유지한다. 함대원은 본인 작업, 함장은 미승인·지연 작업을 우선 표시한다. 채팅/공지와 거래보고는 별개다.

## 검색·표기 원칙

- 한글패치 사전 우선. 현재 `trade-labels.ts`는 `stam-korean.json`과`ai-korean.json`을 합치므로 출처를 분리해 점검해야 한다. 한글패치에 없는 항목을 임의 번역해 확정명처럼 쓰지 않는다.
- 영어 기본 품목코드는 원본 데이터에서 확인된 코드. 충돌·미확인 약자는 정식명으로 대체. 코드·게임명·한국어명은 동일 ID를 가리키며 데이터 키는 변경하지 않는다.
- 자동완성 결과를 품목/거점/함선으로 구분. 장소는 ‘행성계 > 행성권 > 거래소’를 표시. 영문 풀네임은 선택 세부·접근 가능한 설명에서도 확인 가능.
- 추천 별칭은 검증된 사전으로 관리. 오탈자 제안은 ‘이 이름을 찾으셨나요?’로 안내하고 검색어를 몰래 치환하지 않는다.
- 0개 결과는 현재 적용 필터와 원인을 보여준다. 위법/위험 제한을 자동으로 완화하지 않는다.
- 가격이 없음, 해당 방향 거래 없음, 보고 재고0, 수량 미확인을 서로 구분한다.

## 아카데미 읽기 구성

검색→질문형 제목→한 문단 핵심→짧은 도식/실제 예→주의점→관련 도구. 긴 자료 목록과 원문 출처는 펼쳐 보기.

- 초반 평판은 발주처·등급·상자·공통 픽업/배송을 비교. 실측 XP/시간이 없으면 ‘평판 최고 효율’이라고 순위를 매기지 않는다.
- 자료 종류를 게임 규칙/커뮤니티 보고/실제 운항 사례로 구분하고 패치·확인일·출처를 표시.
- 실제 사례는 사용자가 확인한6계약363SCU. 수량 미확정 일곱 번째 계약을 섞지 않는다.
- 학습용 조건을 실제 도구로 넘길 때 변경 내용을 보여주며, 실제 장부·운항에 자동 저장하지 않는다.

## 보존·성능·구현 순서

`PRESERVATION.md`에서 기존 기능 등록부88행 전체를 새 위치로 연결한다. 등록부의 과거 미배포 표시는 현재 배포 사실과 구분한다. 조사에서 발견된 아이디어를 모두 현재 구현 완료로 표현하지 않는다.

- 기존 계산 엔진·원장·권한·동기화는 재사용하되, 사용자가 명시 취소한 예비금은 제거한다. 과거 저장 설정의 예비금 값이 조용히 적용되지 않도록 입력 변환 경계를 점검한다. 기존 실제 장부는 다시 계산하거나 삭제하지 않는다.
- 로컬 품목/거점 검색 인덱스, 안정적인 행 ID, 검색 중 네트워크 재요청 없음. 큰 결과는 페이지/가상화하되 키보드 탐색과 선택 보존.
- 계산은 입력 변경마다 전체 경로 탐색하지 않고 명시 계산 또는 지연 실행. 오래된 응답이 새 조건을 덮지 않도록 한다.
- 그래프·3D·OCR는 펼칠 때 로드. 이미 있는 앱·클라우드 연결은 재개발하지 않는다.
- 승인 셸·패널/버튼 원본 에셋·Barlow500/SUIT500을 실제 구현에 사용. 이번 간이 배치 시안은 새 에셋 승인 요청이 아니다.
- 추천 진행: 배치 검토→확정된 화면/공간/경로 계약 문서→검색·공통 시세 모델→관제실 통합→아카데미→로비/연출 연결→변경 범위 검증. 연출 담당과 동선·방 ID를 먼저 합의하고 최종 로비를 생성한다.

## 검토용 시안의 범위

`/workspace/stam-design-review/redesign-20261118/trade-market-first.html`이 최신 대화 내 구성 검토용이다. 이전 trade-academy-workspace.html의 무역 첫 화면/예비금 구성은 폐기된 제안이다. 8품목의 가상 시세·가상 거점만 사용한다. 실제 시장 계산/판매 가능 판정이 아니며 일부 제약·개인/함대·상세 그래프·세부 기능은 문서에서 보존 위치만 정했다. 한국어/영문 전환은 품목 표기만 바꾼다. 무역센터 두 방과 업무 우선순위는 사용자 확정이다. 세부 배치·외형은 검토 중인 시안이다.

검색/정렬/코드 표기, 매입·판매 가격쌍, 품목 선택→경로 조건 전달, 예비금 없는 수량 계산 예, 미확인 수량 보류, 두 방 이동을 조작할 수 있다. 새 최적경로 엔진이나 실제 거래기록 구현을 뜻하지 않는다. 아카데미는 기존 제안 범위를 보존한다. 실제 계정·저장소·API와 연결되지 않는다.

## 파트너 안내 대화

OpenAI API의 사용 범위는 이용자가 파트너에게 직접 보내는 텍스트 질문과 그 답변이다. 로비에서 인물을 누르면 기존 인사와 예시 질문을 보여주고, 질문을 보내는 순간에만 호출한다. 파트너는 현재 공간, 선택 언어, 이용안내와 아카데미 자료를 바탕으로 설명한다.

| 파트너 | 질문 예시 | 안내 내용 |
| --- | --- | --- |
| 수석 무역관 | “처음 무역하려면 어디부터 봐요?” | 시세표에서 같은 품목의 매입처와 판매처를 찾고 단가와 보고 시점을 읽는 순서 |
| 링 가문 중개인 | “행성계를 넘을 때 뭘 더 확인해야 해요?” | 목적지 수요, 마지막 보고 시각, 장거리 이동 비용을 확인하는 방법 |
| 지도 교수 | “초반 평판용 미션은 어떤 기준으로 묶어요?” | 출발지와 하차 지점이 겹치는 계약을 찾는 방법과 관련 수업 |

시세 조회·검색·경로 계산·장부와 정산은 각각 기존 화면과 데이터 처리 방식을 사용한다. 미션 스크린샷은 기기 내 OCR로 읽는다. 파트너 대화에는 업무 실행 권한이 없으며, 기능 조작으로 OpenAI API를 호출하지 않는다. 공개 API 연결과 비용 집행은 아직 설계 이후의 단계다.
