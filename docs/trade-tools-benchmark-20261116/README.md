# 무역 도구 재조사 — 2026-11-16

> 이 문서는 조사 당시 상태를 보존한 기록이다. 이후 사용자의 구현 지시에 따른 최신 기능·검증 상태는 [무역 기능 대조표](../trade-suite-20261116/README.md)를 따른다.

사용자 요청: 다른 무역 도구를 충분히 조사한 뒤 STAM 무역 구성을 다시 판단한다. 기존 API 수집 조사를 경쟁 도구의 실제 사용 흐름 조사로 대신했던 범위를 바로잡는다. **이번 작업은 조사와 설계 검토다. 기존 지도·적재 연결 작업은 미완료 상태로 보존하며, 제품 코드 추가 수정·배포를 진행하지 않는다.**

## 조사 방법과 판정 기준

- 비로그인 새 Chromium 세션에서 실제 공개 웹 화면을 열어 입력·계산·필터·결과를 확인했다. 원격 응답을 모의 데이터로 교체하지 않았다.
- 환경의 외부 TLS 문제 때문에 브라우저 요청은 검증된 CA/프록시를 쓰는 Node fetch를 통해 전달했다. TLS 검증을 끄지 않았다. 일반 브라우저 성능 측정이나 실제 게임 플레이 검증은 아니다.
- 결과 금액은 조사 시점의 해당 도구 출력이다. 현재 게임에서 확보할 수 있는 재고·수익의 보장이 아니다. 조건과 데이터 시점이 달라 사이트끼리 수익 순위를 매기지 않는다.
- **실행 확인** / **화면·문서 확인** / **미확인·환경 제한**을 구분한다. 버튼 존재를 계산 성공으로, README의 소개를 앱 실사용 검증으로 바꾸지 않는다.
- 사이트 자료·스크린샷은 조사 증거로만 보관한다. 경쟁 서비스의 화면 자산을 제품에 넣지 않는다. 계정 로그인·시세 제출·앱 설치·외부 메시지 전송 없음.

## 먼저 정정할 결론

1. 현재 STAM 계획실은 **고정 매입 거래소에서 한 품목을 한 판매처로 보내는 후보 비교**다. 다중 거래·왕복·목적지 경유 최적화와 같지 않다.
2. 다른 툴의 큰 예상 수익을 그대로 따라가면 안 된다. 오래된 가격, 불확실한 수요, 비용 제외, 평균 속도 ETA가 결과에 포함될 수 있다.
3. 경쟁 도구가 유용한 지점은 가격 수집량만이 아니다. **이미 실은 화물 판매처 찾기, 목적지 가는 길에 거래하기, 다음 거래로 이어가기, 적재 비용·시간 비교**가 실제 사용자 흐름이다.
4. 여러 사이트가 UEX 데이터를 재사용한다. 사이트 수가 늘었다고 독립적인 근거가 늘어난 것은 아니다. 보고 출처와 원천 데이터 계보를 유지해야 한다.
5. 위험도·위법 여부·도난/소유권·가격 신뢰도는 서로 다른 조건이다. 현재 STAM의 거점 감시/정전 구역 필터는 경로 전체 치안 평가가 아니다.

## 실제 계산 표본

입력 공통 예시는 Cutlass Black, 자본 1,000,000 aUEC다. 각 사이트 기본 조건이 달라 수익 우열을 판정하는 실험은 아니다. 기본 예비금은 경쟁 도구에 강제 주입하지 않았다. STAM의 10% 예비금 규칙은 유지해야 한다.

### SC Trade Tools

요청값과 실제 응답은 [sct-calculations.json](evidence/sct-calculations.json)에 보관했다.

- 시간당 수익 기준: Bueno Ravine → The Golden Riviera, Bexalite 42 SCU. 매입 989,352 / 매출 1,323,000 / 차익 333,648 / 표시 시간 3분 23초 / 98,829 UEC/분. 이는 도구의 예상값이며 출발 전 이동·실제 플레이 전체 시간이 검증된 것은 아니다.
- Pure profit 변경: 동일 선두 후보를 유지하되 뒤 순서가 바뀌며 HDMS-Pinewood 출발 후보가 올라왔다. 시간당 효율과 총차익은 다른 정렬이다.
- Auto-loading 켜기: Rat’s Nest → HUR-L1, Diamond 46 SCU 후보가 선두에 표시됐다. 매입 252,264 / 매출 386,400 / 양 끝 비용 1,720씩 / 차익 130,696 / 21분 26초. **386,400 − 252,264 − 1,720 − 1,720 = 130,696**으로 응답과 일치한다.
- 이미 가진 Laranite 32 SCU: 일반 화물 판매처 12개, Stolen cargo 선택 시 10개. 첫 결과는 Nyx의 Stanton Gateway 284,800에서 Pyro Endgame 278,400으로 바뀌었다. 이 값은 판매 총액이며 매입 원가를 빼지 않은 실현 이익이 아니다.
- En route: Everus Harbor → Seraphim Station, 우회 허용 25%, 최대 5 stops. **Everus → Rappel → Grim HEX → Seraphim**의 3거래를 받았다. Scrap → RMC → Human Food Bars로 품목이 바뀐다. 구간별 차익 34,316 / 2,576 / 7,636. 화면은 각 구간 매입·판매·시간을 보여준다. 마지막 Human Food Bars는 매입 가능 규격 8/16/24/32를 표시하면서 수량은 46이다. 실제 구매 상자 조합의 성립 여부는 추가 확인이 필요하므로 외부 추천을 자체 적재 검증 없이 채택하지 않는다.
- Hull C, 10,000,000, 자동 적재: Helium 4,608 SCU 등 대형 적재 후보를 반환했다. 고정 `Pure profit` 조건에서도 화면 첫 두 행 차익은 1,444,192 / 1,798,542로 단순 내림차순과 맞지 않았다. 내부 정렬의 의미를 확정하지 않는다. 외부 첫 행을 무조건 최적해로 가져오면 안 된다.
- Best circular route: 버튼·대화상자는 확인했지만 선택한 Bexalite 경로의 계산 요청이 **조사 브리지의 25초 제한으로 중단**됐다. 뒤의 “No results”를 실제로 왕복 경로가 없다는 증거로 사용하지 않는다.

### UEX

- Cutlass Black·1,000,000 입력으로 후보표가 다시 계산됐다. Legal을 켜면 최초 Osoian Hides 후보가 빠졌고, Predicted를 추가하면 Degnous Root → MIC-L1 선두 후보가 빠졌다. [일반](evidence/uex-cutlass-1m.png) / [합법](evidence/uex-cutlass-1m-legal.png) / [예측 수요](evidence/uex-cutlass-legal-predicted.png).
- Degnous Root 22 SCU → MIC-L1: 툴팁은 매입 `22 × 44,156 = 971,432`, 차익 `(69,000 − 44,156) × 22 = 546,568`을 설명한다. 판매 수요 툴팁은 **불확실하며 마지막 보고가 0 SCU**라고 경고한다. 큰 수익과 실제 전량 판매 가능성은 다르다.
- 같은 결과의 ETA 툴팁: `(146 Gm × 1,000,000) ÷ 115,797 km/s ≈ 21분 1초`. 터미널 보행·대기·수동 상하차·점프 통과 시간이 모두 반영됐다고 해석하지 않는다.
- Predicted에서도 매입 2일·판매 14일 등의 행이 남았다. **안정적인 수요 예측 ≠ 최근 가격 ≠ 확정 수요**.
- Loop 필터도 실제 조작해 별도 저장했다. 재투자·매 구간 자본 변동 계산까지 검증한 것은 아니다.
- SCU-C는 calculated demand, SCU-U는 사용자의 평균 구매/판매량이다. 원본 필드 의미가 다르므로 하나의 `확정 재고` 값으로 합치지 않는다. [툴팁 근거](evidence/uex-assumptions.json).

### Gallog

- Cutlass Black·1,000,000: Sacren’s Plot → Canard View, Partillium **5.86 SCU / 586 Units**, 단위 차익 388.83, 총차익 227,854.38. **586 × 388.83 = 227,854.38**이다. UEX의 SCU당 가격과 Gallog의 이 표본 단위 가격을 그대로 섞으면 100배 오류가 난다.
- 46 SCU 안에 `Astatine 34 + Atlasium 12`처럼 복수 품목이 있는 행도 출력됐다. 우리 단일 품목 후보와 다른 구성이다. 해당 예시 행은 손실이므로 “추천할 수익성 좋은 혼합 적재”로 확정하지 않는다.
- 선택·계산 후에도 카드의 Time은 0이었고 행성계 간 일부 Distance도 0이었다. 결측을 유효 시간/거리로 사용하지 않는다.
- 2 stops로 바꾼 표본은 `1 / 0 / 1 / 0`만 남고 유효 경로를 얻지 못했다. 전체 서비스의 고장이나 모든 조건 실패를 뜻하지 않는다.
- Reinvest 클릭 후 Uec 입력이 1,000,000으로 유지됐다. “재투자 기능 동작 검증 완료”가 아니라 버튼과 의도만 확인한 상태다.

### StarHead

- Cutlass Black / Hurston / 1,000,000 aUEC / 기본 Odyssey / 다른 행성계 허용 / 자동 적재 끔 / 가격 30일: 6개 경로를 받았다. 첫 경로는 Picker’s Field → Seer’s Canyon의 RMC 46 SCU. 표시 매입 328,624 / 판매 391,000 / 차익 62,376 / 27분 20초, 가격 나이는 매입 1일·판매 9일이었다.
- 상자 혼합 `1×2 + 2×6 + 16×2 = 46 SCU`, 양 끝 가능한 상자 규격, 가격 갱신 시각, 경로 추가·저장·정렬 UI를 함께 보여준다. 저장·계정 연결까지 검증한 것은 아니다.
- 가격 제한을 30일→1일로 바꾸자 HTTP 200에 빈 결과 `[]`를 받았다. 같은 함선·자본에서도 최신성 조건에 따라 추천이 사라진다. 오래된 가격을 몰래 다시 포함해 결과를 채우면 안 된다.
- API 요청의 `maxAvailableMoney=10000`, 응답 매입 합계 `3286.2402`와 화면 `1,000,000 / 328,624`는 스케일이 다르다. **API 내부 단위·부동소수 오차를 정규화한 뒤 비교**해야 한다. UEX 원본과 숫자를 곧바로 합치면 안 된다.

공식 [UEX 커뮤니티 도구 목록](https://uexcorp.space/api/community_made)도 확인했다. 이 목록의 여러 도구가 **동일한 UEX 원천**을 쓰므로 모두 독립 시세 검증원으로 세지 않는다. `sc-trader.com`, `sc-trading.app`은 이 환경에서 연결을 확인하지 못했으며 서비스 종료라고 단정하지 않는다.

## 자료 연결 원칙

- **UEX**: 시세·재고/수요·터미널 설비의 우선 출처. 공개 API 문서의 현재 표기는 API 2.0, 120 requests/min·일 172,800이다. 제한을 목표 처리량으로 삼지 말고 서버 캐시·필요 품목 갱신·백오프를 사용한다. 최신값/평균값, 공급/수요/추정 수요, 데이터 수정 시각/수집 시각/게임 패치를 분리한다.
- **SC Trade Tools**: 계산 흐름의 비교 기준이며 보조 시세·루트 계산 후보. 공개 앱의 실제 요청은 성공했지만 외부 앱 REST·MCP 이용은 README의 토큰 절차를 따른다. 아직 STAM용 인증 연결은 없다. 공개 GitHub의 11.5.0 OpenAPI 스키마를 읽었고, 내부 최적화 구현 소스까지 검증했다고 주장하지 않는다.
- **StarHead**: 퀀텀 드라이브·경로 계산의 추가 비교 출처. 브라우저에서 발견한 실제 데이터 경로를 확인해야 하며 임의 추측한 API 루트/Swagger의 404를 API 전체 미작동으로 해석하지 않는다.
- **SCMDB/Wiki**: 기존 사용자 결정대로 미션·함선·좌표 자료를 유지한다. 시세 사이트의 함선명만으로 적재 그리드/용량을 덮어쓰지 않는다.
- **로그/OCR/수동**: 실제 매입·판매 기록의 근거다. 현재 로그 앱이 모든 거래 필드를 제공한다고 가정하지 않는다. OCR 결과는 검토·보완하고, 외부 가격 제출은 별도 명시 동의가 있을 때만 구현한다.
- UEX 약관의 API 절을 확인했다. API 자료 사용과 사이트 전체·이미지의 무제한 재배포를 같은 권리로 해석하지 않는다. 출처/시각을 보존하고 필요한 필드만 정규화한다.

## STAM과의 기능 대조 및 권장 구성

현재 상태는 로컬 코드 `trade-planning.ts`, `TradePlanning.tsx`, `trade-data.ts`, `trade-operations.ts` 대조 기준이다. 기존 검증 완료와 새 지도 작업 WIP를 구분한다.

| 사용자 작업 | 현재 STAM | 보완 방향 |
|---|---|---|
| 함선·출발 거래소·자본으로 추천 | 구현 | 기본 입력을 늘리지 않고 유지 |
| 기본 예비금 10% | 구현·조정 가능 | 연속 거래 매 단계에서도 남겨야 함 |
| 합법/위험 선택 | 서로 독립해 구현 | 화물 취급 위험·거점 조건·항로 위험·소유권을 설명 가능한 기준으로 분리 |
| 최신 가격만 비교 | 현재 패치·24시간 내 수정 기준 | 수정 시각을 게임 관측 시각으로 오인하지 않게 표시; 지연·추정도 구분 |

| 목적지 가는 도중 거래 | 미구현 | 출발/목적지·허용 우회 범위로 선택; 2~3거래부터 제한해서 설명 가능하게 |

### 사용자에게 보일 구성 제안

계획실은 우선 **새로 사서 운송 / 실은 화물 판매 / 목적지 가는 길에 교역**의 세 가지 목적을 고르게 한다. 기본 입력은 함선·현재 위치·자본 또는 보유 화물이다. 위험도·위법 허용은 항상 쉽게 찾게 두고, 경유·우회·상하차·가격 연령은 고급 조건에 둔다. 모든 옵션을 처음부터 한 화면에 쏟아붓지 않는다.

결과는 추천 이유·투입금·예상 차익·소요 시간 근거·화물/시설 적합·가격 시각·수요 불확실성을 같은 행에서 비교한다. 제일 큰 숫자 하나만 강조하지 않는다. “가장 높은 차익 / 짧은 작업 / 보수적인 조건”은 근거가 있을 때만 구분한다.

수석 교역관은 행성계 내부의 접근/상하차·반복 거래에, 링 가문 중개인은 행성계 간 점프·항로·대체 판매처에 초점을 둔다. 두 명의 데이터 모델은 공유하되 이름과 행성계 필터만 다른 것으로 마감하지 않는다. 실제로 아직 두 담당자의 독립 최적화 전략은 구현되지 않았다.

아카데미는 시장정보실의 가격표를 복제하지 않는다. 예비금·순매출/차익·재고/수요·부분 판매·시간 대비 효율을 **패치·가정이 명시된 사례**로 가르치고 실계획실로 연결한다. 초반 평판 미션 조합은 SCMDB/Wiki/보존 로그의 별도 근거로 작성한다. 오래된 인기 무역 루트를 영구 정답처럼 적지 않는다.

### 다음 구현의 권장 순서

1. 데이터 의미 정리: 보고/추정 수요, 가격 시각, 비용·시간 가정을 보존. 확인 불가를 0으로 다루지 않기.
2. 이미 실은 화물 판매처·대체 판매처, 매입 전 재확인. 현재 장부와 소유권을 보존하면서 연결.
3. 비용/상하차/소요 시간 비교, 기존 지도·적재 연결 마감. 기존 실제값을 새 계산으로 덮어쓰지 않음.
4. 목적지 경유·선택 왕복·재투자·혼합 적재. 자본과 잔량을 구간마다 검증하는 경로 모델 먼저.
5. 그 구조를 바탕으로 아카데미 사례, 무역/운송별 새 튜토리얼과 통합 둘러보기.

이 순서는 조사에 따른 제안이다. 이 문서 작성만으로 목록 전체가 구현됐거나 배포됐다는 뜻은 아니다. 사용자 요청에 따라 기능을 임의로 삭제하지 않는다.
