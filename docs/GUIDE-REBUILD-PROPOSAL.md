# 이용안내 구성 참고안

사용자가 전달한 Claude 구성안입니다. 그대로 구현하는 확정 명세가 아닙니다. 기능 오류를 먼저 해결한 뒤 현재 사이트와 대조해 추가·변경·제거를 제안합니다. 실제 사용자 로그·스크린샷은 안내 자산으로 사용하지 않습니다.

[이용안내 재제작 구성안 — Claude 정리, 2026-11-05]
기준: 현재 main 사이트 v3.11.0 (계약 수신함, 연결 앱, 운송 정보실, 패치노트 별도 페이지 포함).
사이트를 직접 열어 실제 화면·문구와 대조하면서 만들 것. 화면과 다른 설명이 있으면 안 됨.

■ 1. 사용자 확정 사항
1) 슬라이드 형식.
2) 패치노트처럼 같은 탭의 별도 페이지(guide.html)로 이동. 뒤로가기로 관제 화면 복귀.
3) 튜토리얼 수준으로 세세하게. 기능은 최대한 많이 설명하되 복잡하지 않게.
4) 검색 기능.
5) 실제 사이트 스크린샷을 써서 보기 쉽게.
6) 파트너가 초상화 안에 갇혀 있지 않고, 화면 밖으로 튀어나와 몸짓·손짓으로 안내.
   - 전에 만들었던 전신 몸짓 연출 방식으로 할 것.
   - 브리지 오퍼레이터는 확정된 새 생단발 얼굴(assets/partners/aide.png) 기준으로 전신을 새로 만든다.
     예전 오퍼레이터의 전신·몸짓 이미지는 쓰지 않는다.
7) 첫 방문 때 안내 페이지로 자동 이동하지 않는다. 첫 방문은 별도 튜토리얼이 맡는다.
   이용 안내는 상단 「이용 안내」 버튼으로만 연다.
8) 문제 해결도 슬라이드로 만든다.
9) 소개 영상은 이용 안내에 넣지 않는다. 메인 화면의 짧은 소개 쪽으로 따로 뺀다.
10) 「?」 바로가기 버튼을 넣는다. 단, 기존 디자인을 해치지 않을 것 (아래 7번 추천안).

■ 2. 페이지 구조
- guide.html + 슬라이드 데이터 모듈. 상단 「이용 안내」 → location.assign('./guide.html'). 패치노트와 같은 방식.
- 이동 전 편집 중인 창이 있으면 기존 beforeReload()처럼 저장/닫기 안내.
- guide.html#장id 로 특정 장 바로가기. 검색 결과와 「?」 버튼도 이 주소를 사용.
- 데스크톱 배치:
  상단: STAM 로고 · 이용 안내 · [검색창] · 한국어/English · [관제로 돌아가기]
  왼쪽: 목차 (맨 위에 「빠른 시작」, 그 아래 장 묶음별 목록)
  가운데: 장 번호/전체 · 제목 · 한 줄 요약
          실제 스크린샷(왼쪽) + 단계 설명 ①②③(오른쪽) + 팁/주의
          아래 [← 이전] 3/55 [다음 →]
  파트너: 슬라이드 가장자리에서 전신으로 튀어나와 몸짓하며 말풍선
- 모바일(390px): 목차는 「목차」 버튼으로 접기, 스크린샷 → 단계 순서로 세로 배치.
- 키보드: ←/→ 이전·다음, / 검색창 이동, Esc 검색 닫기.
- 마지막으로 본 장을 브라우저에 기억해 「이어서 보기」 제공.
- 개발 지침의 「단계형 창 외곽 크기 고정, 넘치는 내용만 내부 스크롤」 규칙을 슬라이드에도 적용.
  장마다 슬라이드 크기가 바뀌지 않게.

■ 3. 세세하지만 복잡하지 않게
1) 한 장 = 한 가지 동작. 단계는 장당 최대 4개.
2) 두 갈래 길: 처음 쓰는 사람용 「빠른 시작」 6장 + 전체 「기능별 안내」.
3) 실제 스크린샷 위에 ①②③ 동그라미를 겹쳐 그리고 오른쪽 단계 번호와 맞춘다.
   단계에 마우스를 올리면 해당 번호가 깜빡임.
   - 번호는 이미지에 굽지 않고 좌표(%)로 겹쳐 그린다 → 한국어/English 스크린샷에 같은 데이터 재사용.
   - 필요한 부분만 잘라 확대한 스크린샷. 전체 화면 축소본은 쓰지 않는다. 장당 1장, 필요하면 2장(전/후).
4) 예외·한계·세부 설정은 「더 알아보기」 접기 칸에 넣는다. 기본 화면은 짧게.
5) 추정 표시(최대 상자 규격 임시 계산, 예상 시간 등)는 사이트 화면과 같은 표현으로 안내.
6) 준비 중 기능(밀수 브로커 무역 등)은 「준비 중」 배지로 짧게만.

■ 4. 검색
- 각 장의 제목·요약·단계·팁·더 알아보기 + keywords(동의어)로 정적 색인.
- 한영 동의어: 로그/Game.log/log, 수신함/inbox, 그리드/grid/구역, 상자/컨테이너/container/box,
  점프/jump/게이트웨이, 냉동포드/cryopod 등.
- 지도 검색처럼 부분 일치 + 흔한 오타 허용.
- 결과: 장 제목 + 일치 문장 한 줄(검색어 강조). 누르면 그 장으로 이동하고 일치 부분 강조.
- 검색창 아래 「자주 찾는」 칩: 계약이 안 들어와요 / Game.log 위치 / 상자 구성 / 그리드 끄기 / 관제 모드 / 계획 초기화.
- 결과가 없으면 파트너가 「그 내용은 아직 안내에 없습니다」 + 피드백 보내기 링크.

■ 5. 파트너 등장
- 사이트에서 선택한 파트너(sfc-voice)가 안내. 안내 페이지 안에서만 바꾸는 「안내 파트너 바꾸기」 제공
  (사이트의 운항 파트너 설정은 바꾸지 않음).
- 등장 위치:
  · 장 첫 슬라이드: 전신으로 크게 튀어나와 인사 몸짓 + 그 장에서 배울 것 한 줄.
  · 모든 슬라이드: 가장자리에서 튀어나와 화면을 가리키는 손짓 등 + 한 줄 팁. 접기 가능(설정 기억).
  · 검색 결과 없음 / 마지막 장: 마무리 몸짓 + 「관제로 돌아가 출항하시죠」 + 관제 복귀 버튼.
- 말투: 수석 항해사 = 침착한 격식체, 브리지 오퍼레이터 = 밝고 친근한 존댓말.
  장마다 두 버전(partnerLine.navigator, partnerLine.operator), 한국어/English.
- 밀수 브로커는 「준비 중」 소개 장 한 곳에만 등장.
- prefers-reduced-motion이면 움직임 없이 정지 이미지. 음성·자동 재생 없음.

■ 7. 「?」 버튼 — 디자인 안 해치는 방식 (추천, 최종 모양은 사용자에게 시안 보여주고 확인)
A) 도움말 모드: 상단바 「이용 안내」 옆에 작은 ? 토글 하나만 둔다.
   켜면 화면에 반투명 막이 깔리고, 설명할 수 있는 영역(왼쪽 버튼들, 지도 도구, 적재 3D, 방문 순서 등)마다
   청록 ? 배지가 뜬다. 배지를 누르면 해당 안내 장으로 이동. Esc나 토글로 끔.
   평소 화면에는 아무것도 추가되지 않는다.
B) 창 제목줄: 운송 계약 추가·미션별 화물 확인·운항 설정·계획 초기화 같은 대화상자 제목줄의
   × 닫기 왼쪽에만 작은 ?를 상시 둔다.
- 메인 화면 패널마다 ?를 상시로 다는 방식은 쓰지 않는다 (지도·적재 위 버튼이 이미 많음).
- A + B 함께 사용. 배지 색·크기는 기존 청록 강조색과 버튼 테두리 규칙을 그대로 쓴다.

■ 9. 스크린샷 제작
- 실제 사이트를 Playwright로 열고 가상 계약으로 상태를 만든 뒤 해당 영역만 캡처.
- 한국어/English 두 벌, 데스크톱 1440px 기준.
- 개인 정보·계정 이메일·실제 로그 경로·실제 미션 ID가 보이지 않게. Game.log 탐색기 장면은 가상 폴더 이름.
