## 지금 바로잡을 문제

- 원래 수동판은 **배치와 시각 품질의 기준**이다. 내부 구현을 그대로 고정하라는 요구가 아니다.
- 기본 `index.html`에 기존 배치와 새 관제 기능을 통합한다. `flight-deck.html`은 비교용 개발 화면으로 남긴다. 두 화면이 각각 작동하는 것으로 전체 통합 완료를 판정하지 않는다.
- 기존 공개 4.0.0 이력을 보존하고 후속 통합 버전을 4.1.0으로 기록한다. 자동 검사를 실게임 검증으로 표현하지 않는다.
- 기존 기능 목록의 날짜별 메모는 이력이다. 서로 모순되는 과거 메모를 현재 상태로 읽지 않는다. 현황은 아래 항목과 `PROJECT_STATUS.md`를 함께 따른다.

최신 사용자 승인(2026-11-04): 남은 개발을 완료했다고 판단되면 최종 이용안내까지 마무리하고 사이트·앱을 배포한다. 사용자 실게임 피드백은 그 다음이다. 조건 충족 뒤 배포를 다시 승인받을 필요는 없다. 개발 미완료와 사용자 PC/게임에서만 가능한 검증을 구분하며, 후자는 `FINAL-GAME-VALIDATION.md`로 안내한다.

필수 사용자 흐름: 실행 → 파트너 → 로그 연결 → 이미 받은/새 계약 → 중형+대형 혼합 항로 → 배송지별 화물 → 일부 적재 → 새 계약 선택 합류 → 포기와 잔여 화물 → 재접속 → 완료/수입 확인.

자동 검사만으로 게임에서 확인한 것으로 쓰지 않는다. 근거가 없는 기능은 구현 불가로 뭉뚱그리지 말고, 가능한 입력 경로·공간 가이드·수동 보정을 먼저 연결한다. 자동으로 얻지 못한 필드만 사용자에게 보완을 요청한다.
