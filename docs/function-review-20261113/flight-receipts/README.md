# 운항 중 계약 변경 확인 / 선내 보류 — 2026-11-13

기능 클라우드 `integration/freight-division-20261113`, `b1abe51` 이후 작업본. 앞선 아카이브·적재 용량·수신함 연속성 변경을 보존했다. 커밋·푸시·배포하지 않았다.

## 확정 동작

- 사용자 확정: 변경을 알리고 사용자가 확인하면 남은 경로를 재계산한다. 취소·종료된 계약의 남은 픽업/배송은 제외하며 이미 실린 화물은 **선내 보류**로 남긴다.
- 감지만으로 경로/선적/배송 완료를 변경하지 않는다. 현재 선택된 수주 인스턴스만 대조한다. 파일에 계약이 안 보이는 것은 취소로 간주하지 않는다.
- 확인창에서 현재 운항과 최근 수신을 비교한다. 수량/규격/거점이 이미 처리한 화물과 충돌하면 자동 적용을 막고 기존 내용을 유지할 수 있다. 미처리 작업의 검증 가능한 변경은 확인 후 반영한다.
- 확인 후 현재 위치에서 남은 작업을 계산한다. 선내 상자 ID·소유권·규격·좌표·픽업/배송 기록·완료 로그를 유지한다. 새 경로의 되돌리기 구간은 새로 시작하며 직전 전체 운항 백업을 별도 저장한다.
- 보류 화물은 실제 공간을 계속 차지한다. 마지막 정상 배송 뒤에도 보류 화물이 있으면 운송 완료가 아닌 ‘남은 배송 없음 · 보류 화물 있음’으로 표시한다. 취소 계약의 보상을 수령한 것으로 기록하지 않는다.
- 오퍼레이터는 경로만 변경하고 적재 3D를 생성하지 않는다. 항해사는 기존 지도/적재 동시 표시를 유지한다.
- 진행 중에도 미션 화면의 로그 선택/자동 수신 재연결을 사용할 수 있다. 계약 편집 잠금은 유지한다.
- 확인창 이후 새 근거/운항 변경, 계산 도중 다른 탭의 저장 변경, Worker 실패, 저장 실패가 생기면 계산 결과로 기존 운항을 덮어쓰지 않는다.
- 전체 수신함은 기존 사용자 결정대로 탭 한정이다. **선택된 운항에 필요한 변경 근거/확인 이력**은 운항에 포함해 저장·백업하여 탭 캐시가 없어져도 미확인 변경이 사라지지 않는다. 로그 원문/파일 핸들은 저장하지 않는다.

## 남은 범위 / 재현

보류 화물의 실제 하역·처분·반송 조작은 아직 구현하지 않았다. 취소를 확인해도 화물을 지우지 않으며 이 추가 조작의 정책을 임의 결정하지 않는다. 처리한 화물의 구조적 변경을 새 로그만으로 자동 재배치하는 것도 지원하지 않는다.

미션 콘솔에서 로그 계약 선택 → 경로 계산 → 관제 콘솔 운항 시작/픽업 완료 → 미션 콘솔에서 종료 알림이 포함된 로그 선택 → 우측 하단 ‘변경 확인’ → 현재/최근 수신 비교 → ‘확인하고 남은 경로 재계산’. 항해사의 선내 보류 수량과 3D 공간, 나머지 계약 배송, 새로고침/백업을 확인한다. 원본 로그가 없으면 위 브라우저 스크립트가 합성 입력을 생성한다.

다음 우선순위는 기존 개인 장소/별칭 데이터의 새 콘솔 호환성 대조다. 새 편집 UI·팁 센터·이용안내 개편·로그 앱 재작성은 이번 범위가 아니다.
