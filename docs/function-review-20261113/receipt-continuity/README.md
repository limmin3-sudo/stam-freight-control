# 수신함 탭 연속성 — 2026-11-13

사용자 확정: 현재 탭에서만 보관하고 탭을 닫으면 초기화한다. 이미 선택한 운항 계약은 기존 운항 저장/백업 범위로 계속 보존한다.

## 구현

- `receipt-cache.ts`: sessionStorage `stam.receipt-inbox.v1`에 원본 카드와 명시적으로 저장한 보완값을 구분한다. 원본 Game.log 문자열, 파일 경로/handle, 감시 상태는 저장하지 않는다. 자동 시간 만료나 파일 권한 자동 재요청은 없다.
- `use-log-receipts.ts`: 처음 열 때 저장 기록을 읽고, 새로고침 후 실제 연결 상태와 구분한다. 새 로그 선택/자동 수신 결과가 성공하면 교체하고 보완값을 대조한다. 읽는 중·실패 시 이전 카드/보완값을 지우지 않는다. 성공한 새 파일은 해당 파일의 수신함으로 교체하는 기존 규칙을 유지한다.
- 보완은 같은 수주 인스턴스 ID·signature·수신 근거에만 적용한다. 동일 미션 정의/품목이라는 이유로 다른 수주에 복사하지 않는다. 종료/충돌/변경 시 예전 보완을 무효화한다. 미확인 수량이나 보상을 임의 확정하지 않는다.
- `MissionConsole.tsx`, `PilotTopbar.tsx`: 복원 시 “저장 기록 · 로그 미연결”, 탭 보관 안내, 복원/저장 실패 알림. 기존 버튼/테마/사이드바 유지. 자동 수신은 사용자가 다시 파일을 선택해야 시작한다.
- `use-dismissed-receipts.ts`: 실제 로그 카드 삭제/복원 목록도 sessionStorage에 둔다. 기존 예시 카드 정리와 운항 저장은 유지한다. 옛 localStorage 삭제 목록은 읽거나 삭제하지 않는다.
- 저장 실패 시 화면의 보완값을 유지하고 마지막 저장본을 덮어쓰지 않는다. 손상된 저장본은 자동 덮어쓰기하지 않고 로그 재선택을 안내한다. 기존 운항 계약은 건드리지 않는다.
