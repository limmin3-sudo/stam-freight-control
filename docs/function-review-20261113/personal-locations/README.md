## 수정한 단절

기존 `locations.mjs`/`location-manager.mjs`는 `sfc-location-overrides-v1`에 개인 장소와 별칭·좌표 수정본을 저장한다. 새 콘솔의 검색, 직접 입력/OCR 텍스트 해석, 지도, 계산 Worker는 정적 자료를 각각 사용해 이 설정을 읽지 않았다.

- 기존 저장 형식을 읽고 검증하여 거점 검색·별칭 선택·직접 입력·OCR 텍스트 해석·계약 백업 가져오기·지도·경로 계산에 공통으로 연결했다. 기존 저장 바이트는 덮어쓰거나 마이그레이션하지 않는다.
- `draft.locationEdits`에 운항 기준 개인 장소 사본을 보관한다. 계산 Worker는 이 사본을 명시적으로 받는다. 운항 백업도 이 사본을 포함하여 다른 브라우저에서 복원·재계산할 수 있다.
- 기존 계획에 사본이 없으면 이전과 같은 공공 좌표 기준(`[]`)을 유지한다. 나중에 저장된 개인 좌표를 기존 계획에 몰래 반영하지 않는다.
- 저장된 개인 장소가 현재 운항 기준과 다르면 미션 화면에 표시한다. 출항 전 ‘운항 준비에 적용 · 경로 재계산 필요’를 누르면 계약은 보존하고 오래된 계획만 비운다. 운항 시작 후에는 이 버튼을 제공하지 않는다. 정상 운항 완료 후 다음 운송은 새 설정을 읽되 현재 위치를 확인할 수 없으면 기존 운항을 유지한다.
- 잘못된 좌표, 중복 ID, 행성계가 다른 부모, 없는 부모, 순환 부모는 거부한다. 좌표 미확인 장소는 경로와 검색 대상에서 제외하고 기본 좌표로 몰래 되돌리지 않는다.
- 로그에서 이름만 알려진 비항법 장소의 표시/계약 자료는 보존한다. 항법 좌표가 없는 장소를 경로 준비 완료로 처리하지 않는다. 개인 장소의 한국어 별칭을 우선 표시하며 실제 선택 ID는 바꾸지 않는다. 옛 도시 단축 ID는 개인 이름 변경 후에도 같은 도시 ID로 연결한다.
- 지도 데이터는 동일한 개인 사본에 대해 동일 객체를 유지한다. 진행 상태 변경만으로 지도를 재생성하지 않으며 이름 조회는 ID 맵, 검색 후보는 자료 변경 시 갱신하는 캐시를 사용한다.

## 구현 경계

`personal-locations.mjs`는 검증/사본/현재 화면 자료를 담당한다. `mission-trial.ts`, `port-search.mjs`, `contract-intake.mjs`, `ContractFields.tsx`, `contract-backup.mjs`가 이를 사용한다. `NavigationChart.tsx`는 같은 자료로 렌더링하고, `flight-engine.mjs`/`saved-flight.mjs`는 사본을 전달받아 계산한다. `use-flight.ts`의 복원/적용/다음 운송과 `flight-backup.ts` 검증을 연결했다.

새 장소 편집기나 복잡한 설정 화면은 추가하지 않았다. 기존 장소 관리와 원본 저장소는 유지한다. 개별 **계약 목록 백업**은 기존 계약 형식이며 장소 좌표를 담지 않는다. 개인 장소까지 옮기려면 전체 **운항 백업** 또는 기존 장소 백업을 사용한다. 로그의 수주 증거/좌표 판독 인덱스를 개인 별칭으로 대체하지 않는다. 실제 게임 좌표의 정확성을 이 검증으로 보장하지 않는다.
