2026-11-14. 사용자가 세 기능 모두 구현하도록 승인했다. `integration/freight-division-20261113`, HEAD `916b067`와 앞선 미커밋 변경을 보존했다. 커밋·푸시·배포하지 않았다.

## 운항 이어하기

서비스센터 → 계정 → **다른 기기에서 이어하기**. 현재 기기와 계정의 함선·파트너·계약 수·진행·현재 위치·선내 화물을 비교하고 확인한 뒤 저장/불러오기를 선택한다. 다른 기기의 운항이 있으면 공간 화면에도 비교 진입 안내가 나온다.

- 복원 전 현재 운항 백업, 기존 위치/상자 소유권/완료 기록/함선 사본/개인 좌표 유지. 재계산 없이 일시정지 상태로 복원한다. 기존 파일 백업도 유지한다.
- 연결한 운항은 15초 간격으로 변경을 확인해 자동 저장한다. 설정에서 끌 수 있다. 매번 전송하지 않고 마지막 저장 사본의 지문이 달라졌을 때만 압축·전송한다.
- 기기별 수정이 충돌하면 자동 저장을 멈추고 비교를 요청한다. 서버 리비전을 트랜잭션으로 검사하고 오래된 선택으로 덮어쓰지 않는다. 늦은 응답은 원래 계정에만 속하며 현재 계정 화면에 적용하지 않는다.
- `users/{uid}/flight/current`와 하위 `parts`에 gzip/base64 분할 저장한다. 기존 설정·완료 기록 동기화와 리비전을 분리했다. 최대 600,000문자씩 나누며 전체 원문 20 MiB/압축 인코딩 8,000,000문자 상한을 적용한다. 초과/오프라인/권한 오류 때 로컬 운항을 유지한다.
- 읽을 때 앞뒤 리비전, 조각 리비전, 길이, SHA256, 압축 해제 상한과 기존 운항 검증을 확인한다. 이전 버전의 불필요한 조각은 새 저장 트랜잭션에서 삭제한다.
- 계정의 인라인 화면이 인증 완료 뒤에도 로그인 폼을 남기던 문제를 수정했다. 새 비교 화면의 중복 외곽 프레임도 제거했다.

**운영 경계:** 이번 `firestore.rules`에는 계정 운항/조각 경로 권한이 추가됐다. 운영 규칙과 웹을 아직 게시하지 않았으므로 현재 공개 사이트에서 새 이어하기가 작동한다고 안내하면 안 된다. 실제 Firebase 로그인/운영 요청은 하지 않았다. 향후 이 기능을 배포할 때 규칙 게시가 함께 필요하다. 로그 앱 개편·실게임 확인을 이번 완료에 포함하지 않는다.

## 아카이브

아카이브 본문의 **함선 자료 / 화물 자료** 카드로 진입한다. 승인 사이드바에 새 세부 펼침을 만들지 않았다.

- 함선: 97개 구성 검색, 최소 적재량 필터, 총 SCU, SCM/NAV, 기본 퀀텀 드라이브, 구역별 치수/용량/상자 제한, 원본 출처·버전. Galaxy 모듈별 구성을 분리한다. 치수 대조 예외/이전 버전 유지도 표시한다. 자료 조회가 실제 운항 함선을 바꾸지 않는다.
- 화물: 현재 미션 자료의 품목을 모아 한/영 검색, 계약별 목록 상자 규격·단위·관련 미션 수를 제공한다. 관련 미션 버튼으로 검색어가 적용된 미션 자료를 연다. SCMDB 우선/Wiki 보완 정책과 공식 표시명을 재사용한다. 수주 수량이나 거래 가격을 추정해 만들지 않는다.
- 함선 조회 때 미션 전체를 불러오지 않도록 함선/화물 자료 로딩을 분리하고 각각 캐시한다. 실패하면 재시도할 수 있다. 기존 서체/유리 패널·금색 선택 강조를 적용했다.

## 지도

입체 항로지도 안의 **실사 / 홀로그램** 버튼으로 바꾼다. 선택은 브라우저에 저장되며 관제 지도에도 적용된다. 기존 비교 URL `chartLook=hologram`은 유지하고, 사용자가 버튼으로 고르면 저장 설정이 적용되도록 URL 임시 선택을 해제한다. 운항 자료를 변경하지 않는다.

테마 전환 시 항성계·선택 위치·확대/회전 상태를 복원하고 이미 실행한 카메라 명령을 다시 재생하지 않는다. 궤도/검색/경로·현재 작업·역할별 적재 정책을 유지한다. 고정 상단바·사이드바는 재디자인하지 않았다.
