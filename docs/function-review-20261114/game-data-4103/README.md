## 갱신 코드

- `scripts/wiki-mission-supplement.mjs`: 제목이 같은 레코드의 페이지 경계 중복을 확인했다. 제목 오름차순에서 UUID 1개가 누락됐다. 역순 조회를 합쳐 **원본 total만큼 고유 ID가 확보된 경우에만** 적용한다. 순서가 달라지는 blueprint 목록만 정규화하고 실제 값 충돌/버전 혼합/총수 부족은 거부한다.
- `scripts/refresh-fleet.mjs`: 버전을 고정한 전체 페이지 및 각 함선 상세 자료를 읽고, 실제 기본 장비 ID를 대조한다. 함선·성능·드라이브·로그 식별자·그리드 대조 결과를 묶어서 검증한 후 저장하며 실패 시 이전 파일을 복구한다. 버전이 다운로드 중 변경돼도 적용하지 않는다.
- 기존 `refresh-performance.mjs`, `refresh-quantum.mjs` 명령도 전체 묶음 갱신을 호출한다. 서로 다른 버전의 두 파일만 따로 저장하지 않는다.
- `.github/workflows/pages.yml` 일일 갱신에 함선 묶음을 추가했다. 실제 원격 워크플로 반영은 추후 커밋·푸시/배포 후다. 함선 API/검증 실패 시 워크플로가 중단되므로 기존 배포가 유지된다.
- `scripts/refresh-data.mjs`: 지도와 로그 매칭 좌표를 같은 원본으로 생성한다. `integration/log/locations.mjs`는 기존 null 버전 자료와 올바른 LIVE 버전 모두 수용하며 PTU/잘못된 버전은 거부한다.
- 이전 로그의 class 이름은 legacy 출처/버전을 붙여 유지한다. 이전 운항/선내 화물/개인 장소/사용자 보정 데이터를 마이그레이션하거나 삭제하지 않는다.

## 보존 및 자료 한계

- **Phoenix Emerald**: 이전 UUID의 4.10.3 상세 조회가 404이고 현재 목록에도 동일 변형이 없다. 일반 Phoenix로 대신 연결하지 않는다. 성능과 모든 호환 드라이브 선택지를 기존 버전으로 보존하고, 계산 결과에 이전 자료 사용 경고를 넣었다. 4.10.3으로 표시하지 않는다.
- Andromeda·Aquila는 현재 목록의 같은 변형 GS UUID로 명시적으로 연결했다. 다른 이름의 함선을 유사도만으로 임의 선택하지 않는다.
- `data/ship-grid-audit.json`에 치수/용량 대조, 커뮤니티 원본 SHA256, 자료 미일치 항목을 저장했다. Wiki는 그리드 부착 위치/회전을 충분히 제공하지 않으므로 이 결과가 전체 선체 배치 실측 검증을 뜻하지 않는다.
- Hermes·Zeus CL·Zeus ES의 `reference-hull` 배치는 기존에 보정해 둔 배치다. 최신 커뮤니티 원본과 다른 것을 확인했지만 기존 보정을 보존했다. 최종 `data/ships.json`은 작업 전과 동일하다. 향후 자동 갱신도 이 보정 배치를 덮지 않는다.
- 비교 불일치: Hammerhead(로컬 적재 40 / Wiki 명목 64), Idris-P, 화물 모듈 Retaliator, Caterpillar, Ironclad(로컬 2160 / Wiki 2200), Syulen, Hull C, Phoenix Emerald. 단순한 용량 차이만으로 부착 위치나 자동 적재 가능 구역을 새로 만들지 않았다.
- Wiki LIVE 차량 목록에는 게임 내부/NPC/파생 자산도 있다. **Lib­erator·Galaxy·Hyun 등의 식별 정보는 갱신됐지만, 현재 선택 목록에 없는 함선의 검증된 적재 배치까지 새로 구현한 것은 아니다.** 해당 미지원 목록은 그리드 감사 파일에 남겼다. 신규 선택 함선 추가와 실제 그리드 확보는 별도 남은 작업이다.
- STAM 공식 한글 원본 패치는 새 원본을 확보한 것이 아니다. 기존 번역과 자동 보완 이름을 유지하고, 현 자료 기준 표시 이름 목록만 재생성했다.

## 이어서 받을 때

이 문서와 변경된 데이터/스크립트를 함께 받아야 한다. 현재 자료 기준 미리보기는 빌드에 반영돼 있지만 공개 사이트는 아직 이 작업본이 아니다. 공개 반영 승인을 받은 뒤 기존 미커밋 UI 작업과 함께 검토·릴리스 기록·커밋·푸시·Pages 확인을 진행한다. 운영 Firebase 규칙/실계정·실게임 검증은 이 데이터 갱신으로 완료되지 않는다.
