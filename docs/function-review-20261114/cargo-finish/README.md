# 적재 3D 재질·조명 보강 — 2026-11-14

기능 클라우드 / `integration/freight-division-20261113`, 기준 HEAD `916b067` 이후 작업본. 앞선 서비스센터·FLIGHT CONSOLE·지도 변경을 보존했다. 커밋·푸시·배포하지 않았다.

## 구현

- `cargo-look.ts`: 도장 요철, 도장 거칠기, 금속 거칠기를 분리했다. 선형 데이터 텍스처로 관리하고 화면 생성 시 한 번 만들어 공유한다. 기존 배송지 색과 실제 SCU 식별판은 유지한다.
- 기존 기본 실내 반사 환경 대신 좁은 면광원과 넓은 보조광의 정적 반사 환경을 구성했다. 이 환경은 재질 조명에만 쓰며 가상의 함선 내부나 방 바닥을 화면에 추가하지 않는다.
- `cargo-scene.ts`: 도장면의 금속성을 줄이고 거칠기를 조정해 중성 금속 프레임과 구분했다. 프레임/코너에 얇은 곡면을 적용하되 기존 상자 치수 안에 둔다. 실제 화물 좌표·소유권·적재량은 바꾸지 않는다.
- 기존 캐시·인스턴스 묶음·정지 화면의 요청 기반 렌더링·적재 변경 때만 그림자 갱신을 유지한다. 같은 물체에 매 프레임 반사 패스를 추가하지 않는다. 곡면으로 정점 수는 늘어나지만 같은 크기/재질의 프레임은 기존 묶음으로 그린다.
- 실제 함선 적재구역만 표시하며 금색 부착면, 회전/하향 부착, 구역 선택, 배송지 색, 상자 클릭을 유지한다. 공통 CargoViewport를 사용하므로 지도 미리보기·항해사 관제·적재 작업 화면에 함께 적용된다. 역할 선택/오퍼레이터 정책은 수정하지 않았다.

## 검증

TypeScript 및 생산 빌드 통과. 기존 대형 청크 경고는 남는다.

생산 빌드 실제 앱에서 예시 계약 선택→경로 계산→적재 미리보기→실제 상자 클릭/계약 확인→시점 변경·확대→운항 상태 보존을 확인했다. 개발 모듈 직접 확인은 Cutlass Black/Hull B/RAFT/Golem OX의 기존 배치 불변, 카메라 보존, 구역 끄기/다시 켜기/전체 끄기를 확인했다. 페이지/셰이더 오류 없음. `browser-check.txt`.

재현:

```sh
STAM_MISSION_URL=http://127.0.0.1:5199/stam-freight-control/ STAM_CARGO_MODULE_URL=http://127.0.0.1:5188/ STAM_QA_OUTPUT=/tmp/stam-cargo-review node scripts/check-cargo-detail-browser.mjs
```

첫 URL은 생산 빌드 미리보기, 두 번째는 동일 작업본 Vite 서버다. 프로필별 확인은 개발 모듈, 사용자 동선은 생산 빌드로 구분한다. 실제 GPU 장시간 FPS/VRAM·실게임 적재 치수는 이번 확인 범위가 아니다. 새로운 고해상도 사진 자산을 제작한 작업도 아니다.
