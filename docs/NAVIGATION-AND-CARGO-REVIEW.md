## 적재 3D 후속 — 컨테이너 구조와 선택

사용자가 지도 표현 선택 후 다음 단계로 진행하도록 요청하여 적재 표현을 보강했다. 도색 본체가 외곽 프레임을 덮던 구조를 수정해 패널을 안으로 넣고, 프레임·모서리·잠금봉·손잡이가 실제 깊이를 갖게 했다. 배송지별 도색, 실제 그리드의 금색 부착면, 부착 방향과 기존 패킹 좌표는 유지한다. 새 함선 외형이나 방 바닥은 추가하지 않았다.

SCU 명판은 표면 UV에서 분리한 2:1 물리 패널로 만들었다. 긴 상자에 글자가 늘어나지 않으며 규격별 질감을 공유한다. 본체뿐 아니라 프레임·잠금장치·명판을 클릭해도 같은 `boxId`의 화물이 선택된다. 인스턴싱과 주문형 렌더링을 유지하며, 적재 화면의 남은 Oxanium 서체를 SUIT로 통일했다. 컨테이너는 절차적 도색과 3D 구조로 만든 표현이고 게임 원본 모델이 아니다.

검증: TypeScript/Vite 빌드, `cargo-plan.test.ts`, 실제 앱 브라우저 검증 통과. 합성 미션의 실제 계산 배치에서 클릭·시점 변경·확대·운항 상태 보존을 확인했다. 동일 그리드 갱신 시 카메라 유지, Cutlass/Hull B/RAFT 표시, 비활성 그리드 제외와 복구도 확인했다. 셰이더/페이지 오류 없음. 캡처는 1600×1000, 소프트웨어 GPU이며 실기기 성능 결과는 아니다.

```sh
node --experimental-strip-types --test apps/control-room/tests/cargo-plan.test.ts
npm run build:control-room
# 실행 중인 Vite 필요. 주소·출력 폴더는 환경 변수로 변경 가능.
STAM_QA_OUTPUT=/tmp/stam-cargo-review node scripts/check-cargo-detail-browser.mjs
```

`cargo-hold.png`, `cargo-detail.png`는 실제 앱의 거점 작업 후 적재 모달이다. 커밋·푸시·배포하지 않았다. 지도 항성의 승인된 중간 개편본은 변경하지 않았다. 현재 천체 표현의 최신 기록은 `CELESTIAL-MATERIALS-REVIEW.md`를 참고한다.

## 구현 기준

미션 콘솔 승인 시안에 이어 모니터 안을 채우는 지도 화면을 구현한다. 영상 접근/복귀와 공간 연출은 별도 담당이다. 실사 질감을 가진 천체·화물에 홀로그램 항로·그리드·조작 UI를 결합하며, 장식 때문에 기존 기능을 줄이지 않는다.

| 영역 | 재사용한 기능 | 이번 변경 |
| --- | --- | --- |
| 지도 카메라 | `starmap.mjs`의 원근 카메라, 감쇠 회전, 화면 기준 이동, 로그 거리 확대 | 현재 React 앱에서 원래 엔진 직접 사용. 우클릭/Shift 이동, 휠, 핀치, 더블클릭과 Esc/F 유지 |
| 지도 탐색 | 전체 항성계→항성계→행성/위성, 거점 검색, 구간 맞춤 보기 | 왼쪽 지도·오른쪽 방문 순서, 전체/위 시점·확대·궤도·화질 조작 |
| 천체 표현 | 원래 위치/위계와 천체 회피 항로 | 기존 표면 이미지, 지형/대기 셰이더, 어두운 성운 배경, SUIT 레이블. Bloom 켜지 않음 |
| 운항 데이터 | 기존 `useFlight`와 계산된 visits/packing | 방문 선택은 보는 구간만 바꾸며 실제 운항 진행은 변경하지 않음 |
| 관제 지도 | 기존 관제 패널과 실제 운항 위치 | 새 지도와 같은 NavigationChart/원래 조작 엔진 사용 |
| 화물 | 기존 함선 그리드, 상자 치수·소유권·회전 부착면 | 실제 도색 면/금속 프레임, 반투명 경계, 부착면 그림자. 같은 그리드의 화물 갱신 시 카메라 유지 |
| 거점 적재 확인 | 각 방문 작업 후 packing | 항해사의 방문 카드에서 3D 미리보기. 오퍼레이터 경로에는 적재 계산/미리보기 추가 안 함 |

천체 표면은 기존 시각 자료와 절차적 재질을 이용한 표현이며 게임 원본 지형과 일치한다고 주장하지 않는다. 천체 크기와 근접 간격은 읽기 쉬운 표시 축척이다. 경로 엔진의 거리·좌표를 바꾸지 않는다. 적재 공간 밖의 가상 함선 외형이나 방 바닥은 만들지 않는다.

## 파일과 연결

- `MapConsole.tsx`, `map-console.css`: 지도와 방문 순서, 거점 적재 미리보기.
- `NavigationChart.tsx`, `chart-appearance.ts`: 원래 지도 엔진의 React 수명 관리와 재질/언어 어댑터.
- `starmap.mjs`: 선택적인 표현 어댑터, 휠과 같은 계산을 쓰는 확대 버튼, 궤도 표시, 드래그의 오선택 방지. 기존 호출은 기본 표현 유지.
- `mapfx.mjs`: 레이블 서체 선택 지원. 기존 호출의 기본 서체 유지.
- `SpaceExperience.tsx`: map 경로의 내부 화면 연결과 Escape 소유권만 변경. 장면/영상 자산 변경 없음.
- `OperationsMap.tsx`: 같은 NavigationChart 재사용.
- `cargo-scene.ts`, `cargo-look.ts`, `cargo-workspace.css`: 재질·그림자·그리드 깊이감, 시점 보존, 우클릭 선택 방지.

기존 `hologram-scene.ts`와 관련 시안 파일은 삭제하지 않았다. 이번 실행 화면은 starmap 엔진을 사용한다. 전체 콘솔을 한 번에 재작성하거나 계산 엔진을 새로 만들지 않았다.

## 검증 명령

```sh
npm test
npm run test:control-room
npm run build:control-room
# 실행 중인 Vite가 필요. STAM_MISSION_URL로 주소 변경 가능.
node scripts/check-navigation-browser.mjs
```

브라우저 검증은 합성 예시 계약으로 수행한다. 원래 카메라 회전/우클릭/Shift 이동/휠, 행성·위성 검색과 항성계 이동, 구간 선택, 상자 소유권 선택, 미리보기의 운항 상태 보존, 언어/모바일과 관제 공용 지도, 화물 갱신 시 카메라 유지가 대상이다. 실제 사용자 게임 운항과 실기기 GPU 성능은 이 검증으로 대체하지 않는다.

실행 결과: 루트 232개, 앱 12개 테스트 파일, TypeScript/Vite 빌드 및 위 브라우저 검증 모두 통과했다. 브라우저 검증은 1440/390 CSS 픽셀 폭, 소프트웨어 GPU·0.5 픽셀 비율로 실행했다. 별도 시각 검토 캡처는 1600×1000·픽셀 비율 1로 남긴다. 빌드의 큰 chunk 경고는 남아 있다.

검수 중 검색 테스트가 언어 선택의 네이티브 option을 클릭하던 문제와 카메라 명령 적용 전 상태를 읽던 문제를 수정했다. 확대 시 지명표가 천체를 가리는 문제, 저프레임에서 감쇠가 지나치게 느려지는 문제도 보완하고 카메라 동작을 다시 확인했다. 방문 카드를 누를 때 이전 탐색 거점 이름이 남지 않도록 선택 정보도 동기화한다.
