## 2026-11-11 집 PC 작업 종료 시점

작업 브랜치는 `handoff/local-studio-20261110`이며 출발 커밋은 `1e40df9`다. 이 브랜치의 최신 커밋을 기준으로 이어간다. 기존 폴더에서는 먼저 `git status -sb`로 브랜치와 미커밋 작업을 확인한다. 재작성 이전 사본만 있으면 아래 clone 절차로 새 폴더에 받는다.

**다시 여는 방법** — 저장소 루트에서 `start-control-room-preview.cmd`를 실행하고 [미션 콘솔](http://127.0.0.1:5173/#/mission?lang=ko)을 연다. 계약 수신함에서 예시 계약을 불러와 **전초기지 보급**을 펼치면 픽업 2곳·배송 2곳·화물 2종을 확인할 수 있다. 체크 후 **선택한 계약 담기 → 예시 항로 검토 → 운항 관제로** 진행한다. 로그 시험은 [합성 로그](handoff-media/2026-11-11/synthetic-receipts.txt)를 별도 폴더에 `Game.log`로 복사한 뒤 미션 콘솔에서 선택한다. 정상 기대값은 카드 2장, 선택 가능 1건, 포트 트레슬러에서 로빌로 8 SCU다.

**현재 화면** — 라운지 원본의 터미널·접수 직원 부분만 합성했고, 디렉터는 데스크 앞 별도 레이어다. 데스크는 튜토리얼, 이용안내는 중앙 서비스센터, 앱 다운로드는 상단에 있다. 관제센터는 어두운 원본 위에 왼쪽 오퍼레이터와 오른쪽 항해사를 배치했다. 라운지·관제센터에는 금색 원형 선택점이 있다. 미션 콘솔은 SUIT/Oxanium과 함교 버튼을 사용하며 계약 수신함과 이번 운송 목록이 분리돼 있다.

**미션 처리 범위** — 파일 선택 시점의 게임 로그를 로컬에서 한 번 읽는다. 계약별 복수 화물·픽업·배송을 유지하고, 기존 STAM 규칙으로 배송 총량을 확인할 수 있는 경우에만 예약한다. 종료·충돌·미확정 카드는 상태를 표시한다. 운송 계획은 탭에 저장되고 원본 로그는 저장하지 않는다. 현재 지도는 네 행성 시안으로, 그림에 없는 거점은 방문 목록에서 확인한다. 운항 관제는 첫 거점 안내까지 동작한다.

**다음 작업 순서**

1. Windows 연결 앱의 실시간 계약 수신을 새 미션 콘솔에 연결한다. 앱에서 새 계약을 받거나 재연결해도 기존 선택·운송 계획이 유지되는지 확인한다. 실제 사용자 로그를 저장소에 넣지 않는다.
2. 미션 콘솔의 계약 순서 예시를 기존 파트너별 항로·적재 계산에 연결한다. 계약별 화물 소유권, 미확인 픽업 분배, 운항 재개 시 적재 위치를 보존한다. 출항 검토에서 실제 방문 순서와 적재를 확인하고 운항 관제에서 작업 완료·되돌리기를 연결한다.
3. 화면 동선이 정해지면 안내데스크→디렉터, 게이트 접근, 미션 콘솔→지도, 지도→운항 관제 전환 영상을 검토한다. 기존 [라운지 시험 영상](handoff-media/2026-11-11/20261110-210036-30ff3d.mp4)은 목표 아치 접근이 불충분해 미채택이다. 모델·시드·실제 출력 규격과 프롬프트는 [시험 기록](handoff-media/2026-11-11/video-test.json)에 있다.

**검증 기록** — 관제실 빌드 및 테스트 12개 통과. 브라우저에서 합성 로그 읽기, 정상·불완전 카드 구분, 지도·관제 이동, 수신함 복귀를 확인했다. 기존 앱 전체 회귀에서는 Windows에서 `/tmp` 고정 경로를 쓰는 `release-module-urls` 테스트 한 건이 실패했다. 사용자 게임 세션에서 실시간 수신 검증은 남아 있다.

## 사용자 확정 방향

- 밝은 지상 공간 이름은 **STAM 라운지**. **STAM 본부**는 향후 여러 사이트 통합용으로 남긴다.
- 왼쪽 안내데스크는 기존 튜토리얼 파트너. 가운데 터미널/우주선 탑승 게이트, 오른쪽 정보실·영상관. 관제센터는 우주에 있다.
- 어두운 우주 관제센터, 좌우 다른 오퍼레이터들은 착석, 사용자 좌석은 양쪽 하나씩 비워 둔다. 왼쪽 미션, 오른쪽 운항/적재. 중앙은 **스탠턴 항성계**. 지구 전경을 실제 게임 지도로 오인하지 않는다.
- 사물을 선택하면 짧은 접근 연출 후 실제 UI. 호버/포커스에 사물 윤곽과 선택형 효과음. 의자가 살짝 뒤로 빠지는 연출은 별도 레이어·배경 복원으로 후속 구현.
- 화면 상하단 UI와 원본 STAM 로고, SUIT/Oxanium 글꼴, A 글라스 분위기 유지. 나중에 이미지/배치/색/전환을 바꿀 수 있게 분리.
- **폐기:** 관제실 전체 3D 모델링, 자유 보행/WASD, 지도 뒤편 콘솔/모니터, 180도 회전, Blender 준비·3D 자산 구매 계획. 실제 항로 지도·적재 3D까지 폐기한 것이 아니다.
- 지도는 고품질 행성, 굵은 홀로그램 경로/사인/정거장 아이콘. 적재는 밝은 배경과 금속 화물/공간 그리드. 실제 좌표·직선 퀀텀/천체 회피·계약 소유권·기존 저장 유지, bloom 비활성.
- 튜토리얼은 핵심 화면 이후 기존 파트너가 실제 사이트 위에서 안내. Bokoko33의 방은 사물 선택 경험 참고다.
- 연결 앱의 설치 아이콘·자동 로그 찾기·선택형 게임 오버레이는 이후 범위. 계획은 로드맵에 보존돼 있다.

## Gen Studio — 사용자가 전달한 로컬 진단

클라우드가 직접 실행한 진단이 아니다. 집 PC의 로컬 Codex 보고를 사용자가 전달했다.

## Git과 이전 PC 충돌 방지

이 묶음은 `.git` 없는 **전체 소스 스냅샷**이다. 최신 Git 이력을 대신하는 저장소가 아니다. 미리보기는 그대로 실행할 수 있다.

- 원격: `https://github.com/limmin3-sudo/stam-freight-control.git`.
- 정확한 기준 SHA/브랜치/변경·삭제 목록은 ZIP 루트 `TRANSFER-MANIFEST.json`에서 읽는다.
- 과거 재작성 전 체크아웃/객체를 가져와 합치거나 push하지 않는다. 클라우드의 폐기 경로를 복구하지 않는다.
- Git 연결이 필요하면 **새 빈 경로**로 현재 원격을 clone하고 manifest 기준 커밋이 그 새 이력에 있는지 확인한다. 원격이 그 이후 전진했으면 차이를 먼저 검토한다.
- 새 clone에서 기준 커밋에 로컬 작업 브랜치를 만든 다음, 검증된 source 파일을 복사해 미커밋 변경으로 복원한다. manifest의 삭제 목록도 따로 대조한다. 기존 작업 폴더를 reset하거나 덮어쓰지 않는다.
- `git init`으로 별도 루트 이력을 만든 뒤 기존 저장소에 합치지 않는다. 클라우드에서 커밋/푸시/배포하지 않았으며 로컬에서도 별도 승인 없이 하지 않는다.
