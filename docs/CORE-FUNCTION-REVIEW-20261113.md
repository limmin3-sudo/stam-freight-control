## 바로 시작할 첫 작업

**미션 콘솔의 유효 적재 용량부터 표시/계산을 일치시킨다.** 기존 미션 선택과 계약 데이터를 유지한 상태로 Cutlass Black의 구역 하나를 끄고, 미션 요약 → 계산 결과 → 관제 적재의 용량이 같은 기준인지 확인한다. 관련 파일은 MissionConsole.tsx / use-flight.ts / cargo-plan.mjs / CargoWorkspace.tsx. 함선 선택을 두 군데에서 바꿀 때 실제 항로 함선과 미리보기 함선을 혼동하지 않게 해야 한다. 기존 선적을 재배치하거나 기능을 삭제하지 않는다.

이번 턴에서는 이 수정까지 실행하지 않았다. 전체 기능 목록을 다시 감사한 결과와 다음 작업의 완료 기준을 정리했다. 이전 테스트 결과는 `function-review-20261113/integration/README.md`, `function-review-20261113/archive-reference/README.md`를 참조한다. 제품 코드를 바꾸지 않아 전체 테스트/빌드를 다시 돌리지 않았고 문서·Git 차이를 확인했다.


## 2026-11-13 후속 구현 — 1번 적재 용량

- 미션 표시·적재 미리보기·경로 Worker가 `ship-profile.mjs`의 동일 프로필 해석을 사용한다. 비활성 그리드는 용량/배치에서 제외하고 원래 bin 인덱스는 유지한다.
- 미션 요약은 “사용 가능한 적재 용량”으로 표시한다. 그리드 토글 저장 이벤트로 즉시 갱신하며, 운항 중에는 저장된 계획의 함선을 기준으로 표시한다.
- 적재 상세는 이번 운송의 함선으로 시작한다. 다른 함선을 별도로 살펴볼 수 있고, 그 경우 이번 운송의 함선이 바뀌지 않는다는 안내를 표시한다. 미션에서 함선을 변경하면 열려 있는 상세도 따라간다.
- 기존 customShip의 치수·비활성 플래그·부착 좌표를 보존한다. 기본 함선과 ID가 같은 복원 프로필도 기본 프리셋으로 덮어쓰지 않는다. 새 그리드 편집기는 추가하지 않았다.
- 2~5번은 미완료다. 운항 중 계약 변경 알림→확인→남은 경로 재계산 정책 자체는 아직 구현하지 않았다.

검증 결과: 루트 238개·앱 64개·TypeScript/Vite·Chromium 화면 조작 통과. [상세 기록/캡처](function-review-20261113/cargo-capacity/README.md). 미커밋·미배포.


## 2026-11-13 후속 구현 — 2번 수신함 연속성

사용자가 ‘현재 탭에서만 보관하고 탭을 닫으면 초기화’를 선택했다. 수신 카드/저장한 보완값/실제 수신함 삭제 목록을 sessionStorage에 보관한다. 새로고침 후 자동 감시는 시작하지 않으며 상단에 저장 기록·로그 미연결로 표시한다. 선택 운항은 기존 저장으로 유지한다. [구현/검증 기록](function-review-20261113/receipt-continuity/README.md).

새 수신 결과의 수주 ID·signature·근거가 달라지거나 종료/충돌 상태가 되면 이전 보완값은 적용하지 않는다. 읽기/저장 오류와 손상된 캐시에서도 현재 운항을 삭제하지 않는다. 3~5번은 아직 미완료다.
