# Codex Cloud 새 작업에 붙여넣을 내용

아래 내용을 저장소 `limmin3-sudo/stam-freight-control`를 선택한 Cloud 작업에서 사용한다. 이 문서는 새 Cloud 작업을 자동으로 만들거나 기존 로컬 대화를 옮기지는 않는다.

---

이 저장소의 STAM FREIGHT CONTROL 개발을 이어서 진행해 줘.

먼저 현재 브랜치와 미커밋 변경, GitHub 최신 이력을 확인하고 기존 작업을 보존해 줘. AGENTS.md, docs/DEVELOPMENT.md, PROJECT_STATUS.md, docs/CLOUD-HANDOFF.md, README.md를 읽고 실제 코드와 테스트로 현재 상태를 확인해 줘. a445f8ff925457bfe9f3c32c814fcccf1840147f는 마지막 기능 배포 기준이지만, 이후 변경을 버리거나 그 커밋으로 되돌리지 마.

함선 51종, 미션 OCR·수정·상자 구성 템플릿, 3D 지도·적재, 운항 파트너 3명, 함선별 비행 성능·Atlas/Hemera/Erebos 자동 설정과 수동 수정은 구현돼 있어. 서로 다른 미션의 화물 소유권을 반드시 분리하고, 현재 그리드 중심 화면·파트너 말투·지도 배경색을 유지해 줘.

제품 백로그에는 게스트 사용을 유지하면서 Google 로그인과 사용자별 설정·미션 저장을 연결하는 작업이 있어. 실제 수행할 작업은 사용자의 현재 요청과 PROJECT_STATUS.md를 먼저 확인해서 정해 줘. Firebase를 제안받았지만 아직 프로젝트 연결이나 로그인·동기화는 구현되지 않았어. 이 Cloud 환경에서 실제로 쓸 수 있는 연결과 필요한 사용자 설정부터 확인해 줘. 다른 사용자의 데이터를 읽거나 덮어쓰지 않도록 권한과 계정별 캐시를 분리하고, 처음 로그인할 때 게스트 데이터와 저장된 데이터가 충돌해도 조용히 덮어쓰지 마.

node scripts/prepare.mjs로 라이브러리·좌표를 준비하고 npm test를 실행해 줘. 이전 기준은 테스트 32개 통과야. Node 22 기반이며 실제 API 키 없이 기존 로컬 기능과 테스트를 사용할 수 있어.

설명은 한국어로 간단하게 해 줘. 앱 문구는 자연스러운 존댓말로 유지하고, 일상적인 수정마다 재확인하지 말고 진행해 줘. 다만 계정 연결·사용자 로그인·약관 동의·실제 권한 부여는 필요한 시점에 안내해 줘. 비밀키나 이전 컴퓨터의 파일·로그인이 이 환경에 있다고 가정하지 마.

작업 종료 전 PROJECT_STATUS.md에 변경·검증·남은 문제·다음 단계를 기록해 줘. 커밋·푸시는 사용자 승인 후 진행해 줘. 배포는 GitHub Pages를 유지하고, 기능 배포가 승인돼 실행된 경우 테스트와 실제 배포 결과까지 확인해 줘. 이전 로컬 대화 전체를 알고 있다고 가정하지 말고 이 인수인계와 최신 코드를 기준으로 이어가 줘.
