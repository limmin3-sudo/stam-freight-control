# 로그 연동 운송 준비 흐름

2026-11-04 KST. 사용자 제안에 따른 다음 UI 개편안. **이 문서는 아래 전체 흐름의 구현 완료를 뜻하지 않는다.** 기존 기본 화면 배치·관제 모드는 유지한다.

## 사용 흐름

1. 최초 한 번 로그를 연결한다. 평소에는 파트너를 고르고 운송 준비 화면에서 기다린다. 로그인은 선택이다.
2. 함선·출발지 카드는 검증된 본인 감지 값을 우선 표시하고 수정은 접힌 기능으로 제공한다. 현재 함선/위치를 확인하지 못했으면 이전 설정임을 표시한다. 이전 선택을 현재 감지 값으로 승격하지 않는다.
3. 계약 수락 시 실행 ID별 카드에 자동 반영한다. `준비 3건 · 정보 확인 중 1건`처럼 계약별 상태를 보여준다. 수동 계약 추가·명세 편집은 보조 기능으로 내린다.
4. 주 버튼 하나가 `로그 연결` → `계약 수신 대기` → `준비 정보 확인` 또는 `경로 계산·운송 시작` → `운송 안내 중`으로 바뀐다. 계산 가능한 선택 계약이 있으면 선택한 파트너 정책으로 계산하고 지도·적재 안내를 시작한다. 준비 화면에서 공개/실제 정보 확인이 필요한 부분만 수정한다.
5. 계산 실패·상자/배분 충돌 시 해당 오류를 표시하고 안내 시작으로 넘어가지 않는다. 운송 중에는 수정/재계산·실제 진행 보존 규칙을 따른다. 새 계약이 들어와도 이미 실린 위치나 완료 상태를 초기화하지 않는다.

## 상태를 구분하는 기준

- 로그 연결됨 ≠ 모든 계약 정보 수신됨 ≠ 현재 위치 실시간 동기화됨.
- 카드의 값마다 `감지됨 / 이전 설정 / 직접 지정 / 확인 필요`와 마지막 관측 시각을 구분한다. 현재 조종 함선은 채팅 채널 참여나 보유 목록만으로 확정하지 않는다.
- 계약 수신 완료를 조용한 시간 몇 초가 흘렀다는 이유로 선언하지 않는다. 선택한 계약의 품목·총량·거점 배분·상자 근거 등 필요한 필드로 준비 여부를 계산한다.
- 미확인 계약을 몰래 제외해 ‘전부 준비됨’으로 표시하지 않는다. 다른 준비 계약만 진행하려면 그 선택 범위를 분명히 표시한다. 계약 0건이면 출발 버튼을 활성화하지 않는다.
- 실제 출발 위치가 없을 때 저장된 출발지는 후보일 뿐이다. 사용자가 확인하거나 직접 지정하기 전에는 실제 현재 위치라고 표시하지 않는다.
- `운송 시작`은 STAM의 안내 시작이다. 게임 입력·매크로·함선 조작을 수행하지 않으며 실제 출항/적재/배송/보상 완료로 기록하지 않는다. 실제 위치 공급이 없으면 `예상 이동`을 표시한다.
- 개인 장소 좌표는 예상 경로에만 사용한다. 공개 로그 마커 판별 근거와 분리한다.

## 구현 순서

1. 현재의 계정·개인 장소·업데이트·피드백 연결을 완료한다.
2. 본인 함선/위치 관측 어댑터와 세션 복원을 검증하고, 없는 관측은 미확인으로 남긴다.
3. 계약 전에도 파트너 선택·연결 상태·함선 후보를 볼 수 있는 준비 화면을 만든다.
4. 기존 여러 입력 단계와 시작 버튼을 위 상태 기반 주 버튼으로 통합한다. 지도·적재·기존 배치는 유지한다.
5. 최종 검증에서 미확인 값·충돌·재연결·부분 적재 중 추가 계약을 포함해 확인한다.

현재 상태: 기존 계약 자동 선택/계획과 예상 이동 기능은 연결돼 있다. 이 준비 화면과 검증된 함선/현재 위치 자동 채움은 아직 구현 전이다.
