# 유형 ID 목록과 실제 계약 대조 — 2026-11-03

## 결론

후속 작업에서 부모 행성/위성 기준 XYZ로 이번 6개 지표 마커의 거점을 대조했다. [위치 대조와 복귀 알림](LOG-LOCATION-EVIDENCE.md)이 최신 위치 확인 범위다. 아래의 미확인 설명 중 실제 거점 선택은 이 부분까지 진전됐으며, 주문별 할당과 실제 상자 구성은 여전히 미확인이다.

로그의 계약 정의 ID로 공개 목록을 찾는 방식은 사용할 수 있다. 이번 두 유형은 원본의 품목·주문 수량·품목별 상자 상한을 찾았고, 중형의 화면상 수량 및 대형의 로그상 수량과 일치했다. 이전의 ‘로그에 명세가 없다’는 분석은 이 공개 정의 대조를 대체하지 않는다.

다만 **유형 정의, 이번 실행에서 선택된 거점, 실제 상자 구성**은 서로 다른 정보다. 공개 정의를 조회했다고 이번 계약의 모든 필드가 확정된 것은 아니다. 구현은 정의 규칙을 자동 조회·표시하며, 아직 미확인인 실행 명세를 경로/적재 엔진으로 넘기지 않는다.

## 수량이 고정인지에 대한 정확한 범위

두 유형의 각 주문은 `max_scu`에 위 숫자, `min_scu`에는 `null`을 반환한다. 제공자의 [API 변환 소스](https://github.com/StarCitizenWiki/API/blob/fab953d20b6d6c485c2430066e0a03a7db6fbbb6/app/Http/Resources/Game/Mission/MissionHaulingResource.php)는 원본 두 수량 필드를 정렬하고 0/누락 경계를 `null`로 바꾼다. [표시 소스](https://github.com/StarCitizenWiki/API/blob/fab953d20b6d6c485c2430066e0a03a7db6fbbb6/resources/views/components/missions/hauling-section.blade.php)는 경계 하나가 `null`이면 남은 숫자를 단일값으로 표시한다.

따라서 이번 자료는 **‘정의에 단일값으로 표시되는 수량이며 이번 관측과 일치’**까지 검증됐다. `null`을 멋대로 0이나 고정 플래그로 바꾸지 않는다. 최소=최대, 단일 경계, 서로 다른 범위, 수량 미확인, 선택형 주문을 코드에서 구분한다. 단일값 표기만으로 모든 실행에서 고정된다고 확정하지 않는다.

## 위치와 상자에서 아직 모르는 것

- **중형:** 공개 `Location|Address`는 `a Salvage Yard on Daymar` 하나, `Location1|Address`는 Cantwell/McGrath 등을 포함한 7개 후보, `Destination|Address`는 7개 후보다. 후보 한 개도 정확한 실제 거점 ID나 모든 품목의 픽업 할당으로 승격하지 않는다.
- **대형:** `Location|Address`는 6개 후보, `Destination1|Address`는 7개 후보다. 설명에는 `Destination|Address`도 있지만 해당 후보 필드는 응답에 없다. 다른 배송 슬롯의 후보를 복사해서 채우지 않는다.
- 후보 목록은 실행 때 선택된 값을 알려주지 않는다. 로그 `zoneHostId`를 공개 거점 UUID와 같다고 간주하거나 좌표를 가장 가까운 거점에 붙이지 않는다.
- 상자 상한 8 SCU와 총 12 SCU를 알아도 실제로 8+4인지 다른 구성인지 확정되지 않는다. 최대 규격으로 만든 가정 구성을 ‘실제 상자’라고 표시하지 않는다.

## 이번 구현과 검사

- `data/log-mission-index.json`: 공개 정의 1,840개 ID를 유지하며 주문·범위·선택 분기·주소 후보를 추가했다. 같은 주문이 반복되면 보존한다. 기존 `hauling-missions.json`의 제목/주문 기준 중복 제거 목록을 실행 계약 ID 대조용으로 대신 쓰지 않는다.
- `scripts/build-log-index.mjs`: 공개 응답 캐시에서 필요한 사실 필드만 투영한다. 게임 파일/global.ini/기존 한글 패치 데이터는 이 작업의 입력이 아니다. 원문 설명·사용자 로그·캐릭터 정보도 넣지 않는다.
- `catalog.mjs`/`catalog-view.mjs`: 정확한 유형 ID로 규칙을 조회하고 출처·버전·불확실성을 표시한다. 실제 명세와 계산 허용 상태는 변경하지 않는다. 별도 실행 계약들은 같은 정의를 참고하더라도 합쳐지지 않는다.
- 목록은 약 5.31 MB이며 시작할 때 한 번 로컬에서 읽는다. 로그 감시마다 API 요청/목록 재해석을 하지 않는다. 카드 상세와 거점 후보는 펼칠 때 표시한다.
- Node 22/26 전체 테스트 각각 **175개 통과, Windows 전용 1개 건너뜀**. 새 정의 대조 검사 7개. Chromium에서 실제 제공 로그 재생 시 2개 계약, 중형/대형 규칙·계산 차단 유지, 390px 넘침/JS 오류 없음, 로컬 요청만 발생, 목록 요청 1회를 확인했다.

다음 검증 대상은 **선택된 위치를 신뢰할 수 있게 연결하는 방법, 품목별 실제 상자 분포 근거, 공개 정의와 실행 빌드의 호환 범위**다. 이 확인을 위해 Data.p4k 추가 추출을 요구하거나 게임 파일을 수정하지 않았다.
