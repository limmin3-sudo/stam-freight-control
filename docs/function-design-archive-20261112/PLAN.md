# STAM 콘솔 디자인 비교 · 2026-11-12

이번 결과물은 독립 시안이다. 운영 코드 수정·PR 병합·배포는 하지 않는다. index.html은 로컬 폰트와 CSS/SVG로 실행되며 실제 데이터에 연결하지 않는다. 생성된 이미지 보드는 재질 목표이고, 브라우저 시안은 화면 구성·글자·조작 상태를 검토하는 자료다. 현재 SVG 도식은 완성된 실사 지도/적재 렌더링이 아니다.

## 세 가지 테마

- A / Aether Glass: 스모크 유리, 얇은 실버 베벨, 부분적인 아이스 블루 하이라이트. 추천 기본안. 정보 영역은 반사를 줄이고 조작부에만 입체감과 발광을 집중한다.
- B / Titanium Bridge: 브러시드 금속 프레임, 매입형 유리, 앰버 상태등. 더 묵직한 장비 느낌. 큰 외곽 구조는 금속, 콘텐츠는 어둡고 명확하게 유지한다.
- C / Orbital Prism: 다층 유리, 펄·바이올렛 굴절, 둥근 조작부. 홀로그램 인상이 강하며 작은 글자에는 색수차/번짐을 적용하지 않는다.

버튼은 주요 실행·보조·선택 토글·원형 조작·사용 불가의 다섯 종류를 각 테마에 제공한다. 기본/hover/눌림/focus/선택/disabled 상태를 구현했다. 중요한 액션의 텍스트를 이미지에 굽지 않는다. 이미지나 셰이더는 재질층으로 쓰고 한글/영문·키보드 동작·반응형 영역은 실제 UI로 보존한다. 삭제는 기본 화면에서 강조하지 않고 별도 관리 메뉴에 둔다.

## 폰트 비교

1. SUIT Variable — 한글·영문·숫자를 같은 가족으로 통일. 제목 600, 버튼 600, 본문 450–500, 수치 550. 기본 추천.
2. Pretendard Variable — 높은 가독성, 기존 정보 밀도에 유리. 자간과 크기 위계로 장비 느낌을 조정한다.
3. Gmarket Sans — 넓고 기하학적인 글자. 미래적 인상은 더 강하지만 긴 미션명/작은 글자의 실제 밀도 검토가 필요하다. 비교본은 Medium 실제 파일을 사용한다.

폰트 소스: SUIT/Pretendard는 기존 저장소 assets/fonts의 파일, Gmarket Sans Medium은 projectnoonnu/noonfonts_2001의 배포 파일. 이 시안은 내부 비교용이다. 제품 반영 시 원제작자 라이선스/고지 파일을 동봉한다.

## 미션콘솔

상단: 현재 함선·출발지·파트너. 퀀텀 선택은 기본 흐름에서 제거하고 기본 장착을 적용한다.

왼쪽 약 65%: 계약 수신·선택. 카드 전체 선택과 독립 상세 수정, 배송지별 총 SCU 바로 입력. 상자 구성 확인/총량 확인/최대치 기준 상태를 명시한다. 최대치도 모르면 자동 계산 제외와 이유 표시. OCR을 기본 입력으로 요구하지 않는다.

오른쪽 약 35%: 선택 계약 요약, 확인한 총량/예상량 구별, 계산 가능한지와 보완할 정보, 하나의 ‘경로·적재 계산’ 버튼. 총 운송량과 최대 동시 적재량은 구별한다.

결과: 방문·작업 순서 + 적재 가능 여부 + 필요 시 적재 3D 상세. 별도 수동 입력·수정은 접어서 제공한다. 저장 버튼을 눌러야 선택되는 흐름은 만들지 않는다.

## 지도콘솔

왼쪽 70% 지도 / 오른쪽 30% 방문·작업 순서. 미션이 없을 때는 탐색·장소 정보, 계산 결과가 있을 때는 픽업/배송/점프 순서. 경로 항목과 지도 선택은 서로 연결한다. 출발지부터 첫 픽업까지 포함한다.

지도 재개발 대신 구버전 starmap.mjs의 Rig, 회전/팬/로그 거리 줌, 선택 판정, 계층 탐색을 기준으로 복원한다. 행성 재질·구름·대기 표현·배경·라벨·경로 선은 분리 개선한다. 읽기 어려운 과도한 bloom은 적용하지 않는다. 기존과 동일 데이터/뷰포트/입력으로 비교 후 조작값을 보존한다.

현재 확인한 근거: 구버전 로컬 main 988027e의 starmap.mjs/scene.mjs. 원격 e1d9f0d의 OperationsMap.tsx는 StantonHologram을 사용한다. 새 지도 엔진 전체를 검증한 것은 아니므로 결함 원인을 단정하지 않는다. 좋은 조작감으로 돌아가기 위한 구현 방침이다.

## 관제콘솔

구버전 관제모드의 현재 거점·다음 거점·픽업/배송 작업·완료/되돌리기를 중심으로 복원한다. 위쪽은 지도와 이번 작업 정보, 아래는 고정된 현재 거점/주요 완료 버튼. 큰 적재 화면이 주 역할을 대신하지 않는다.

적재 3D는 ‘적재 상세’로 열고 닫는다. 필요하면 작은 접이식 미리보기를 제공하되 현재 작업과 완료 버튼을 가리지 않는다. 운영상 관측한 정보와 사용자가 확인한 상태를 실시간 게임 정보로 위장하지 않는다.

구버전 README에는 지도·적재 3D 병렬과 하단 진행바가 명시돼 있다. 이번 배치안은 그 진행 기능을 유지하면서 사용자가 지적한 적재 3D 편중을 줄인 제안이며, ‘구버전 화면 그대로’라고 주장하지 않는다.

## 적재 3D

계산 엔진을 그래픽 개편 때문에 새로 쓰지 않는다. 우선 구버전의 계약/운송 항목/상자 소유권, 예약 공간, 실제 선적 위치 유지, 그리드 선택·부착 방향을 기준으로 기능을 연결한다. 화면 계층은 별도 교체 가능하게 만든다.

현재 e1d9f0d CargoWorkspace.tsx에서 확인한 구조: empty/demo/manifest/aboard 모드 분리, manifest는 단일 actualPickup의 화물을 표시하며 UI도 현재 선적/운항 진행 미포함을 명시한다. 이것을 전체 운송 계획의 화면처럼 쓰면 혼동할 수 있다. 임의 코드 변경으로 고치지 않고 운항 단계별 동일 계획 데이터를 공급하는 연결을 먼저 설계한다.

선택 가능한 시점: 현재 / 다음 작업 후 / 각 방문 단계. 예약과 실제 화물은 다른 재질 및 텍스트로 표시한다. 실제로 확인되지 않은 상자 구성을 ‘실제’로 표시하지 않는다. 다른 계약의 같은 화물을 합치지 않는다. 기존 선적 화물을 다시 자동배치하지 않는다.

표현: 실체 상자는 모서리 베벨·절제된 반사·접촉 그림자, 예약은 반투명 윤곽. 배송지 색상과 명도 대비를 유지한다. 배경 격납고 연출은 실제 그리드 밖에 두며 정확한 승인 모델 없이 함선 외형을 임의로 만들지 않는다.

## 작업 순서 및 수락 기준

1. 사용자가 테마와 폰트 후보 선택. 지도콘솔 한 화면에서 대표 재질·버튼·한글·수치를 완성하여 먼저 비교한다.
2. 기존 기능 목록과 새 화면 연결표 작성. 수신→카드 선택→수량 보완→계산→지도/관제/적재까지 하나의 계획으로 연결한다.
3. 지도는 같은 입력으로 회전/줌/이동/천체 선택/계층 복귀를 구버전과 비교한다. 그래픽은 이 동작을 바꾸지 않고 개선한다.
4. 적재는 배송 총량 중복 예약 없음, 미확인 픽업 분배 생성 없음, 단계 전환의 소유권/실린 위치 보존, 초과 적재 검출을 검증한다.
5. 같은 PC/브라우저/뷰포트에서 새 렌더링 프레임 시간과 메모리를 비교한다. 시각 시안만으로 실제 성능이나 계산 정확성이 개선됐다고 말하지 않는다.
6. 데스크톱과 모바일, 긴 한글 미션명, 키보드 포커스, 동작 줄이기, 빈 계약·보완 필요·계산 실패·진행 재개 상태를 확인한다.
7. 사용자의 별도 배포 지시 전까지 PR 병합·운영 반영 보류.
