# 데스크 → 시네마: 실사 2.5D 가이드 시안

브랜치 `cinematic/desk-cinema-25d-20261113`, 최신 원격 main `fa647d0` 기준의 독립 시안이다. 사용자가 첨부한 현재 데스크 장면에서 시네마로 안내하는 느낌을 실제로 비교하기 위한 작업이다. 공유 앱/기능/테마/라우팅에는 연결하지 않았다. #28~#31의 통합본이 아니며 기능 담당의 작업을 덮어쓰지 않는다. main·공통 인계 병합·배포 없음.

## 실행

저장소 루트에서 의존성이 있는 상태로 다음을 실행한다.

```sh
npm run build --prefix apps/control-room
node docs/cinematics/desk-cinema-25d-20261113/server.mjs
```

미리보기: `http://127.0.0.1:5196/`. 다른 포트는 `STAM_TOUR_PORT`로 지정한다. 서버는 시안/기존 이미지·서체/로컬 Three 모듈/앱 빌드만 정적 제공한다. `/live/`는 현재 `apps/control-room/dist/`를 읽는다. 별도 서버이며 운영 배포를 시작하지 않는다.

첫 홀로그램 또는 아래 ‘가이드 따라가기’를 누르면 시작한다. 일시정지/계속 보기, 처음으로, 도착 장면, 타임라인으로 비교할 수 있다. 동작 줄이기 설정에서는 도착 상태로 건너뛴다. 브라우저에 한국어 음성이 있을 때만 선택적으로 기본 TTS를 켤 수 있고, 없으면 자막으로 안내한다. 승인된 가이드 음성 제작본이 아니다.

## 실제로 구현한 것

| 시간 | 화면 |
| --- | --- |
| 0초 | 저장소 고해상도 데스크 사진을 기준으로 한 가이드·기존 단일 홀로그램. 첨부 대기 영상과 자세가 완전히 같은 프레임을 복원한 것은 아님 |
| 0~2.7초 | 가이드 자막, 홀로그램 왼쪽 수납, 카메라가 데스크에서 벗어남. 가이드와 배경의 깊이/이동량이 다름 |
| 2.7~4.15초 | 라운지 전경으로 짧은 디졸브 연결 |
| 4~8.5초 | 가이드가 앞쪽에 서서 돌아보고 시네마를 가리킴. 커진 입구 표식, 카메라 우측 이동/접근, 근접 이미지로 연결 |
| 8.5~11.2초 | 입구에서 안내하는 새 가이드 자세, 시네마 근접, 어두워짐·STAM 로고·250ms 전류 후 실제 화면 |
| 11.2초 이후 | 현재 로컬 빌드의 실제 시네마와 버튼/상단바/사이드바. 동일 가이드 자산·자막으로 장소 소개. 다음 안내는 이번 시안의 끝이라고 명시 |

움직임은 영상 파일/저프레임 이미지 교체가 아니라 Three.js 투영 카메라와 `requestAnimationFrame`으로 계산한다. 사진을 깊이가 연속된 얕은 메시 표면에 투영하고, 가이드 RGBA 카드를 별도 깊이에 둔다. 처음에 보였던 잘게 나눈 바닥/문틀 카드의 경계는 연속 표면으로 교체했다. 디졸브 중에만 두 장면을 렌더하고, 단일 장면은 바로 출력한다. 느린 환경에서 프레임 지연이 지속되면 **이동 캔버스만** 렌더 배율을 .65로 낮추고, 정지/일시정지에서는 원래 배율로 복원한다. HTML 글자/패널/실제 메뉴는 이 조절로 흐려지지 않는다.

가이드는 데스크/앞쪽 안내/입구 손짓의 정지 자산이다. 발을 바닥 기준의 고정된 3D 위치에 두고 카메라가 따라간다. 걷기·눈깜빡임·립싱크를 구현한 것이 아니다. 깊이/구도 이동과 자막으로 안내의 연결성을 검토한다. 각 뷰의 디졸브가 있으며 긴 복도를 물리적으로 연속 이동하는 3D 모델은 아니다. 새 근접 컷은 원래 우측 시네마를 참고해 생성했으므로 정확한 미관측 공간 복원이라고 주장하지 않는다. 자유롭게 큰 각도로 회전하면 가려진 곳을 새로 보여줄 수 없다.

실제 시네마는 기존 앱 빌드를 그대로 iframe으로 읽는다. 이후 테마/기능 빌드를 바꾸면 새 화면을 사용한다. 기능 담당용 최종 결합은 튜토리얼의 화면 진입/설명 유지/다음 이동 계약으로 연결해야 하며, 이번 iframe을 운영 앱 안에 다시 중첩하는 구조로 통합하지 않는다. 게스트/계약/로그/계정 상태를 변경하는 새 핸들러는 없다.

## 자산

기본 전경은 현재 앱 `space-config.ts`와 같은 `lounge-original-composite.png`를 사용한다. 폐기된 중앙 모니터가 포함된 `lounge-original.png`를 첫 시안에서 잘못 재사용했으나 사용자 정정 후 런타임 입력에서 제외했다. 중앙 모니터·받침·부착 화단·원형 바닥 조명은 현재 전경에 없다. 원본 가이드/라운지/홀로그램 자산 자체는 수정하지 않았다. 새 clean plate, 시네마 근접 컷, 투명 가이드 및 앞쪽/입구 안내 자세는 이 폴더 assets에만 저장했다. 생성 원본은 별도 제작 폴더에 보존했다. 생성/참조와 SHA256은 [source-record.json](source-record.json)에 기록했다. 가이드 투명 자산은 참조 편집 결과이며 원본 픽셀과 완전히 동일한 자동 분할이라고 주장하지 않는다.

## 사용자 피드백 반영: 앞서 안내 / 표식 가독성

사용자가 2.5D 구성은 유지하되 가이드가 앞에서 안내하는 느낌과 더 잘 보이는 시네마 이름을 요청했다. 뒤·측면으로 돌아보는 앞쪽 안내 자세와 입구 손짓 자세를 새 자산으로 추가했다. 다리가 짧아지고 상체 볼륨/얼굴 인상이 달라진 초기 입구 자산은 제외했다. 원본 전신/얼굴을 다시 참조해 만든 `guide-entrance.png`를 사용자가 확인하고 승인했다. 원본 전신·초상화 파일은 교체하지 않았다.

앞쪽/입구 자산은 가로·세로를 따로 늘리지 않고 원래 비율로 그린다. 접지 위치도 고정하여 정지 포즈가 바닥 위로 미끄러지지 않게 했다. 각 뷰의 가이드가 디졸브로 이어지며, 이는 새 걷기 애니메이션이 아니다.

시네마 본문 표식은 데스크톱 약33px/굵기650, 모바일 최소22px로 키웠다. 따뜻한 밝은 글자에 어두운 외곽선/그림자와 부드러운 국소 음영을 사용해 밝은 벽에서도 읽힌다. 이름 아래 설명을 추가하고, 표식은 화면 고정 좌표 대신 카메라에 투영한 입구 위치를 따라간다. 버튼 판을 추가하거나 공용 장소 라벨 스타일을 변경하지 않았다.

## 검증과 화면

전용 서버/브라우저 스크립트의 문법 검사와 실제 Chromium 검수. 공유 실행 코드를 바꾸지 않아 앱 계산 테스트를 새 작업의 검증으로 재사용하지 않는다.

- 실제 WebGL canvas, 이동 영상 요소 없음, 가이드/배경 투영 차이, 새 전신 자산 원본 비율/고정 발 위치, 커진 시네마 문구 확인.
- 실제 시간 재생·일시정지·다시 보기·도착 건너뛰기·타임라인, 실제 시네마와 기존 버튼/고정 메뉴, 자막 이어짐 확인.
- 1280px 데스크톱/390px 모바일, 가로 넘침 없음. 모바일 실제 화면은 세로 높이를 확보하고 설명을 장면 아래에 배치.
- 동작 줄이기는 도착으로 건너뜀. 브라우저 오류/누락 자산 없음.
- Headless Chromium/SwiftShader와 녹화를 사용한 프레임 수치는 [checks.json](review/checks.json)에 기록한다. 실제 GPU/사용자 기기의 60fps를 보장하지 않는다. 확인 영상은 실제 브라우저 재생을 녹화한 자료이며 런타임 이동용 영상 자산이 아니다.
