# 기능 담당 인계 · 배포 시험용 라운지 가이드 투어

브랜치: `cinematic/lounge-tour-20261114` / PR #34. 최종 커밋은 PR HEAD를 확인한다. 사용자가 현재 결과로 배포 시험할 수 있게 마무리해 달라고 요청해 **실제 React 앱 연결까지 추가했다.** 이전 `247d88d`의 독립 시안 전용 인계는 아래 최신 내용으로 대체한다. main·`handoff/local-studio-20261110`에는 직접 병합/푸시/배포하지 않았다.

## 적용 순서와 포함 관계

1. 기존 기능 작업을 보존한 상태에서 승인된 다른 연출 인계들을 통합한다. #28·#29·#30·#31은 이번 브랜치의 코드에 포함하지 않는다. 공용 테마/하위 메뉴/FLIGHT CONSOLE 작업은 기능 담당 소유다.
2. #32 `cinematic/desk-cinema-25d-20261113` / `b0d8bdb` → #34 순서다. #34는 #32에 쌓은 후속이므로 #32의 이미지 경로가 필요하다.
3. #33 보행 리깅은 **포함하지 않는다.** 이 투어는 사진 기반 정지 자세·깊이 카메라·디졸브이며 자연 보행이 아니다.
4. 실제 연결 코드는 `247d88d` 이후 커밋에 있다. 독립 HTML/iframe/검토용 서버를 제품에 배포하지 않는다. Vite가 실제 컴포넌트와 필요한 PNG를 해시 자산으로 묶는다.

## 실제 진입과 동작

- 안내데스크 화면의 새 **‘라운지 투어 · 가이드 따라가기’** 버튼으로 시작한다. 기존 첫 운송/운송 준비/정보/복귀 버튼의 컨트롤러와 DOM 식별자는 그대로다.
- 데스크 → 시네마 → 아카이브 → 서비스센터 → 게이트. 각 실제 메뉴가 마운트된 뒤 가이드 소개와 다음 버튼을 표시한다. 새 iframe이나 별도 앱/저장소를 만들지 않는다.
- 고정 상단바/사이드바를 유지한다. 이동 중 본문만 inert 처리하고 도착 후 실제 메뉴를 사용할 수 있다. 일반 사이드바 이동/뒤로가기/언어 변경은 투어를 종료하고 기존 동작을 따른다.
- 일시정지/계속/이동 건너뛰기/투어 종료, Escape, 창을 벗어날 때 일시정지, 동작 줄이기, WebGL 미지원용 정지 자산 대체를 연결했다.
- 기본은 장소 소개마다 기다린다. 실시간 셔틀 카운트다운이나 자동 다음 장소 이동은 없다.
- 게이트에서 투어를 마치면 기존 라운지 조작을 사용할 수 있다. 기존 셔틀 영상·관제센터 진입을 새 투어가 자동 실행하지 않는다. 게이트 이후 셔틀 전용 연출은 별도 후속이다.
- 진행 상태는 메모리에만 있다. 새로고침 시 현재 투어를 재개하지 않는다. 기존 운항/미션/함선/계정 저장 모델을 변경하지 않았다.

### #31과의 공유 파일 대조

`git merge-tree`로 #31 HEAD `6fc12a9`와 실제 연결 커밋 `2bd2142`를 작업본 변경 없이 대조했다. 충돌 파일은 `PROJECT_STATUS.md`와 `SpaceExperience.tsx`다. 공유 소스의4개 충돌 지점에 대해 **양쪽 변경을 보존한 추가 패치**를 `integration/pr31-tour-hooks.patch`로 저장했고 #31 트리에 `git apply --cached --check`를 통과했다. [대조 기록](integration/merge-check.json).

- hash 동기화에서는 Archive 펄스 정리와 투어 기대 목적지 처리를 둘 다 둔다.
- Escape effect 의존성에는 기존 `motion`과 새 `tour`를 둘 다 둔다.
- 일반 `enter`에서는 투어 종료를 먼저 처리한 뒤 기존 Archive 하위 메뉴 분기를 보존한다.
- 기존 `href(screen, view?)`를 보존하고 투어의 close/navigate/start만 추가한다.

패치는 #31의 정확한 공유 파일 기준이다. 현재 기능 쪽 파일이 더 바뀌었다면 먼저 `git apply --check`로 대조하고 위4개 원칙으로 병합한다. 전체 파일 교체용 자료가 아니다. 상태 문서는 양쪽 최신 항목을 모두 보존한다. 이 대조는 기능 브랜치를 실제로 합치거나 통합 후 브라우저 검증한 것과 구분한다.

새 자산은 `docs/cinematics/lounge-tour-20261114/assets/`, 데스크/시네마 근접 자산은 #32 폴더를 정적 import한다. 빌드 후 네트워크 요청은 `assets/*-hash.png`이며 `/docs`·`/apps` 개발 경로가 아니다. PNG를 앱 자산 폴더로 옮기면 import만 함께 수정한다.

## 검증 / 남은 사항

최신 실제 앱 검증은 `runtime-review/checks.json`과 `runtime-review/verify-native-tour.mjs`다. Pages와 같은 `/stam-freight-control/` 하위 경로의 **Vite 배포 빌드**를 대상으로 했다. 기존 독립 시안의 `review/checks.json`은 별도 과거 기록이다.

확인 항목: 실제 앱 진입/게이트까지 순서/기존 메뉴 마운트, 기존 첫 운송 버튼, 일반 사이드바 이탈, Escape/일시정지/종료와 캔버스 정리, 운항 저장 값 보존,390px/모바일 메뉴, 영어/동작 줄이기, WebGL 대체, 실제 연속 재생, 해시 자산·하위 경로. 타입 검사·Vite 빌드·기존 앱 테스트와 루트 테스트 결과는 README를 참조한다.

남은 것은 새 자산 외형의 후속 보정, 확정 음성/립싱크/자연 보행, 게이트 이후 셔틀 전용 연결, 별도 요청 시 튜토리얼 진행 저장·재개다. 완료됐다고 보고하지 않는다. 현재 요청은 이 범위의 투어를 우선 배포 시험할 수 있게 연결하는 것이다.

통합 후 기능 담당이 자신의 최신 공용 테마/하위 메뉴와 함께 최종 브라우저 검증하고 기존 Pages 워크플로로 배포한다. 배포 승인/실행을 이 브랜치의 main 병합으로 대신하지 않는다.
