# FLIGHT CONSOLE / 상단 계정·로그 / 공간 이름

브랜치 `cinematic/pilot-desk-20261113`, 기준 beta 2.7.0 main `fa647d0`. 사용자 요청에 따라 새 브랜치에서 연출·기존 기능 연결을 구현했다. 기능 담당이 통합·검증 후 배포한다.

## 최종 이름

- `FLIGHT CONSOLE`, `SPACEPORT LOUNGE`, `CONTROL CENTER`: ko/mix/en 모두 영어 고정.
- 정보실 → **아카이브**, 영상관 → **시네마**: ko/mix는 한국어로 적은 외래어, en은 Archive/Cinema.
- 기존 장소/화면 ID와 목적지 해시는 유지한다. 데스크·서비스센터·게이트 등 나머지 명칭은 변경하지 않는다.

## 패널 동작

사이드바 최상단에서 실제 현재 함선, 선택한 파트너, 선택 미션 수를 요약한다. hover/키보드 focus로 상세를 열고 클릭으로 고정·접기한다. Esc는 패널을 접고 요약 버튼으로 초점을 돌린다. 데스크톱은 상세가 메뉴 위에 겹쳐져 아래 메뉴의 클릭 위치가 움직이지 않는다. 모바일은 탭으로 펼치고 접는다.

상세에는 실제 준비/계산/운항/완료 상태, 선택한 미션 수, 로그 수신 계약 수, 현재 목적지, 이번 항로의 방문 진행을 읽어서 표시한다. 적재/용량은 항해사일 때만 기존 확정 필드를 표시하며 값이 없으면 미확인으로 표시한다. 임의의 SCU나 수주 수를 만들지 않는다. **요약 미션 수는 현재 draft에 담은 계약 수**이며 게임의 미수신 계약까지 전부 수주한 수라고 주장하지 않는다.

## 기존 기능에 연결한 조작

- 함선 변경 / 파트너 변경: 기존 미션 콘솔로 이동하고 해당 선택 항목에 초점을 맞춘다. 운항 중에는 기존 fieldset/훅의 잠금이 그대로 적용된다. 패널에서 임의 변경 로직을 새로 만들지 않았다.
- 미션 변경·취소: 기존 미션 준비 화면으로 이동한다. 개별 계약의 수정/삭제/수신 상태 처리는 기존 기능이 담당한다.
- 운항·계획 초기화: 확인창 후 기존 `flight.stop()`을 호출한다. **계산된 계획과 운항만 해제하며 선택한 계약·함선·파트너는 유지**한다. 선택 계약 전체 삭제나 계정/저장소 초기화 기능이 아니다. 계산 중/저장 복구 오류 상태에서는 비활성화한다.

패널 안의 직접 계약 편집·수주 상태 변경·전체 데이터 초기화가 추가로 필요하면 기능 담당이 별도 정책/핸들러를 연결해야 한다. 현재 조작 경로와 보존 범위를 다른 기능으로 설명하지 않는다.

## 상단 상태

로그인/계정 버튼과 로그 상태는 고정 상단바에 둔다. 기존 `serviceControls().accountButton`의 텍스트 상태를 관찰하고 기존 버튼을 눌러 계정 창을 연다. 서비스센터의 계정 관리는 같은 컨트롤러를 재사용한다. 계정 동기화/인증 코드를 바꾸거나 별도 인증 인스턴스를 만들지 않는다.

로그는 기존 `flight.receipts` 훅의 상태를 표시한다. 미연결, 읽는 중, 파일 읽음(단건), 자동 수신 중, 오류/플레이어 확인 필요를 구분한다. 파일을 한 번 읽은 것을 실시간 연결됨으로 표시하지 않는다. 상태를 누르면 기존 Game.log 준비 항목으로 이동한다. 별도 서버 연결 확인이나 로컬 앱 연결 상태를 새로 추정하지 않는다.

## 변경 파일과 통합

- `PilotDesk.tsx`, `PilotTopbar.tsx`, `pilot-desk.css`: 공용 Barlow/SUIT와 `projection-even-frame.svg`를 재사용한 새 패널/상단 표시.
- `SpaceExperience.tsx`: 현재 운항/로그 상태를 props로 전달하고 기존 미션 화면으로 이동·초점 연결.
- `ServiceAccountHistory.tsx`: 계정 버튼 DOM을 옮기는 대신 동일 컨트롤러의 계정 관리 버튼을 호출. 기록 읽기·갱신은 유지.
- `SpaceNavigation.tsx`, `space-config.ts`: 사용자 확정 명칭만 변경. 기존 메뉴 이미지·폰트·배치·펼침 로직은 유지한다. 모바일에서 추가 상단 상태 줄과 패널을 배치하는 CSS만 새 파일에 한정했다.

공유 파일은 최신 기능 변경과 diff를 대조해 합친다. main에 직접 반영/배포하지 않았다. PR #28(복귀 축소), #29(중복 안내 제거/250ms/안내 구성)과 독립적인 main 기준 PR이므로 기능 담당이 함께 합쳐야 한다. 이 PR만으로 아카이브/시네마 하위 페이지가 내부 연결 완료됐다고 보고하지 않는다.

## 검증

TypeScript/Vite 빌드 및 앱 테스트 14개 파일 통과. 실제 production preview Chromium의 ko/mix/en에서 이름, 실제 샘플 운항 표시, hover 메뉴 위치 고정, 클릭 고정/접기, 저장값 불변을 확인했다. 기존 계정 모달/서비스 계정 재사용, 운항 중 변경 제한, 파트너 선택 초점, 초기화 취소 시 완전 보존·확인 시 plan/run만 해제, 390px 모바일 배치/터치식 조작/가로 넘침 없음을 검수했다.

기존 계산기로 만든 합성 운항 1건을 사용했으며 사용자 계정/계약을 쓰지 않았다. 로그 검증은 빈 합성 파일과 테스트용 파일 선택 API로 단건 읽기/자동 수신/수신 중지를 확인했다. 실제 OS 파일 권한과 계정 로그인/클라우드 동기화의 검증을 뜻하지 않는다.
