# 무역 클라우드 · 아카데미 기능 — 2026-11-17

사용자 요청에 따라 무역 클라우드를 포함해 아카데미 세 방 기능을 연결했다. 기존 미커밋 연출·무역 기능을 보존했다. 커밋·푸시·운영 규칙 게시·사이트 배포는 하지 않았다.

## 무역 계정 저장

- 교역 계획실/관제실의 **계정 저장 · 다른 기기에서 이어하기**에서 기존 인증을 사용한다. 최초 기기 기록 업로드는 양쪽 기록 확인 후 실행한다. 빈 새 기기는 검증된 계정 기록을 받아온다.
- 확장 교역 장부와 이전 교역 장부, 저장 경로, 관심 가격, 즐겨찾기를 함께 저장한다. 실제 재고·창고·비용·거래 사건·감사 이력도 장부 그대로 보존한다. 개인 시세 입력, 전체 앱 설정, 운송 장부를 이 묶음에 섞지 않는다.
- 무역 작업 화면이 열려 있고 탭이 보이는 동안 15초 간격으로 변경을 확인한다. 연결된 기기의 단독 변경은 저장하고, 양쪽 변경은 비교 선택으로 전환한다. 기존 교역 화면에서도 같은 동기화 인스턴스를 유지한다.
- 다른 기록 불러오기는 별도 확인이 필요하다. 기기 교체 전 두 세대 장부를 원자적으로 백업하며, 직전 기기 기록을 복원하거나 파일로 보관할 수 있다. 복원은 계정 기록을 바꾸지 않고 자동 저장을 멈춘다.
- `/users/{uid}/trade/current`의 별도 revision/parts를 사용한다. 기존 운송 `/flight/current`는 분리한다. 소유자 경계, 늦은 인증 응답, 압축 크기/해시, 동시 저장 충돌, 다중 키 저장 실패 복구를 검증했다.
- **운영 적용은 아직 아니다.** 새로운 Firestore trade 규칙과 웹 빌드 배포가 필요하다. 실제 운영 계정 두 기기 검증은 별도로 남아 있다. 현재 확인은 demo 프로젝트 에뮬레이터와 모의 SDK 브라우저다.

## 아카데미

| 방 | 기능 |
| --- | --- |
| 운송 정보실 | 기존 아카이브의 미션 검색·함선·화물 자료를 내부에서 재사용. 화물의 관련 미션도 이 방 안에서 연결. 운송 노하우·패치 유의사항·출처 대조 유지 |
| 교육실 | 한국어/영어 학습 7항목, 검색/주제 필터, 현재 탭 읽음 표시. 실제 4.10.3 미션 정의의 발주처·단계·상자·수량·행성계로 초반 계약 유형 비교 |
| 작전 연구실 | 확인된 Hull B·오리슨 출발 6계약/363 SCU 사례로 통합/계약별 운송 비교. 계약/함선 변경, Worker 계산, 방문별 지도·적재·상자 선택 |

### 데이터 의미와 제한

- SCMDB 중심, 같은 정의 ID의 누락값은 Wiki 보완이라는 기존 출처 규칙을 재사용한다. 자료에 없는 평판 획득량·승급 횟수·평판/시간 순위를 만들어 표시하지 않는다.
- 교육실은 **계약 유형 참고 비교**다. 실시간 수주 목록이 아니다. 합법 여부·단계·상자·수량 상한이 확인된 정의를 사용하며 기본은 행성계 내부다. 같은 발주처, 공통 후보 거점, 최대 수량 합을 비교한다. 실제 수주 거점·상자 구성과 동시 수주 가능성은 별도다.
- 자동 조합 후보는 필터 결과 앞 60개 중 최대 6쌍이다. 다른 정의는 검색·목록에서 직접 최대 3개 선택한다. 명목 용량 필터가 실제 혼합 배치 성공을 뜻하지 않는다.
- 사례는 과거에 확인된 6계약의 비식별 사본이다. 픽업지별 수량 미확정인 7번째 계약은 제외한다. 개인 원본 로그를 새로 공개하지 않았다.
- 현재 엔진/함선/좌표 기준 비교에서 통합 점프 1회, 계약별 점프 11회다. 계약별은 고정 목록 순서로 직전 배송지에서 다음 픽업으로 이동한다. 시간은 이동/접근 추정이고 실측 상하차·대기·서버 지연이나 실제 보상 기록이 아니다.
- 학습/연구는 실제 수신함·운항·계약·교역 장부를 바꾸지 않는다. 미션 카탈로그를 실제 계약으로 임의 주입하지 않는다.
- 새 통합 둘러보기·운송/무역 튜토리얼은 사용자 결정대로 후속이다. 새 캐릭터·배경·버튼 자산은 만들거나 승인하지 않았다.

## 검증과 인계

실행 증거는 `runtime-review/`와 `validation.json`을 참고한다. 에뮬레이터는 실제 SDK/규칙, 클라우드 브라우저는 모의 SDK 트랜잭션과 실제 앱 UI, 사례 연구는 보존 자료와 실제 계산 엔진을 사용했다. 실게임·운영 계정 성공과 혼동하지 않는다.

연출용 연결 경계는 [CINEMATIC-HANDOFF.md](CINEMATIC-HANDOFF.md)에 정리했다. 현재는 기존 로비 확대와 기능 패널이며, 실제 모니터에 접근해 화면으로 이어지는 연출까지 완료한 것이 아니다.
