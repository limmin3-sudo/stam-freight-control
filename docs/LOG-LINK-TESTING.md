# 집에서 하는 실시간 로그 연결 테스트

## 기본 화면과 관제 모드

- 기본 화면은 왼쪽 함선·출발·계약, 가운데 큰 지도와 아래 적재 3D, 오른쪽 방문 순서·단계별 작업 안내입니다.
- 계획이 준비되면 왼쪽 **운송 시작 · 예상 이동**을 누르세요. 화물 정보는 다시 입력하지 않습니다. 지도 위 주황색 배지는 실제 위치가 아닌 계획 시간 기준의 예상 위치임을 나타냅니다.
- **관제 모드**에서는 지도와 적재 3D를 나란히 보고 카메라가 예상 함선을 따라갑니다. **기본 화면으로** 또는 Escape로 돌아옵니다. 두 모드는 같은 캔버스를 사용합니다.
- 실제 도착·작업을 마쳤다면 **다음 구간 출발 · 예상 이동**으로 다음 이동 표시를 시작할 수 있습니다. 이 버튼과 예상 시간 경과는 게임 계약의 완료/배송/수입을 기록하지 않습니다.
- 예상 시간이 지나면 **위치 확인 대기**로 표시합니다. 자동으로 다음 구간으로 넘어가지 않습니다. 일시정지·계속 이동·이동 표시 종료도 제공됩니다.
- 지도·경로 단계 선택은 배치 미리보기입니다. 실제 적재 현황과 구분하세요. 선택 계약/함선/그리드/출발지가 바뀌면 이전 예상 이동을 중단하고 재계산합니다.
- 현재 실제 함선 위치를 지속적으로 공급하는 연결은 없습니다. 로그 감시 중이라는 이유만으로 청록색 **실시간 동기화**를 표시하지 않습니다.

전체 재구축 기능과 다른 도구에서 합칠 기능은 [기능 작업 목록](REBUILD-FEATURE-TRACKER.md)을 참고하세요. 계정·언어·실제 aboard 등의 미완료 기능도 따로 표시합니다.


이번 시험판은 **계약 기록이 자동으로 들어오는지, 같은 유형의 별도 계약이 분리되는지, 파티원의 행동을 본인과 구분하는지** 확인하는 버전입니다. 확인된 대형 유형은 목적지별 원래 계약 상자 명세까지 연결합니다. 모든 유형의 자동화와 현재 적재·배송 진행 상태 연동은 아직 완료되지 않았습니다.

로그 실행기 안에서 여러 계약의 경로·적재 3D 미리보기를 사용할 수 있습니다. [전체 완료 범위](REBUILD-PROGRESS.md)를 참고해 주세요.

## 가장 간단한 실행 방법 — Windows

1. [시험 브랜치 ZIP](https://github.com/limmin3-sudo/stam-freight-control/archive/refs/heads/rebuild/log-evidence-foundation.zip)을 받아 **압축을 풀어 주세요**. 기존 폴더에 덮어쓸 필요는 없습니다.
2. Node.js **22 이상**이 설치되어 있어야 합니다. **이미 24나 26을 사용한다면 제거하거나 22로 바꾸지 마세요.** Node가 없을 때만 [공식 다운로드](https://nodejs.org/en/download)에서 설치해 주세요.
3. 압축을 푼 폴더에서 **`start-log-link.cmd`를 두 번 클릭**해 주세요.
4. 파일 선택창에서 현재 사용하는 게임 폴더의 **`LIVE\Game.log`**를 선택해 주세요. 기본 설치 경로는 `C:\Program Files\Roberts Space Industries\StarCitizen\LIVE\Game.log`입니다. 다른 드라이브나 채널을 사용한다면 실제 실행한 게임의 로그를 선택해야 합니다. `logbackups`의 과거 파일은 실시간으로 갱신되지 않습니다.
5. 자동으로 열린 브라우저에서 **‘실시간 감시 중’**을 확인해 주세요. 브라우저가 열리지 않으면 실행 창에 표시된 주소를 복사해 열면 됩니다.

`npm install`, Firebase 로그인, 게임 내 명령 입력은 필요하지 않습니다. 3D를 처음 열 때는 고정 버전 Three.js를 자동으로 내려받아 앱 폴더에 저장하므로 인터넷 연결과 해당 폴더의 쓰기 권한이 필요합니다. 실패하면 화면의 「3D 준비 다시 시도」를 사용할 수 있으며 로그 감시는 계속됩니다. 게임 폴더에 파일을 설치하거나 수정하지 않습니다. 브라우저와 실행 창은 테스트 중 열어 두세요. 이 연결은 **게임 PC 전용**이며 휴대폰에서 같은 localhost 주소로 접속할 수는 없습니다.

실행 창의 주소에는 로컬 연결 키가 포함됩니다. 주소 전체를 공개하거나 제보에 붙이지 마세요. 브라우저가 열린 뒤 주소창에서는 키를 지우고 해당 탭의 세션에만 보관합니다. 새로고침은 다시 연결되며 프로그램을 재시작하면 새 주소를 사용해야 합니다.

### 명령으로 실행하는 방법

저장소/압축 해제 폴더에서:

```powershell
node scripts/log-link-server.mjs --file "C:\Program Files\Roberts Space Industries\StarCitizen\LIVE\Game.log" --open
```

게임 로그 경로가 다르면 본인 경로로 바꿔 주세요. 프로그램은 지정한 파일 하나만 읽습니다. 브라우저에서 서버에 다른 파일 경로를 전달하는 기능은 없습니다.

계약 카드를 펼치면 **‘유형 ID로 찾은 화물 규칙’**이 표시됩니다. 로그 수량 알림이 없는 계약도 공개 정의를 찾을 수 있습니다. 여기의 주문 수는 상자 개수가 아니며, 지점 후보는 실제로 선택된 거점이 아닙니다. [대조 결과와 한계](MISSION-ID-COMPARISON.md)를 참고해 주세요.

그 아래 **‘로그에서 찾은 픽업·배송 지점’**은 행성·위성 기준 XYZ가 공개 좌표와 1cm 이내로 일치하는 지표 거점을 표시합니다. 일치하지 않거나 여러 곳이 겹치면 미확인으로 남습니다. 검증된 대형의 동일 배송 묶음만 원래 명세에 연결하며, 다른 유형의 모든 품목에 자동 배정하지는 않습니다. 복귀·방문처럼 SCU 없는 알림은 **‘수량 없는 목표 알림’**에서 볼 수 있습니다. 알림이 남아 있다고 완료된 계약에 귀환 구간을 추가하지 않습니다. [위치·복귀 확인 범위](LOG-LOCATION-EVIDENCE.md).

### 2026-11-03 고정 상자 조합 확인

사용자가 확인한 대형 유형은 **‘고정형 상자 조합’**에 Ship Ammunition 16 SCU × 4개, Hydrogen 16 SCU × 4개, Medical Supplies 2 SCU × 20개를 표시합니다. 정확한 유형 ID와 로그의 게임 빌드 12913470이 맞아야 합니다. 중형은 고정형 여부만 확인되어 크기별 개수를 채우지 않습니다. [적용 근거와 제한](FIXED-BOX-PROFILES.md).

이번 표시만 확인하려면 게임에서 미션을 다시 받을 필요 없이 최신 시험판으로 **이미 수락 기록이 남은 Game.log**를 열어도 됩니다. 기존 실행 창은 Ctrl+C로 종료한 뒤 새 폴더의 실행기를 사용해 주세요. 대형 카드를 열고 위 세 줄과 총 28개/168 SCU를 확인하면 됩니다. 세 지점이 대조되면 네 번째 지표 **‘목적지별 원래 명세가 연결된 계약’이 1**이 되고, 대형 카드에 **‘목적지별 원래 계약 상자 명세’**가 표시됩니다. 배송지마다 탄약 16 SCU×2 / 수소 16 SCU×2 / 의약용품 2 SCU×10, 합계 84 SCU/14개인지 확인해 주세요. 지점이 다르거나 빠진 기록은 연결하지 않습니다.

이번 확인에는 **게임 재실행이나 새 계약 수락이 필요하지 않습니다.** 이미 받은 기록을 재생하면 됩니다.

## 계약 정보를 다시 입력하지 않고 계획하기

1. 위 실행 순서로 기존 Game.log를 여세요. 예전 실행기는 Ctrl+C로 종료한 뒤 새 폴더에서 실행해 주세요.
2. 검증된 대형처럼 자동 연결이 가능한 수락·본인 참여 계약은 자동 선택됩니다. 종료·이탈 기록은 자동 선택하지 않으며 직접 해제한 선택도 다시 켜지 않습니다. 「운송 관제 열기」를 여세요.
3. 처음 한 번 함선·출발지·파트너를 정해 주세요. `New Babbage` 등 계약 밖의 출발지도 사용할 수 있습니다. 출발지 선택 후 자동 계산하며, 계약의 품목·SCU·거점·상자를 다시 입력하지 않습니다.
4. 지도와 전체 화물의 3D 배치를 함께 보여 줍니다. 경로의 **1번은 출발지**이며 방문 목록 또는 이전/다음 단계를 누르면 지도 구간과 화물 배치가 같이 바뀝니다. 점프는 별도 번호로 표시하며 이동 중 화물을 미리 내리지 않습니다. 「나란히 / 지도 / 적재 3D」로 원하는 화면만 켤 수 있습니다.
5. 함선·파트너·출발지·사용할 그리드를 바꾸면 짧은 지연 후 자동 재계산합니다. 관련 없는 로그 갱신은 현재 화면을 유지합니다. 선택된 계약에 충돌이 생기면 이전 결과를 지우고 보류 이유를 표시합니다.
6. 중형의 **픽업별 배분 자동화는 아직 해결되지 않았습니다.** 미확인 계약은 보류 이유만 표시하며 수동 입력을 요구하지 않습니다. 직접 계획이 필요한 경우에만 해당 계약을 선택하고 접힌 「직접 확인한 정보로 별도 예상 계획 만들기」를 사용할 수 있습니다. 이 기능은 자동 연동이 아닙니다. 미확인 계약을 직접 선택하면 전체 선택 묶음을 보류하며, 조용히 빼고 계산하지 않습니다.

로그 원문·공개 유형 표는 아래의 접힌 근거 보기에서 확인할 수 있습니다. 이번 변경은 제공된 로그로 개발 환경에서 재생 검증했으며, 같은 계약 수락 시험을 다시 할 필요는 없습니다.

지도에서 영문 지명을 검색하고 「선택 지점에서 출발」을 누르면 출발지를 바꿀 수 있습니다. 지도 왼쪽 위의 STARMAP 표시 아래에 현재 파트너의 초상화가 표시됩니다. 초상화를 누르면 설정을 엽니다. 기본/상세 화질을 선택할 수 있으며 화면이 가만히 있거나 숨겨져 있을 때는 새 지도 렌더링을 멈춥니다. 실제 게임 FPS 영향은 아직 측정하지 않았습니다.

이 계획은 계약의 **원래 화물** 기준입니다. 이미 일부 적재·배송한 상태를 자동 복원한 것으로 사용하지 마세요. 함선·그리드·출발지·파트너 설정은 같은 로컬 주소에서 새로고침하면 유지됩니다. 실행기를 재시작하여 포트가 바뀌는 경우까지 설정을 이전하는 기능은 아직 없습니다.

## 새 로그 기록을 추가 확인해야 할 때만

1. **연결 확인:** 상태가 ‘실시간 감시 중’이며 마지막 읽기 시각이 갱신되는지 확인합니다. 과거 수락 기록이 먼저 보일 수 있습니다.
2. **새 운송 계약 수락:** 게임에서 계약을 하나 받고 새 카드가 생기는지 확인합니다. 수량 알림이 실제 로그에 있을 때만 카드의 알림 목록이 늘어납니다. 수량·거점·상자 정보가 비어 있으면 자동으로 추정해 채우지 않습니다.
3. **같은 유형 두 계약:** 가능하다면 같은 유형을 별도로 두 건 받아 카드가 각각 유지되는지 확인합니다. 같은 실행 계약을 다시 공유한 알림은 별도 계약으로 복제되지 않아야 합니다.
4. **파티 공유:** 공유 알림만 받은 상태와 실제 수락한 뒤를 비교합니다. 타인의 참여/이탈은 본인의 상태가 되면 안 됩니다. 본인 식별 근거가 부족하면 ‘미확인’으로 남아야 합니다.
5. **가능하면 이탈·재수락:** 포기해도 되는 계약에서만 확인합니다. 동일 실행 ID로 다시 참여하면 기존 이력을 유지합니다. 새 실행 ID가 발급되면 별도 계약입니다. `PlayerLeft`만으로 직접 포기·추방·완료 후 정리 중 원인을 단정하지 않습니다.
6. **감시 일시정지·재개:** 정지 중에는 새 기록을 반영하지 않고, 재개하면 읽지 않은 부분을 처리해야 합니다. 이미 시작된 작은 읽기 작업은 종료된 뒤 멈춥니다.
7. **필요한 기록 저장:** ‘계약 원문 없이 검증 요약 저장’을 눌러 `STAM-log-check.json`을 저장해 주세요. 여기에는 집계·진단·충돌 개수만 있고 계약 제목/실행 ID/캐릭터 ID/로그 경로/연결 키는 없습니다. 자동 전송은 하지 않습니다.

잘못 들어온 것 같다면 임의로 맞추지 말고 **어떤 행동 직후였는지, 화면에 어떻게 나왔는지, 요약 파일**을 알려 주세요. 더 필요한 로그가 있으면 그 행동 전후 구간을 따로 요청하겠습니다. 새 로그 파일을 공유할 때는 개인정보를 먼저 가려 주세요.

실행기만 확인하려면 새 시험판 폴더의 명령 창에서 `start-log-link.cmd --check`를 실행해 주세요. 사용 중인 Node 버전/경로를 표시하고, 파일 선택창 없이 종료합니다.

## 연결이 안 되면

| 표시/상황 | 확인할 것 |
|---|---|
| `Node.js 22 is required.`만 표시됨 | 이전 실행기입니다. 최신 시험판을 새 폴더에 압축 해제해 실행해 주세요. Node 24/26을 제거할 필요는 없습니다. |
| `Node.js was not found on PATH` | Node 22 이상을 설치하고 실행 창을 새로 열어 주세요. |
| `Using Node.js …` 다음에 버전 오류 | 표시된 버전/경로를 확인해 주세요. 22 미만만 차단합니다. |
| 파일 선택창이 열리지 않음 | 위 명령으로 직접 실행해 주세요. 보안 정책을 끄거나 관리자 권한으로 게임에 접근할 필요는 없습니다. |
| 선택한 로그를 읽을 수 없음 | 실행 중인 게임의 `Game.log`인지, 파일이 존재하고 읽기 권한이 있는지 확인해 주세요. 잠김·교체 중이면 다시 시도합니다. |
| 계약이 안 들어옴 | 읽기 시각과 읽은 용량이 갱신되는지 먼저 확인해 주세요. 로그에 없는 정보를 추정 등록하지 않으므로 미지원 형식/누락 가능성을 조사해야 합니다. |
| 내 참여 상태 미확인 | 같은 로그 세대에 본인 캐릭터를 식별할 근거가 부족할 수 있습니다. 다른 사람의 ID를 본인으로 지정하지 않습니다. |
| 연결 키 만료 | 실행 창의 현재 주소를 다시 열어 주세요. 이전 프로그램의 키는 재사용되지 않습니다. |
| 감시 중단 | 상한이나 해석 오류가 발생한 상태입니다. 마지막 정상 기록만 유지하며 부분 정보를 계산에 넘기지 않습니다. 요약을 저장하고 실행 창을 다시 시작해 주세요. |
| 프로그램 종료 | 실행 창에서 Ctrl+C를 누르세요. 화면 연결 해제만 하면 수집기는 계속 실행됩니다. |

## 검증 범위

제공된 Game.log 재생과 합성 이벤트로 검사했습니다. 최신 자동 검사와 브라우저 결과는 [PROJECT_STATUS.md](../PROJECT_STATUS.md)를 확인해 주세요. **새 Windows 실게임 실행과 게임 FPS/GPU 부하는 미확인**입니다. 앞에서 했던 수락·추적 시험을 반복할 필요는 없습니다.

기존 로그인·동기화·실운항 데이터를 이 시험 앱이 덮어쓰지 않습니다. 계약 기록과 주문 초안은 메모리에만 있으며 새로고침하면 로그에서 다시 읽습니다. 과거 계약도 목록에 있으므로 현재 활성 계약 전체로 간주하지 마세요.
