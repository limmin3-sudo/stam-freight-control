# 집에서 하는 실시간 로그 연결 테스트

이번 시험판은 **계약 기록이 자동으로 들어오는지, 같은 유형의 별도 계약이 분리되는지, 파티원의 행동을 본인과 구분하는지** 확인하는 버전입니다. 실제 화물 명세와 상자 구성을 모두 확정하는 단계는 아닙니다. 미확인 값은 넣지 않으며 **적재 계산 가능한 계약 수가 0으로 남는 것이 현재 정상 동작**입니다.

지도·적재 3D의 이번 개선은 별도 기존 앱 화면에서 확인합니다. 로그 실행기에는 3D가 표시되지 않습니다. [전체 완료 범위와 3D 확인 방법](REBUILD-PROGRESS.md)을 참고해 주세요.

## 가장 간단한 실행 방법 — Windows

1. [시험 브랜치 ZIP](https://github.com/limmin3-sudo/stam-freight-control/archive/refs/heads/rebuild/log-evidence-foundation.zip)을 받아 **압축을 풀어 주세요**. 기존 폴더에 덮어쓸 필요는 없습니다.
2. Node.js **22**가 설치되어 있어야 합니다. 없으면 [Node.js 공식 다운로드](https://nodejs.org/en/download)에서 22 버전의 Windows 설치 파일을 선택해 설치해 주세요.
3. 압축을 푼 폴더에서 **`start-log-link.cmd`를 두 번 클릭**해 주세요.
4. 파일 선택창에서 현재 사용하는 게임 폴더의 **`LIVE\Game.log`**를 선택해 주세요. 기본 설치 경로는 `C:\Program Files\Roberts Space Industries\StarCitizen\LIVE\Game.log`입니다. 다른 드라이브나 채널을 사용한다면 실제 실행한 게임의 로그를 선택해야 합니다. `logbackups`의 과거 파일은 실시간으로 갱신되지 않습니다.
5. 자동으로 열린 브라우저에서 **‘실시간 감시 중’**을 확인해 주세요. 브라우저가 열리지 않으면 실행 창에 표시된 주소를 복사해 열면 됩니다.

`npm install`, Three.js 다운로드, Firebase 로그인, 게임 내 명령 입력은 필요하지 않습니다. 게임 폴더에 파일을 설치하거나 수정하지 않습니다. 브라우저와 실행 창은 테스트 중 열어 두세요. 이 연결은 **게임 PC 전용**이며 휴대폰에서 같은 localhost 주소로 접속할 수는 없습니다.

실행 창의 주소에는 로컬 연결 키가 포함됩니다. 주소 전체를 공개하거나 제보에 붙이지 마세요. 브라우저가 열린 뒤 주소창에서는 키를 지우고 해당 탭의 세션에만 보관합니다. 새로고침은 다시 연결되며 프로그램을 재시작하면 새 주소를 사용해야 합니다.

### 명령으로 실행하는 방법

저장소/압축 해제 폴더에서:

```powershell
node scripts/log-link-server.mjs --file "C:\Program Files\Roberts Space Industries\StarCitizen\LIVE\Game.log" --open
```

게임 로그 경로가 다르면 본인 경로로 바꿔 주세요. 프로그램은 지정한 파일 하나만 읽습니다. 브라우저에서 서버에 다른 파일 경로를 전달하는 기능은 없습니다.

## 확인 순서

1. **연결 확인:** 상태가 ‘실시간 감시 중’이며 마지막 읽기 시각이 갱신되는지 확인합니다. 과거 수락 기록이 먼저 보일 수 있습니다.
2. **새 운송 계약 수락:** 게임에서 계약을 하나 받고 새 카드가 생기는지 확인합니다. 수량 알림이 실제 로그에 있을 때만 카드의 알림 목록이 늘어납니다. 수량·거점·상자 정보가 비어 있으면 자동으로 추정해 채우지 않습니다.
3. **같은 유형 두 계약:** 가능하다면 같은 유형을 별도로 두 건 받아 카드가 각각 유지되는지 확인합니다. 같은 실행 계약을 다시 공유한 알림은 별도 계약으로 복제되지 않아야 합니다.
4. **파티 공유:** 공유 알림만 받은 상태와 실제 수락한 뒤를 비교합니다. 타인의 참여/이탈은 본인의 상태가 되면 안 됩니다. 본인 식별 근거가 부족하면 ‘미확인’으로 남아야 합니다.
5. **가능하면 이탈·재수락:** 포기해도 되는 계약에서만 확인합니다. 동일 실행 ID로 다시 참여하면 기존 이력을 유지합니다. 새 실행 ID가 발급되면 별도 계약입니다. `PlayerLeft`만으로 직접 포기·추방·완료 후 정리 중 원인을 단정하지 않습니다.
6. **감시 일시정지·재개:** 정지 중에는 새 기록을 반영하지 않고, 재개하면 읽지 않은 부분을 처리해야 합니다. 이미 시작된 작은 읽기 작업은 종료된 뒤 멈춥니다.
7. **필요한 기록 저장:** ‘계약 원문 없이 검증 요약 저장’을 눌러 `STAM-log-check.json`을 저장해 주세요. 여기에는 집계·진단·충돌 개수만 있고 계약 제목/실행 ID/캐릭터 ID/로그 경로/연결 키는 없습니다. 자동 전송은 하지 않습니다.

잘못 들어온 것 같다면 임의로 맞추지 말고 **어떤 행동 직후였는지, 화면에 어떻게 나왔는지, 요약 파일**을 알려 주세요. 더 필요한 로그가 있으면 그 행동 전후 구간을 따로 요청하겠습니다. 새 로그 파일을 공유할 때는 개인정보를 먼저 가려 주세요.

## 연결이 안 되면

| 표시/상황 | 확인할 것 |
|---|---|
| Node.js 22 필요 | Node 22 설치 후 실행 창을 새로 열어 주세요. |
| 파일 선택창이 열리지 않음 | 위 명령으로 직접 실행해 주세요. 보안 정책을 끄거나 관리자 권한으로 게임에 접근할 필요는 없습니다. |
| 선택한 로그를 읽을 수 없음 | 실행 중인 게임의 `Game.log`인지, 파일이 존재하고 읽기 권한이 있는지 확인해 주세요. 잠김·교체 중이면 다시 시도합니다. |
| 계약이 안 들어옴 | 읽기 시각과 읽은 용량이 갱신되는지 먼저 확인해 주세요. 로그에 없는 정보를 추정 등록하지 않으므로 미지원 형식/누락 가능성을 조사해야 합니다. |
| 내 참여 상태 미확인 | 같은 로그 세대에 본인 캐릭터를 식별할 근거가 부족할 수 있습니다. 다른 사람의 ID를 본인으로 지정하지 않습니다. |
| 연결 키 만료 | 실행 창의 현재 주소를 다시 열어 주세요. 이전 프로그램의 키는 재사용되지 않습니다. |
| 감시 중단 | 상한이나 해석 오류가 발생한 상태입니다. 마지막 정상 기록만 유지하며 부분 정보를 계산에 넘기지 않습니다. 요약을 저장하고 실행 창을 다시 시작해 주세요. |
| 프로그램 종료 | 실행 창에서 Ctrl+C를 누르세요. 화면 연결 해제만 하면 수집기는 계속 실행됩니다. |

## 검증 범위

제공된 빌드 `12913470` 로그와 가상 이벤트로 개발했습니다. 전체 Node 22 테스트 161개와 브라우저 검사를 통과했고, [Windows·Ubuntu 원격 검사](https://github.com/limmin3-sudo/stam-freight-control/actions/runs/41597058933)에서도 로그 관련 35개 검사가 각각 통과했습니다. **Windows 파일 선택창의 실제 조작, 실게임 계약 수락, EAC와 게임 FPS 영향은 집에서 확인해야 합니다.** 다른 게임 빌드까지 정확히 지원한다고 가정하지 않습니다.

현재 시험판은 기존 로그인·동기화·운항 데이터·지도·적재 3D를 수정하지 않습니다. 실행 기록은 메모리에만 있고 다시 실행하면 선택한 로그를 처음부터 읽습니다. 게임 파일 교체 이후에도 이전 관측 이력을 유지하므로 카드 목록을 ‘현재 활성 계약 전체’로 간주하지 마세요.
