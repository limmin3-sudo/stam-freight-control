# 로컬 개발판 실행 안내

현재 작업은 기능 확대 중입니다. 이 문서는 이후 실행할 때의 안내이며, 지금 같은 미션을 반복 테스트하도록 요구하는 문서는 아닙니다.

현재 시험판은 **PC의 로컬 실행기 + 브라우저 화면**입니다. 로그는 PC 안에서 읽습니다. GitHub Pages 사이트에서 실행하는 것이 아닙니다. 런타임을 포함한 설치형 앱은 아직 제작 전이며, 현재는 Node.js 22 이상이 필요합니다. 설치된 24/26을 지울 필요는 없습니다. [Node 공식 다운로드](https://nodejs.org/en/download)

## 실행

1. 최신 시험 브랜치 ZIP을 내려받아 **새 폴더에 압축을 완전히 풉니다.** 기존 실행기가 켜져 있다면 그 창에서 `Ctrl+C`로 종료합니다.
2. 압축을 푼 폴더에서 **`start-log-link.cmd`를 실행**합니다. 관리자 권한은 필요하지 않습니다.
3. 실제 플레이하는 설치 폴더의 **`StarCitizen\LIVE\Game.log`**를 선택합니다. 백업 로그를 고르면 새 게임 기록을 받을 수 없습니다. PTU를 플레이한다면 해당 설치의 Game.log를 선택합니다.
4. 자동으로 열린 화면에서 **실시간 감시 중**을 확인합니다. 검은 실행 창은 켜 두고, 게임에 접속합니다. 메뉴 화면에서는 새 운송 계약이 생기지 않습니다.

브라우저가 열리지 않으면 실행 창의 주소를 복사해 여세요. 주소에 연결 키가 있으므로 공유하지 마세요. 과거 브라우저 탭이나 즐겨찾기 대신 이번 실행기가 연 주소를 사용하세요.

## 계약을 받고 출항하기

1. 왼쪽 **출항 준비**에서 파트너를 고릅니다. **함선·출발지 수정**을 펼쳐 실제 운항에 맞게 확인하고 **이 설정으로 준비**를 누릅니다. 최근 로그 후보가 맞으면 **준비 정보에 적용**을 먼저 사용할 수 있습니다.
2. 게임에서 운송 계약을 받습니다. 검증된 대형은 명세·항로를 연결하고, 확인한 중형은 배송지별 50 SCU 공간을 예약합니다. 현재 로그에 이미 기록된 계약이 있다면 다시 받을 필요가 없습니다.
3. **운송 계약** 목록에서 자동 선택된 계약과 품목·총량을 확인합니다. 준비되지 않은 다른 계약까지 억지로 선택할 필요는 없습니다.
4. **항로 계산·안내 시작**을 누릅니다. 중앙 지도와 아래 적재 3D, 방문 순서를 확인하고 운항합니다. 첫 지도 실행에는 3D 라이브러리 다운로드가 한 번 필요합니다.
5. 게임에서 이동·픽업·배송을 진행합니다. 계약 목표/완료 기록이 로그에 찍히면 별도로 표시됩니다. **운송 중 · 다음 구간**은 예상 항로 안내를 넘기는 버튼이며 실제 하역/계약 완료/수입을 입력하는 버튼이 아닙니다.

현재 확인한 자동 명세: 빌드 **12913470**, Ship Ammunition **16 SCU×4**, Hydrogen **16 SCU×4**, Medical Supplies **2 SCU×20** — 총 **28상자/168 SCU**. 같은 대형 제목이라도 다른 정의 ID나 빌드이면 동일 구성으로 확정하지 않습니다. 중형은 Nitrogen 24 / Organics 12 / Ranta Dung 14 SCU를 반투명 예약 공간으로 표시합니다. 전체 픽업·배송지가 확인된 계약은 공간 예약과 함께 방문 항로를 연결합니다. 계약별 모든 픽업을 마친 뒤 배송하도록 순서를 잡으며, 픽업별 수량이나 단계별 실제 적재량은 추정하지 않습니다. 전체 목표가 없는 부분 예약에는 항로를 만들지 않습니다. 다른 유형은 정확한 목표 ID에 품목·SCU·배송 마커가 함께 있는 부분만 예약합니다.

### 실제 상자 구성과 화면 보조 감시

- 적재 화면의 계약별 화물에서 **상자 구성 직접 지정**을 펼쳐 크기별 개수를 넣습니다. 합계가 계약 SCU와 같아야 적용됩니다. 같은 계약의 새 목표가 들어와도 적용값을 유지하지만 화물·배송지·수량이 바뀌면 재확인을 요구합니다. 현재 이 입력은 페이지 메모리에만 보관되며 새로고침·계정 전환 때 보존되지 않습니다.
- **화면 보조 감시**는 선택 기능입니다. 실시간 로그 연결 후 게임 화면 연결 → 공유할 창 선택 → 읽을 영역 드래그 → 선택한 영역 감시 순서입니다. 수락 알림 또는 진행 중 계약 수 중 하나를 선택합니다. 계약 수는 전체 게임 계약 수일 수 있어 운송 계약 수로 단정하지 않습니다.
- 첫 활성화에는 약 11 MB의 고정 버전 인식 도구/모델을 받습니다. 이후 검증된 로컬 파일을 재사용합니다. 화면은 브라우저 안에서 처리하며 이미지·인식 문장을 서버나 계정으로 전송하지 않습니다. 화면 감시 끄기 또는 브라우저의 공유 종료로 멈춥니다.
- 4초마다 작은 영역의 변화를 검사하고 바뀔 때만 OCR을 실행합니다. 백그라운드 브라우저 제한·짧은 알림·다른 창·최소화·해상도 변경에 따라 놓칠 수 있습니다. 화면 크기가 바뀌면 다시 영역을 지정해야 합니다.
- 화면 후보는 확인 중으로 남기며 같은 제목·가까운 시각의 유일한 로그만 대조합니다. 같은 제목 여러 건·오독·로그 미수신은 자동 합치지 않습니다. **OCR 후보만으로 경로·적재·계약 완료를 바꾸지 않습니다.**

## 다시 실행할 때

- 기본 주소는 `http://127.0.0.1:41454`로 고정됩니다. 같은 브라우저 프로필에서 다시 켜면 로컬 설정 저장 공간을 계속 사용합니다. 연결 키는 매번 새로 발급됩니다.
- **이전 설정은 현재 함선/위치 자동 감지가 아닙니다.** 다시 확인한 뒤 사용합니다. 계약 관측은 현재 선택한 로그를 다시 읽습니다. 삭제·교체된 과거 로그의 계약이나 진행을 영구 복원하는 기능은 아직 없습니다.
- 과거 시험판의 임의 포트에 있던 브라우저 데이터나 운영 사이트의 데이터가 새 주소로 자동 이동하지는 않습니다. 기존 클라우드 데이터는 계정 로그인으로 불러올 수 있습니다. 실제 계정/PC 간 복원은 최종 확인 대상입니다. 시크릿 모드·브라우저 데이터 삭제·다른 프로필도 저장 공간이 다릅니다.
- **주소가 이미 사용 중**이면 이전 STAM 실행 창을 종료하고 다시 실행합니다. 임의로 다른 프로그램을 종료하지 마세요. 개발용 `--port`로 다른 주소를 지정할 수 있지만 저장 공간도 바뀝니다. `--port 0`은 임시 주소 검사에만 사용합니다.

## 문제가 생기면

- 계약이 들어오지 않으면 실제 플레이 설치의 Game.log인지, 감시 중인지 먼저 확인합니다. 계약 정보가 부족하면 목록의 보류 이유를 봅니다. 계약을 포기/반복 수락하지 않아도 됩니다.
- 게임 추적을 켜고 연속 수락하면 항상 누락된다는 결론은 아직 없습니다. 추적 상태 비교는 [최종 검증 목록](FINAL-GAME-VALIDATION.md)에 남겨 두었습니다.
- 화면 아래 **연결 진단 → 계약 원문 없이 검증 요약 저장**으로 요약을 남길 수 있습니다. 오류 안내와 함께 알려주시면 됩니다. 로그/스크린샷은 자동 전송하지 않습니다.
- 현 단계에서 실제 연속 위치, 실제 실린 상자·잔여 화물, 지급액의 계약 귀속·누적 수입 자동 기록은 완성되지 않았습니다. **이 흐름의 Windows 실게임 운항과 게임 동시 실행 FPS는 미확인**입니다.

## 운송 중 계약 제외

- 계약 옆 **운송에서 제외**를 누르면 “이 계약의 화물이 함선에 남아 있나요?”를 묻습니다. 게임 계약 포기는 게임에서 직접 진행합니다.
- **없습니다**: 계약의 항로와 적재 공간을 제외하고 다시 계산합니다.
- **남아 있습니다**: 아직 실려 있는 상자·예약 영역을 고르고 표시 위치가 맞는지 확인합니다. 선택한 위치를 유지한 채 남은 계약을 다시 배치합니다. 영역 일부만 실려 있다면 영역 전체를 보수적으로 확보합니다.
- 종료·참여 이탈 기록이 들어와도 남은 화물을 자동 삭제하지 않습니다. 확인을 미루거나 새로고침해도 화물 확인 상태를 보관합니다.
- **함선에 남은 화물 → 화물 정리**는 실제로 화물이 없어진 뒤 사용합니다. 위치를 알 수 없는 화물은 새 적재 계산을 보류합니다. 기록은 같은 브라우저·계정별로 보관하고 계정 동기화에는 보내지 않습니다.

## 직접 지정한 상자 구성

- 상자 구성의 **이 상자 구성 적용**을 누르면 같은 브라우저·계정에 저장합니다. 로그를 다시 읽었을 때 같은 계약과 화물 정보가 일치하면 복원합니다.
- 빌드·계약 유형·품목·SCU·픽업/배송 정보가 달라지면 재확인을 요청합니다. 구성 수정 또는 **자동 구성으로 되돌리기**로 해결합니다. 같은 유형의 다른 계약에는 복사하지 않습니다.
- 다른 PC와 동기화되지 않으며, 실제 함선에 실린 위치나 배송 진행을 복원하는 기능은 아닙니다.

## 운송 중 적재 상태 이어가기

1. 적재도에서 **적재 상태 확인**을 엽니다. 선택한 파트너가 안내합니다.
2. **실린 화물 위치 유지**에서 작업 거점과 화물을 고르고, 실제 위치가 적재도와 맞는지 확인합니다. 새 계약을 추가해도 이 위치를 유지합니다. 예약 영역은 공간만 확보하며 픽업 완료로 처리하지 않습니다. 영역 일부만 사용하는 경우 전체 영역을 보수적으로 유지합니다.
3. 배송했다면 **배송한 화물 반영**으로 전환하고 해당 배송지를 고릅니다. 기록된 실물 상자 중 그 배송지 화물만 선택할 수 있습니다. 전달 확인 후 공간과 항로를 다시 계산합니다.
4. 잘못 기록했다면 **배송 기록 되돌리기**를 사용합니다. 상자가 이전 위치에 있는지 확인하며, 다른 적재 화물과 겹치면 되돌리지 않습니다.
5. 재실행 후 같은 브라우저·계정에서는 적재 기록을 복원해 새 로그와 대조합니다. 계약이 잠시 보이지 않아도 실린 화물 위치는 유지합니다. 출발지는 마지막으로 직접 선택한 작업 거점이므로 실제 현재 위치와 맞는지 확인합니다.

게임의 실제 적재·하역·계약 완료를 자동 수행하지 않습니다. 현재 원문 로그로 상자 위치를 알 수 없어 이 상태는 사용자 확인 기준이며, 계정 운항 기록·수입을 자동 생성하지 않습니다. 함선/화물칸/화물 내용이 바뀌면 위치 확인 전 재배치를 보류합니다. 기존 적재를 유지한 계산은 전체 남은 공간이 한 번에 들어가는 경우를 지원하며, 이를 넘는 분할 운송과 실제 위치 편집은 후속 작업입니다.
