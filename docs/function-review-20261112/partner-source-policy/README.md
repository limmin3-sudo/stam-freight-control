# 파트너 역할·SCMDB/Wiki 보충 검수

작업본: `feature/mission-intake-flow-20261112`. 기존 미커밋 변경을 보존했다. 이 기록은 공개 배포 완료를 뜻하지 않는다.

## 사용자 확정 기준

- 새 운송을 시작할 때 파트너부터 선택한다. 기존 계약/운항 저장 상태는 유지한다.
- 오퍼레이터는 픽업·배송 경로 전용이다. 적재량/상자 배치 계산과 적재 3D를 관제 화면에서 보여주지 않는다. 구형 workspace URL도 동일하다.
- 미션·배송지별 실제 총 SCU가 미확인이고 입력 없이 계속하면 오퍼레이터로 계산한다. 여러 픽업의 배분이 없어도 배송지별 총량이 있으면 항해사 계산이 가능하다. 목록 최대치는 실제 총량으로 간주하지 않는다.
- 보상·내용·유형 누락은 파트너 전환 기준이 아니다. 사용자가 오퍼레이터를 직접 선택하면 수량을 알아도 경로 전용을 유지한다.
- **최종 선택 연출은 2.5D 관제센터에 서 있는 파트너를 누르는 구성이다. 별도 초상화 카드는 임시 기능 화면이며, 최종 연출 승인이 아니다.** 연출은 후속 작업이다. 임시 화면에서도 큰 세로 원본 초상화를 전부 표시하고 머리를 자르는 가로 크롭을 제거했다.
- 고정 상단바와 승인 사이드바를 유지한다.

## 자료 정책과 실제 갱신

`scripts/wiki-mission-supplement.mjs`가 SCMDB와 같은 정의 UUID의 빈 필드만 Wiki로 보충한다. 같은 값은 출처를 합치고 다른 값은 별도 기록한다. SCMDB의 기존 값, 0/false, 내부 불일치와 실제 수주 계약을 덮어쓰지 않는다. 이름만으로 다른 정의나 변형 미션을 결합하지 않는다. Wiki 전용 항목은 자신의 UUID로만 추가한다.

- SCMDB: `4.10.2-live.12913470`
- Wiki API: `4.10.2-LIVE.12881860`
- 실제 Wiki 목록 1,819개 및 운송 계열/변형 1,072개 상세 요청에서 2,830개 레코드를 수집했다. 두 자료의 빌드 차이는 출처별로 보존한다.
- 병합 후 정의 3,458개, 운송 정의 1,396개. Wiki 전용 정의 1,098개, 그중 운송 532개. 새 Wiki 항목을 포함한 보충 필드 수는 10,304개다.
- 기존 SCMDB 필드 25,064개가 유지되는 것을 실제 데이터 대조로 확인했다.
- `data/wiki-mission-supplement.json`에는 필요한 필드만 남긴 검증용 캐시를 보존한다. 원본 32MB 다운로드는 저장소에 추가하지 않았다.
- `refresh-missions.mjs`와 기존 Pages 일일 갱신 작업이 SCMDB 후 Wiki를 별도로 갱신한다. SCMDB에 변화가 없어도 Wiki를 확인한다. 연결 실패 시 검증된 캐시를 유지하고 잘못된 응답으로 기존 파일을 교체하지 않는다. 체크섬은 로컬 무결성 검사용이며 공식 API 서명은 아니다.
- 임시 디렉터리에서 실제 API/캐시를 사용하는 재갱신을 실행해 위 정의 수를 재현했다. 공개 CI 스케줄의 실행/배포는 이번 검증 범위가 아니다.

미션 카드의 펼침 자료와 정보실 목록에 유형·내용·보상 참고 및 출처/버전을 표시한다. 목록의 보상을 수주 계약의 확정 보상으로 넣지 않는다. 기존 SCMDB 템플릿 별칭이 Wiki 별칭 중복 때문에 무효화되지 않게 SCMDB 우선순위를 유지했다.

## 주요 파일

- `PartnerChoice.tsx`, `partner-policy.ts`, `SpaceExperience.tsx`: 새 운송의 파트너 선택과 기존 운항 보존.
- `MissionConsole.tsx`, `ScreenshotIntake.tsx`: 총 SCU 미입력 시 경로만 계속하기와 자동 역할 전환.
- `FlightOperations.tsx`, `ControlRoom.tsx`: 오퍼레이터의 기본/구형 관제에서 적재 UI 제거.
- `receipt-log.worker.mjs`, `MissionReference.tsx`: 정의 ID 기반 자료 표시, 수주 보상과 목록 보상의 분리.
- `scripts/wiki-mission-supplement.mjs`, `scripts/refresh-missions.mjs`, `mission-catalog.mjs`, `contract-info.mjs`, `operations-intel.mjs`: 병합/갱신/우선순위/출처 표시.

## 검증

- 루트 테스트 238/238, 앱 테스트 48/48, TypeScript/Vite 배포용 빌드 통과.
- 실제 브라우저: 파트너 선택 전 미션 진입 차단, 총량 없는 다중 픽업을 항해사로 선택한 뒤 계산하면 오퍼레이터로 전환, 기본/구형 관제에서 적재 3D 없음, 운항 시작/출발/재접속 상태 유지, 총량 22 SCU이면 항해사와 실제 적재 3D 유지.
- 개발 및 배포용 빌드에서 역할 검사를 통과했다. 실제 로그 Worker의 UUID 자료 연결/SCMDB+Wiki 출처/미션 유형 표시, 8/4/4 SCU 배송 계산, 중복 로그 수신 방지, 완료 계약 계산 차단을 배포용 브라우저에서 확인했다. 목록 보상이 표시되어도 수주 보상은 미확인으로 남는 것도 검사했다.
- 초상화 수정 후 배포용 화면을 다시 캡처했다. 데스크톱은 두 원본을 각각 424×565 크기에 `object-fit:contain`으로 모두 표시한다. 390px 모바일에서 가로 넘침이 없다. `partner-choice-desktop.png`, `partner-choice-mobile.png`는 실제 브라우저 캡처다.
- 자료 테스트: 같은 UUID만 보충, 0/false 유지, 다른 값 분리, 기본 자료의 모호함 유지, 변형에 부모 보상 복사 금지, 반복 갱신 안정성, 오프라인 캐시와 손상 응답 보존, SCMDB 별칭 우선.
- 브라우저의 계약 입력은 합성 로그/계약을 사용한다. 실게임 OCR 정확도, 실제 기기/GPU, Safari/Firefox, 수주 보상과 자료집 보상의 일치는 보장하지 않는다.

```sh

STAM_MISSION_URL=http://127.0.0.1:5188/ node scripts/check-partner-policy-browser.mjs
```

`5188`은 현재 작업본의 배포용 빌드 미리보기다. `5186`은 개발 서버다. 브라우저 프로세스는 이 Cloud 환경에서 네트워크 사용 가능 실행 권한이 필요하다. 제한된 실행에서 Chromium 자체가 SIGTRAP으로 종료된 시도는 제품 검사 결과에 포함하지 않았다.

## 남은 작업

2.5D 관제센터의 실제 인물 클릭에 파트너 선택 함수를 연결하고 임시 카드 화면을 대체한다. 기존 진입 영상/공간 구성을 바꾸거나 새 연출을 확정하지 않는다. 지도/관제의 전체 테마 정비와 미완성 영상·음향 작업은 별도 후속 범위다.
