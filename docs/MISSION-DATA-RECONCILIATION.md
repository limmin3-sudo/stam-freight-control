# 미션 자료 출처와 자동 갱신

사용자 최종 결정(2026-11-07): **미션 자료는 SCMDB만 사용한다.** Wiki 보완·충돌 시 우선 선택 방식은 이 결정으로 대체됐다. 실제 수량·보상·상자 구성과 수주별 소유권은 보존한다. 지도·함선·퀀텀 자료의 Wiki 사용은 별도다.

- [SCMDB 사이트](https://scmdb.dev/)
- [공개 데이터 미러](https://github.com/KrovaxCode/SCMDB_DATA): 원본 저장소에서 자동 동기화한다고 명시하며, 2026-11-04·05·06(KST)의 동기화 이력을 확인했다. CIG 공식 데이터 서비스라는 의미는 아니다.
- 최초 묶음: `4.10.2-live.12913470`, commit `937f66810a392aa5682b9615a1afbff20fe96e3f`, Git blob `a71db80e033817c8af67b309f825c2f618eb4505`, 원문 SHA256 `72153c1ba58e497549628f134168c2f2c97b342c76e436292a304407a61a5186`.

## 사용하는 파일

`data/mission-details.json`: 정의 UUID2,360개의 유형·본문·랭크·기본 보상 등. `data/log-mission-index.json`: 안전하게 단일 명세를 정할 수 있는 화물 정의864개 및 위치 후보. `data/hauling-missions.json`: 같은 SCMDB 원문에서 만든 수동 입력의 품목·미션 매칭 자료. 위 개수는 최초 묶음 기준이며 자동 갱신 시 달라질 수 있다.

정의 UUID와 `contractDefinitionIds` 별칭으로 찾고 수주 인스턴스를 합치지 않는다. 부모의 `subContractIds`에만 등장하는 자식은 부모 보상으로 채우지 않는다. 같은 SCMDB UUID에 서로 다른 후보가 남으면 해당 값은 미확인으로 남긴다. 위키에만 있는 정의는 런타임 미션 자료에 넣지 않는다.

화물 배열의 순서와 로그 objective 인덱스를 사용하며, 배열과 다중 장소의 대응이 불명확하면 장소를 임의로 채우지 않는다. SCMDB의 위치 후보 이름과 게임 로그의 실제 좌표 표식을 구분한다. 선택형 명세는 임의의 한 가지를 선택하지 않는다. `maxSCU:0`과 양수 `minSCU`의 고정 쿼터 표기는 최소값을 고정량으로 처리한다. 포드는 사용자 확인 규칙인1개=1 SCU를 유지한다.

SCMDB가 제공하지 않는 수량·규격은 실제 입력을 받는다. 최대치가 확인된 경우에만 최대치 예상 선택을 쓸 수 있다. 실제 총량을 입력하면 그 수주×배송지의 총량을 한 번 예약하며 목록 최대치를 다시 더하지 않는다.

## 자동 갱신

기존 Pages 작업의 매일 **09:23 KST** 예약 실행에서 `scripts/refresh-missions.mjs`가 수행된다. main 배포나 수동 Actions 실행에서도 확인한다. GitHub 작업 대기 때문에 실제 실행은 늦어질 수 있다.

1. SCMDB 미러의 main commit을 고정한다.
2. 그 commit의 `game-versions.json`에서 LIVE만 선택한다. 더 새 PTU가 있어도 제외한다.
3. 같은 commit의 원문을 내려받고 GitHub blob SHA1·바이트 수·JSON 버전을 검증한다. SHA256과 commit을 출처로 저장한다.
4. 정의·명세를 정규화하고 비정상적인 자료 급감 등 검증 실패 시 기존3개 파일을 유지한다. 성공 시 세 파일을 함께 교체한다. 내용이 같으면 갱신하지 않는다.
5. 전체 테스트와 Pages 배포를 통과한 묶음이 공개된다. 테스트·배포 실패 시 기존 공개 사이트가 유지된다. 실행 중인 화물을 새 목록으로 조용히 바꾸지 않는다.

이후 사이트를 새로 열거나 새로고침하면 공개된 미션 자료를 확인한다. 연결 앱의 웹 묶음은 기존 검증·적용 절차를 따른다. 실제 입력 데이터는 지우지 않는다.

## 최초 묶음 재생성

```sh
node scripts/build-scmdb-missions.mjs SCMDB_JSON
node scripts/build-ai-korean.mjs
```

최초 생성 명령은 원문 체크섬을 확인한다. 자동 갱신은 고정된 최신 commit과 독립적인 GitHub blob 메타데이터를 검증한다. 과거 Wiki 데이터는 이전 저장 형식의 회귀 테스트에만 보존하며 공개 사이트 묶음에 포함하지 않는다.
