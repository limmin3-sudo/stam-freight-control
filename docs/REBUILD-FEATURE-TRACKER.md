# STAM 재구축 전체 기능 목록

2026-11-03 사용자 지시를 기준으로 작성. 구현 완료 목록이 아니라 **유지할 기능, 합칠 기능, 미완료 범위와 완료 조건**이다. 기존 코드의 존재와 새 운송 화면에 연결된 상태를 구분한다. 이 문서에서 빠진 기존 기능을 임의로 삭제하지 않는다.

[로그 연동 운송 준비 흐름](FLIGHT-READY-FLOW.md): 파트너 선택→계약 수신 대기→상태에 따라 바뀌는 주 버튼. 계약 전 파트너·대기와 이전 설정 확인/수정, 단일 주 버튼을 연결했다. 최근 함선/창고 후보의 명시 적용을 연결했다. 현재 탑승·위치 확정과 완전 자동 채움은 남아 있다.

2026-11-03: 추적 중 새 수락 시 목표가 누락될 수 있다는 사용자 조사/경험을 반영했다. 마커 없는 수락을 별도 확인 대기 목록에 보관하고, 같은 실행 ID의 뒤늦은 정보로 연결한다. 준비된 다른 계약은 계속 사용하며 반복 마커·진행 알림으로 동일한 원래 계획/예상 이동을 초기화하지 않는다. 게임이 아예 쓰지 않은 정보를 복원하는 기능이나 추적 전환 자동 조작은 아니다. [조사·복구·한계](LOG-OBJECTIVE-RECOVERY.md).

[최종 실게임 검증 목록](FINAL-GAME-VALIDATION.md): 추적 유지/해제 연속 수락, 파티 공유, 화물·위치·계정·부하 조건과 통과 기준. 지금 반복 시험을 요구하는 목록이 아니다.

## 제품 흐름과 화면

원래 아파트의 배치를 유지하고 가구·설비를 교체한다. 기본 화면은 왼쪽 계정/함선/시작/계약, 가운데 큰 지도와 아래 적재 3D, 오른쪽 경로/작업 안내. 관제 모드는 지도 왼쪽·적재 오른쪽·운항 안내 아래. 같은 렌더러를 재사용한다.

1. 로그인하면 기존 사용자 데이터·함선·설정·기록을 복원한다. 기존 자료를 지우거나 다른 스키마로 덮어쓰지 않는다.
2. 처음 한 번 사용자가 Game.log를 선택한다. 로그 원문은 서버로 보내지 않는다.
3. 파트너·함선·출발지를 고른다. 함선 감지는 근거가 있을 때 후보로 제시하며 보유/탑승/조종을 구분한다.
4. 계약 수락·본인 참여를 실행 계약 ID로 구분해 자동 표시한다. 같은 유형의 공유 계약도 합치지 않는다.
5. 정의 ID로 공개 목록을 조회하고 실제 로그 목표·공개 규칙·확인된 고정 프로필을 대조한다.
6. 부족한 항목만 추가 근거나 선택적 OCR로 보완한다. 이미 얻은 값을 다시 입력시키지 않는다. 계약별 준비 상태를 보여 주며 다른 준비된 계약의 사용을 막지 않는다. 사용자가 미확인 계약을 직접 계산 대상으로 선택했다면 조용히 빼고 계산하지 않는다.
7. 파트너에 맞춰 경로·배치를 계산한다. 미확인 상자 조합의 예상 배치는 명시적으로 구분한다. 모르는 픽업별 수량을 균등 배분하지 않는다.
8. 운항 중 목표·완료 근거를 반영한다. 새 계약을 받아도 이미 실린 화물의 배치와 진행 상태를 보존한다.
9. 완료와 지급을 대조해 운항 기록·거리·수입을 갱신한다. 불분명한 지급은 미배정 수입으로 남긴다.

| SCStats / SC Overlay | 통계·정보 배치 아이디어 | 제한된 라이선스의 코드 재사용 제외 |

OCR은 과거 제외 의견 이후 **보조 활용 허용으로 변경**됐다. 사용 통계 전송은 운송에 필요하지 않아 제외한다. 메모리 읽기·프로세스 주입·패킷 감청·입력 매크로·게임 파일 수정·EAC 우회·RSI 로그인 수집은 계속 금지한다.

## 가볍고 정확하게 합치는 구조

- 로그는 한 수집기에서 증분 읽기, 한 번 파싱한다. 외부 도구들을 모두 실행시키지 않는다.
- 계약 실행 ID·정의 ID·목표 ID·출처·게임 빌드·관측 시각을 보존한다. 같은 로그를 여러 도구가 읽은 결과는 독립 증거 여러 개가 아니다.
- 빠른 로그 반영과 비싼 보완 작업을 분리한다. 공개 데이터는 캐시하고 OCR은 필요할 때만 실행한다.
- 계약별로 `확인됨 / 일부 확인 / 미확인 / 충돌`을 표시한다. 정보가 늦으면 해당 항목만 대기한다.
- 적재/경로 계산은 Worker, 변경은 묶어 재계산한다. 이미 실린 위치와 실제 진행을 보존한다.
- 기본/관제는 같은 지도·적재 캔버스를 쓴다. 정지·비표시 화면은 렌더를 쉰다. 위치 추적과 카메라 움직임을 분리한다.
- 실제 좌표를 공급하는 어댑터가 아직 없으면 예상 표시만 제공한다. 새 근거가 생길 때 부드럽게 보정하되 자동 배송 처리하지 않는다.

## 실행 순서

1. 연결됨: 원래 화면 구도, 예상 이동, 관제 추적, 상태 배지. 실게임 부하 검증은 남음.
2. 계정·설정·기존 기록 연결됨. 업데이트·피드백·개인 장소도 연결됨. 실제 계정 복원 검증은 남음. 기존 데이터 이전 보호.
3. 세션 복원과 함선/위치/진행/보상 이벤트 통합. 동시에 공개 정의 목록과 자동 명세 범위 확대.
4. 누락 항목 OCR 보조, 실제 상자 구성 보정과 aboard 보존. 미확인 유형은 개별 보류.
5. 번역 교체 승인·언어 모드·설치형 배포·실게임 부하 확인. 운영 반영은 사용자의 ‘올려’ 지시 후.

현재 자동 미션 범위의 부족을 UI 완료로 포장하지 않는다. 반대로 미션 근거 조사 때문에 독립적인 계정·화면·성능 작업을 멈추지 않는다.

### 2026-11-04 공간 예약 및 상자 보정

- 배송지 우선 공유 배치, 내부 계약 소유권 보존. 66 SCU는 32+32+2 가이드이며 실제 세 상자라는 뜻이 아니다. 작은 그리드는 가이드만 분할하고 사용자가 지정한 실제 상자는 분할하지 않는다.
- 상자 크기별 개수 직접 입력, 총량 검증·변경된 화물 바인딩 검증. 현재 메모리 내 초안이며 영구 저장·aboard 적용은 남았다.
- 확인되지 않은 픽업별 배분은 채우지 않는다. 공간 예약을 포함한 선택은 항로를 만들지 않으며 알려진 다른 계약의 항로와 합치는 단계는 남았다.
