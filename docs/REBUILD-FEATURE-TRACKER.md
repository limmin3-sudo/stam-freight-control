## 제품 흐름과 화면

원래 아파트의 배치를 유지하고 가구·설비를 교체한다. 기본 화면은 왼쪽 계정/함선/시작/계약, 가운데 큰 지도와 아래 적재 3D, 오른쪽 경로/작업 안내. 관제 모드는 지도 왼쪽·적재 오른쪽·운항 안내 아래. 같은 렌더러를 재사용한다.

1. 로그인하면 기존 사용자 데이터·함선·설정·기록을 복원한다. 기존 자료를 지우거나 다른 스키마로 덮어쓰지 않는다.
2. 처음 한 번 사용자가 Game.log를 선택한다. 로그 원문은 서버로 보내지 않는다.
3. 파트너·함선·출발지를 고른다. 함선 감지는 근거가 있을 때 후보로 제시하며 보유/탑승/조종을 구분한다.
4. 계약 수락·본인 참여를 실행 계약 ID로 구분해 자동 표시한다. 같은 유형의 공유 계약도 합치지 않는다.
5. 정의 ID로 공개 목록을 조회하고 실제 로그 목표·공개 규칙·확인된 고정 프로필을 대조한다.
6. 부족한 항목만 추가 근거나 선택적 OCR로 보완한다. 이미 얻은 값을 다시 입력시키지 않는다. 계약별 준비 상태를 보여 주며 다른 준비된 계약의 사용을 막지 않는다. 사용자가 미확인 계약을 직접 계산 대상으로 선택했다면 조용히 빼고 계산하지 않는다.
7. 파트너에 맞춰 경로·배치를 계산한다. 미확인 상자 조합의 예상 배치는 명시적으로 구분한다. 모르는 픽업별 수량을 균등 배분하지 않는다.
8. 운항 중 목표·완료 근거를 반영한다. 새 계약을 받아도 이미 실린 화물의 배치와 진행 상태를 보존한다.
9. 완료와 지급을 대조해 운항 기록·거리·수입을 갱신한다. 불분명한 지급은 미배정 수입으로 남긴다.

## 다른 도구에서 합칠 기능

다음은 사용자와 합의한 **기능 참고 목록**이다. 이번 UI 작업에서 해당 도구의 최신 코드/약관을 다시 검토했다는 뜻이 아니다. 코드나 자료를 실제 가져올 때는 고정 소스·라이선스·출처를 기록하고 필요한 표시를 유지한다. 다른 도구가 제공한다는 사실만으로 CIG 허용 근거로 삼지 않는다.

| 참고 도구 | STAM에 합칠 기능 | 검증 조건 |
|---|---|---|
| SC Bridge | 세션 복원, 여러 줄 이벤트 결합, 함선·위치·계약 상태 | 본인/타인, 탑승/조종/보유 구분. 필요한 이벤트만 처리 |
| SuperCargo | 수락·목표·종료·공유, 파일 교체, 목적지별 목록, 계약 정보 보완 | 공개·허용 출처 우선. global.ini/contracts.ini 직접 읽기를 이 이름만 보고 채택하지 않음 |
| SuperCargo의 보상 연결 | 완료와 지급 대조, 수입 통계 | 직전 계약에 다음 지급을 무조건 연결하지 않음. 복수 후보는 미배정 수입 |

OCR은 과거 제외 의견 이후 **보조 활용 허용으로 변경**됐다. 사용 통계 전송은 운송에 필요하지 않아 제외한다. 메모리 읽기·프로세스 주입·패킷 감청·입력 매크로·게임 파일 수정·EAC 우회·RSI 로그인 수집은 계속 금지한다.

## 가볍고 정확하게 합치는 구조

- 로그는 한 수집기에서 증분 읽기, 한 번 파싱한다. 외부 도구들을 모두 실행시키지 않는다.
- 계약 실행 ID·정의 ID·목표 ID·출처·게임 빌드·관측 시각을 보존한다. 같은 로그를 여러 도구가 읽은 결과는 독립 증거 여러 개가 아니다.
- 빠른 로그 반영과 비싼 보완 작업을 분리한다. 공개 데이터는 캐시하고 OCR은 필요할 때만 실행한다.
- 계약별로 `확인됨 / 일부 확인 / 미확인 / 충돌`을 표시한다. 정보가 늦으면 해당 항목만 대기한다.
- 적재/경로 계산은 Worker, 변경은 묶어 재계산한다. 이미 실린 위치와 실제 진행을 보존한다.
- 기본/관제는 같은 지도·적재 캔버스를 쓴다. 정지·비표시 화면은 렌더를 쉰다. 위치 추적과 카메라 움직임을 분리한다.
- 실제 좌표를 공급하는 어댑터가 아직 없으면 예상 표시만 제공한다. 새 근거가 생길 때 부드럽게 보정하되 자동 배송 처리하지 않는다.

## 실행 순서

1. 연결됨: 원래 화면 구도, 예상 이동, 관제 추적, 상태 배지. 실게임 부하 검증은 남음.
2. 계정·설정·기존 기록 연결됨. 업데이트·피드백·개인 장소도 연결됨. 실제 계정 복원 검증은 남음. 기존 데이터 이전 보호.
3. 세션 복원과 함선/위치/진행/보상 이벤트 통합. 동시에 공개 정의 목록과 자동 명세 범위 확대.
4. 누락 항목 OCR 보조, 실제 상자 구성 보정과 aboard 보존. 미확인 유형은 개별 보류.
5. 번역 교체 승인·언어 모드·설치형 배포·실게임 부하 확인. 운영 반영은 사용자의 ‘올려’ 지시 후.

현재 자동 미션 범위의 부족을 UI 완료로 포장하지 않는다. 반대로 미션 근거 조사 때문에 독립적인 계정·화면·성능 작업을 멈추지 않는다.

### 2026-11-04 공간 예약 및 상자 보정

- 배송지 우선 공유 배치, 내부 계약 소유권 보존. 66 SCU는 32+32+2 가이드이며 실제 세 상자라는 뜻이 아니다. 작은 그리드는 가이드만 분할하고 사용자가 지정한 실제 상자는 분할하지 않는다.
- 상자 크기별 개수 직접 입력, 총량 검증·변경된 화물 바인딩 검증. 현재 메모리 내 초안이며 영구 저장·aboard 적용은 남았다.
- 확인되지 않은 픽업별 배분은 채우지 않는다. 전체 목표가 확인된 중형·대형 혼합 선택은 방문 항로를 연결한다. 모든 픽업 선행, 전체 공간이 한 번에 들어가는 경우로 한정하며 픽업별 수량을 만들지 않는다. 부분 근거만 있는 계약의 전체 항로는 보류한다.
- 목록의 1,840개 정의는 공개 목록 범위이며 게임 내 모든 유형/모든 실행 조합 지원을 보장하지 않는다.

### 2026-11-04 계약 제외·남은 화물

- 계약 제외 질문을 “남아 있습니다 / 없습니다”로 정리. 일부 상자·예약 영역 선택 및 표시 위치 확인 후 남은 화물을 고정한다.
- 남은 화물은 계약 항로에서 제외하되 공간·위치는 유지. 마지막 계약을 제외해도 남은 화물 표시를 유지한다. 해당 그리드 끄기와 변경된 화물칸 구성을 차단한다.
- 종료/참여 이탈 후 확인 대기를 로컬에 저장하고 재접속 후에도 다시 묻는다. 계정별 로컬 기록이며 Firebase 동기화 대상이 아니다.
- 일반 계약의 실제 aboard 자동 감지, 남은 화물 위치 직접 편집, 확정 적재의 단계별 재개는 후속 작업이다. 실게임 미확인.

### 현재 남은 작업 순서 (2026-11-04 갱신)

목표는 기존 STAM의 배치·지도·파트너·계정 기능을 유지하며 로그 기반 자동 입력을 붙이는 것이다. 현재 `log-link.html`은 별도 개발 진입점이며, 운영 `index.html`과 최종 사용자 흐름을 합치는 작업은 완료되지 않았다.

1. **운항 연속성:** 사용자 확인 기준 활성 화물 위치 유지·부분 배송·배송 되돌리기·로컬 복원·새 계약 합류/제외는 연결했다. 실제 aboard 자동 판별, 위치 직접 편집, 진행 중 분할 운송, 계정 간 운항 상태 공유와 게임 재접속 전체 검증은 남았다.
2. **명세 범위 확대:** 일반 유형의 픽업별 배분·배송지, 빠진 로그의 보완 경로, 실제 상자 구성 교차 검증. 공개 목록1840개가 전 유형 자동 지원을 뜻하지 않는다. 근거 없는 값은 넣지 않는다.
3. **함선·위치:** 지원 함선 확대, 본인 조종 여부 확인, 실제 위치 자료가 있는 경우에만 지도 동기화. 예상 이동은 계속 구분한다.
4. **기존 기능 통합 마무리:** 한 진입 흐름, recipes 재사용 제안, 실제 완료·보상과 기록/통계 연결, 기존 계정/두 기기 복원, 지도·관제·적재의 부드러운 시각 연출. 사용자 입력을 새 자동 기능 때문에 다시 요구하지 않는다.
6. **최종 실게임 검증:** 추적 켠 채 연속 수락/공유 같은 유형 계약/일부 적재·배송·포기/재접속/해상도와 OCR/게임 동시 CPU·GPU·FPS/실제 계정 동기화.

파트너 대사는 `integration/log/partner-voice.mjs`에서 선택별로 관리한다. 대사만을 위해 기존 `voice.mjs`의 구 번역 모듈을 새 화면에 가져오지 않는다. 상자 구성은 같은 실행 계약에 한해 계정별 로컬에 저장하며 Firebase나 로그 원문 저장과 분리한다.

### 2026-11-04 운송 중 적재 상태

- 사용자 확인 적재 위치·배송 상태를 계정별 로컬에 저장하고 새 로그의 실행 계약/정의/빌드/화물 바인딩과 대조한다. 공개 정보·사용자 확인을 게임의 실시간 상자 텔레메트리라고 부르지 않는다.
- 새 계약은 고정된 화물을 피해 배치. 누락된 계약의 실린 화물도 공간을 유지. 배송한 실물 상자만 제거하고 해당 배송지 방문을 줄이며 전체 실물 적재 시 픽업을 생략한다. 영역 사용만으로 완료하지 않는다.
- 실제 완료·보상·계정 기록은 변경하지 않으며 출발지는 사용자가 확인한 작업 거점이다. 저장한 상태가 현재 실제 상태와 다르면 직접 확인해야 한다.
