# 안내데스크 대화형 가이드와 분리된 운송 연습

2026-11-16 · 기능 Codex · 로컬 구현 / 미배포

## 사용자 확정과 현재 범위

- 기존 라운지 투어처럼 큰 인물과 하단 대화창, 이전/다음으로 진행한다. 작은 전신 아이콘과 팝업 안 연습 대시보드 형태는 사용자 반려. 최신 화면은 장면 중심으로 수정하고 기존 라운지 투어의 승인 face/frame 자산을 재사용한다. 새 패널 그림 승인으로 취급하지 않는다.
- 예시 계약은 사용자가 확인한 **Hull B / 오리슨 출발 / 스탠턴 → 파이로 / 6계약 363 SCU**이다. 원본은 비공개 첨부에 남기며 제품에 복사하지 않는다.
- 근거: `tests/route-optimization.test.mjs`와 `docs/WORKLOG-2026-10-30.md`의 확인된 운송 장소·수량. 임의의 균등 분할을 하지 않고, 픽업별 수량이 미확정인 일곱 번째 계약은 제외한다. 실제 인스턴스 ID·보상·개인정보를 옮기지 않는다. 품목은 연습 화물로 표시하고, 상자 배치는 현재 엔진의 계산 결과이며 원본의 실측 상자 구성을 재현한다고 주장하지 않는다.
- 이동 안내: 사이드바는 즉시 이동, 공간의 장소/표식 선택은 연결된 기존 연출. 모바일은 공간 메뉴. 전체 가이드 첫 단계와 서비스센터 이용안내에 설명한다.
- 순서: 아카데미 소개 → 무역센터 소개 → 라운지 투어 → 확정 셔틀 탑승 영상 → 관제센터 소개 → 첫 운송 연습. 미완성 이륙/착륙 영상이나 음성을 새로 붙이지 않는다.

## 버튼 연결

| 안내데스크 버튼 | 동작 |
| --- | --- |
| 첫 운송 시작 | 분리된 예시 연습: 소개 → Hull B/파트너 → 예시 계약 불러오기/선택 → Worker 경로 계산/지도·적재 → 시작·작업·점프·되돌리기 → 실제 미션 화면 |
| 운송 절차 안내 | 준비·로그/OCR/직접입력·선택/계산·운항/변경의 대화형 설명 → 기존 이용안내 또는 연습 |
| 함선·화물 정보 | 두 주제 설명과 실제 아카이브 ships/cargo 직접 연결 |
| 처음이에요. 안내해 주세요. | 사업부 소개와 시설별 설명 → 기존 라운지 투어 → 셔틀 → 관제 소개 |
| 운송 준비부터 시작할게요. | 기존 미션 화면으로 빠르게 이동 |
| 라운지로 돌아가기 | 기존 승인 복귀 영상/동작 유지 |

기존 별도 「라운지 투어」 버튼은 기존 단독 투어로 유지한다. 전체 둘러보기에서 시작한 투어만 게이트 이후 관제센터 안내를 연결한다. 동작 줄이기 설정에서는 탑승 연출을 건너뛰고 소개로 이어진다. 종료/Esc는 실제 운항을 바꾸지 않으며, 실제 운송으로 넘어갈 때 연습 계약을 복사하지 않는다.

## 시설 확장 연결

- `division-facilities.ts`: 시설 ID·이름·요약·설명·destination·tour가 공통 등록 데이터. 무역센터와 아카데미의 사이드바 문구도 이 데이터에서 읽는다.
- `divisionTourOrder`: 지상 아카데미 → 무역센터 → 라운지 → 궤도 관제센터 순서. 지상 안내 후 기존 라운지 투어/셔틀 연결, 궤도 안내는 별도 단계다.
- 시설이 완성되면 실제 화면을 `SpaceScreen`/라우터에 등록하고 해당 시설의 `destination`과 `state`를 갱신한다. 사업부 클릭 영역·사이드바는 같은 목적지를 사용한다. 새 화면이 없는 동안은 미구현 안내를 유지한다.
- 시설의 `tour`에 `{title:[ko,en],body:[ko,en]}` 단계들을 등록하면 전체 둘러보기의 해당 위치에 자동 삽입된다. 아직 등록하지 않은 시설은 짧은 기존 소개 한 단계다. 페이지의 목적지 버튼도 연결된 실제 화면을 연다. 향후 시설 전용 이동 영상/인터랙션은 그 시설 구현 때 별도로 연결/검증해야 한다.
- `guide-journey-content.ts`: 주제별 대사. `GuideJourney.tsx`: 공통 대화/키보드/단계 UI와 연습 화면. 기존 안내데스크 DOM/버튼 자산을 유지한 채 controller의 `onGuide` 콜백으로 연결한다.

## 연습의 데이터 경계

`guide-practice.ts`는 매번 독립적인 계약/Draft를 만든다. `GuideJourney`는 React 메모리 상태와 전용 Worker만 사용하고 `useFlight`의 commit/change/progress, 로그 수신, 계정/히스토리 저장을 호출하지 않는다. 경로 계산은 기존 `flight.worker.mjs`, 진행은 순수 `blankRun/startRun/completeStep/undoStep`을 재사용한다. 종료/언마운트 시 Worker와 3D 화면을 정리한다. 계산 결과가 오기 전에는 다음 단계로 진행할 수 없다. 연습의 저장/재개는 제공하지 않는다.

항해사는 실제 Hull B 그리드의 예상 적재와 지도를 함께 표시하고, 오퍼레이터는 적재 컴포넌트를 마운트하지 않는다. 실제 로그 자동 수신이나 게임 속 화물 이동을 이 연습으로 검증했다고 주장하지 않는다.

## 다른 둘러보기의 확대·강조 통일 (2026-11-16 추가)

- `GuideScene`과 `guide-scene-camera.ts`가 승인 사진, 분리 인물, 시설 윤곽 강조를 렌더링한다. 페이지별 `GuideShot`으로 이동·확대·대상을 지정한다. 다음/이전 시 약 1.9초간 현재 카메라 위치에서 새 대상으로 이동한다.
- 아카데미 → 무역센터 → 라운지 외관을 각각 확대하고 주변을 어둡게 만든다. 관제센터는 파트너 소개 → 왼쪽 미션 콘솔 → 중앙 지도 → 오른쪽 관제 콘솔 순서다. 미구현 시설 내부는 임의로 만들지 않았다.
- 기존 라운지 투어의 Three.js 투영 장면/승인 영상은 그대로다. 새 단계는 사진 기반 이동·확대와 별도 인물을 조합한 세미 2.5D 표현이며, 실제 3D 건물 모델이나 새 보행 영상은 아니다.
- 미래 시설의 `tour[].shot`에 장면·초점·확대율·대상·승인된 근접 배경 경로를 등록할 수 있다. 운항 저장 구조와 분리했다.
- 카메라는 원본 경계를 넘지 않으며 창 크기 변경, 백그라운드 전환, OS 동작 줄이기 및 앱의 이동 연출 끄기에서는 즉시 최종 구도로 간다. RAF는 전환 중에만 실행하고 해제 시 정리한다. 추가 WebGL 컨텍스트를 만들지 않는다.
- 안내데스크에서는 원래 사이드바를 숨겼으나, 대화형 둘러보기 중에는 고정 사이드바를 다시 표시한다. 새 에셋 후보는 `asset-review/`에만 보관하며 아직 적용하지 않았다.
- 검증: 타입 검사/생산 빌드 통과. 실제 앱에서 시설 6곳의 카메라 이동/강조, 고정 메뉴, 기존 라운지 투어에서 관제/연습 연결, OS/앱 연출 끄기, 모바일 ko/en/mix 및 가로 넘침 없음 확인 통과(`camera-review/report.json`). 관제 배경은 기존 실행 화면과 같은 빈 좌석 패치를 함께 적용했다. 신규 커밋·푸시·배포 없음.

## 글씨 가독성 보강 — 라운지 투어 포함

- 대사: 데스크톱 22–28px / 모바일 18px, 행간 1.6–1.65. 버튼 16px, 화자/단계 14–15px. 승인한 Barlow Medium/SUIT와 프레임은 보존하고 글자 뒤 배경을 어둡게 했다.
- 라운지와 새 안내에 동일 `tour-readability.css` 적용. ResizeObserver로 대화창 높이를 측정해 연습 본문이 밑으로 가려지지 않도록 확보한다. 짧은 가로 화면/긴 대사는 글씨를 줄이지 않고 내부에서 읽을 수 있게 한다.
- `scripts/check-tour-readability-browser.mjs`: 한/영 각 6개 화면 크기(1920×1080, 2560×1440, 1366×768, 390×844, 360×640, 844×390), 라운지 4단계, 버튼 노출/글자 크기/가로 넘침, 모바일 예시 계약 영역 보존 확인 통과. `readability-review/`에 실제 캡처와 수치 저장. 타입 검사/생산 빌드 통과.
- 이 검증은 가독성과 배치 확인이며 운항 엔진 전체 회귀 검증을 재실행한 것은 아니다. 새 이미지 후보의 승인이 아니며 배포 없음.
