## 충돌 해결

지원 패치 `docs/cinematics/lounge-tour-20261114/integration/pr31-tour-hooks.patch`는 최신 기능 파일의 첫 hunk부터 적용 검사에 실패했다. 파일 전체 교체 대신 자동 병합 후 5개 충돌을 대조했다.

1. hash 변경: 기존 Archive 펄스 정리/복귀 방향을 포함한 도착 객체와 투어 기대 목적지를 모두 보존.
2. Escape effect: 기존 motion/sound/volume 및 tour 의존성 유지.
3. 일반 이동: 투어 종료 후 기존 Archive 하위 메뉴 분기와 beginTravel을 그대로 실행.
4. href: 기존 `view` 인자를 유지하고 투어 시작/이동/종료만 추가.
5. 하단 overlay: 기존 Archive 점등/복귀 방향 ConsoleArrival과 투어를 함께 유지.

현재 상단바·한글 공간 버튼·FLIGHT CONSOLE·파트너 선택·서비스센터 내부 화면·아카이브 하위 메뉴·운항 기능은 보존했다. 서비스센터의 non-modal inline dialog가 투어 Escape를 막지 않도록 구분했다. 내부 계정 화면을 열 때 첫 입력칸으로 모바일 화면이 강제 스크롤되지 않도록 자동 포커스는 기존 modal에서만 수행한다.

## 배포 범위

라운지 투어와 이전에 보존된 계약 입력/수신함 연속성, 변경 확인/보류 후처리, 유효 적재 용량, 개인 장소, 출처 대조, 계정별 운항 보호, 서비스센터 내부 화면을 포함한다. UI/콘솔 코드를 이전 연출 버전으로 되돌리지 않았다. 릴리스 기록은 beta 2.8.0.

- 제품에는 Vite가 묶은 투어 컴포넌트와 사용 PNG만 포함. 독립 검토용 HTML/iframe/서버 및 docs 폴더는 Pages 조립 대상이 아니다.
- 기존 첫 운송/일반 메뉴 이동 유지. 투어는 시네마→아카이브→서비스센터→게이트 순서이며 다음 버튼을 기다린다.
- 게이트 이후 셔틀 전용 연결, 확정 음성/립싱크/자연 보행, 투어 저장·재개는 미구현 후속.
- **Firebase 운영 규칙은 미게시.** 인증이 제공되지 않았고 Pages는 Firestore 규칙을 배포하지 않는다. 기존 규칙은 새 트랜잭션의 형식과 호환되지만 구버전 강제 차단까지 운영 반영됐다고 주장하지 않는다. 새 콘솔 기기 간 클라우드 이어하기도 별도 후속이다.

## 게시

검증 커밋을 integration 브랜치·공통 개발 인계·main에 강제 갱신 없이 같은 SHA로 푸시한다. main 푸시의 GitHub Pages 작업 성공과 실제 `version.json`/진입 HTML/투어 해시 자산을 확인한 뒤 사용자에게 통합 SHA와 URL을 보고한다. 이 문서의 미래형 절차만으로 배포 성공을 주장하지 않는다.
