# 재구축 시험판: 완료 범위와 다음 검증

이 브랜치는 **완성판이 아닙니다.** 게임에서 수락한 계약의 기록을 자동으로 관측하는 시험 앱과, 기존 지도·적재 화면을 개선한 코드가 함께 있습니다. 두 화면을 실제 화물 명세로 연결하는 작업은 아직 완료되지 않았습니다. `main`과 운영 사이트에는 반영하지 않습니다.

## 현재 사용할 수 있는 것

| 기능 | 현재 상태 |
|---|---|

| 파티 공유·참여·이탈 | 관측 근거와 본인 식별 여부를 구분합니다. 공유 알림만으로 수락을 확정하지 않습니다. |
| 실제 화물·상자 자동 확정 | **미완료.** 일부 수량 알림만으로 전체 명세를 확정하지 않으며, 미확인 계약의 계산을 차단합니다. |

| 3D 자원 정리 | 꺼진 블룸의 10개 보조 버퍼를 만들지 않습니다. 기존 색조 처리를 위한 1개 버퍼는 유지합니다. 공용 상자 테두리는 재사용하며 화면 종료 시 관찰자·입력·GPU 자원을 정리합니다. |
| 로그인·동기화·파트너·기록 | 기존 구현과 데이터는 유지합니다. 새 로그 앱의 계정·진행 정보 이전은 아직 연결하지 않았습니다. |
| 영어/한영/한글과 번역 출처 이전 | 미구현입니다. 사용 방식과 출처 표시 확인이 먼저 필요합니다. |
| 전체 화면·적재 3D의 전면 디자인 | 진행 전입니다. 이번 시점 전환·렌더링 개선만으로 전면 개편 완료라고 부르지 않습니다. |

## 게임을 켜지 않고 먼저 진행한 이유

### 완성본 설치·Node 호환 요구사항 (2026-11-03 사용자 요청)

- 사용자에게 Node 별도 설치를 요구하지 않도록 실행 환경을 포함하는 배포 방식을 우선 검토합니다. 아직 패키징을 구현한 상태는 아닙니다.
- 외부 Node를 사용하는 방식은 최신 버전과 지원 가능한 이전 버전을 함께 검사합니다. 특정 메이저만 허용하는 조건을 넣지 않고, 실행에 필요한 최소 버전과 실제 검사한 버전을 구분해 안내합니다.
- Node가 없거나 최소 버전보다 오래되면 발견한 버전(발견된 경우), 필요한 버전, [공식 설치 링크](https://nodejs.org/en/download)를 제공합니다. 이미 호환되는 Node가 설치되어 있으면 제거·다운그레이드를 요구하지 않습니다.
- 현재 시험판의 최소 버전은 22입니다. CI에서 Windows/Ubuntu의 Node 22·24·26.13.0을 검사하며, 다른 모든 과거·미래 버전의 동작을 검증한 것으로 간주하지 않습니다.

### 실게임 자료와 독립적인 작업

렌더링 수명 관리, 프레임 제한, 카메라 전환은 실게임의 미션 내용과 독립적이므로 먼저 구현하고 검사할 수 있습니다. 반면 계약마다 정확한 화물 종류·수량·픽업/배송 할당·상자 크기와 개수를 채우려면 실제 관측 자료와 일치하는 근거가 필요합니다. 공개 미션 유형의 최대 수량/최대 상자 크기를 그 계약의 실제 구성으로 바꾸어 넣지 않습니다.

추가 로그를 받는다고 반드시 누락된 값이 나오는 것은 아닙니다. 로그에 없으면 허용된 다른 자료나 사용자가 확인한 근거가 필요하며, 그전에는 미확인으로 유지합니다. 계약 전체 목록이나 현재 실제 적재 좌표를 알고 있다고 표시하지 않습니다.

## 시험 방법

**게임 로그 연결:** [LOG-LINK-TESTING.md](LOG-LINK-TESTING.md)의 `start-log-link.cmd`를 사용합니다. 이 실행기는 로그 화면만 제공하며 지도·적재 화면을 함께 실행하지 않습니다.

**지도·적재 화면:** 시험 브랜치 폴더에서 Node.js 22로 `npm start`를 실행하고 `http://127.0.0.1:4173`을 엽니다. 첫 준비 시 Three.js와 공개 지도 좌표를 내려받을 수 있습니다. 기존 앱 화면의 예시 미션으로 시점 버튼·드래그·그리드 선택을 확인할 수 있습니다. 예시는 실게임 자동 연동 결과가 아닙니다. 기존 운영 사이트와 localhost의 브라우저 저장소는 별개입니다.

1. 적재 화면의 `위`, `좌현`, `우현`, `전체`를 눌러 전환과 드래그 중단을 확인해 주세요.
2. 그리드 선택 모드에서 구역 선택, 실제 적재 중인 구역 차단, 화면 확대/축소를 확인해 주세요.
3. 지도 이동·확대와 경로 표시, 탭/관제 화면 전환 후 복귀를 확인해 주세요.
4. 게임과 같이 실행했을 때 프레임 저하가 있다면 함선, 상자 수, 지도 화질, 브라우저, 화면 크기와 함께 알려 주세요.

## 이번 코드 검증

- Node.js 22 전체 테스트 **168개 통과**. 로그 35개 및 렌더링 예약/가시성/해제/컨텍스트 복구/감쇠 7개를 Windows·Ubuntu CI 대상으로 구성했습니다.
- Chromium의 합성 Hull B 배치에서 정지 적재 화면의 추가 렌더링 0회, 숨긴 두 화면의 추가 렌더링 0회, 위 시점 전환, 키보드 그리드 토글, 390px 가로 넘침 없음, 중복 종료 후 남은 캔버스 0개를 확인했습니다.
- 같은 배치를 12번 갱신했을 때 GPU geometry 144개/texture 7개로 유지됐습니다. 이 숫자는 해당 합성 배치의 검사 결과이며 모든 함선의 자원 사용량을 뜻하지 않습니다.
- Cloud 소프트웨어 렌더러이므로 화면 품질·상태 전환을 확인한 것이며 실제 PC의 FPS 측정이 아닙니다. 최초 검사에서 외부 글꼴 인증서 오류가 있어, 최종 검사는 외부 글꼴 요청을 빈 스타일로 대체한 뒤 앱/셰이더 오류 없이 완료했습니다. TLS 검증을 끄지 않았습니다.
- **실게임 미확인:** 계약 명세 완전성, 실제 화물 상자, 파티 수락 전체 흐름, Windows 게임 실행 중 파일 잠금, 게임 FPS 영향, EAC 환경에서의 동작. 정책 허용 여부나 제재 가능성을 자동 테스트가 보증하지 않습니다.

다음 단계는 집에서 얻은 수락/공유/완료 관측과 실제 계약 내용을 대조하고, 확인 가능한 필드부터 명세 검증 계층으로 연결하는 것입니다. 추정으로 계산 차단을 해제하지 않습니다.
