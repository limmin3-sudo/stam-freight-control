# 재구축 시험판: 완료 범위와 다음 검증

이 문서는 `rebuild/log-evidence-foundation`의 시험 앱 기준입니다. 운영 사이트와 새 앱의 전면 개편은 별개이며, 완성판이 아닙니다.

## 현재 가능한 흐름

1. `start-log-link.cmd`로 사용자가 고른 Game.log를 읽습니다. 게임 파일을 수정하지 않습니다.
2. **운송 계약**에서 근거가 충분한 수락·본인 참여 기록은 자동 선택합니다. 종료·이탈과 사용자의 수동 해제를 존중하며, 같은 유형도 실행 계약별 상자 소유권을 유지합니다. 과거 수락 기록이 현재 진행 중임을 보장하지는 않습니다.
3. **운송 관제 열기**를 열고 함선·출발지·파트너를 선택합니다. New Babbage 등 계약 밖의 공개 지점도 출발지로 선택할 수 있습니다.
4. 확인된 대형 유형의 원래 명세는 입력 없이 자동 사용합니다. 미확인 배분은 보류 이유를 표시합니다. 수동 입력은 접힌 선택 기능이며 자동 연동을 대신하는 필수 단계가 아닙니다.
5. 처음에는 전체 화물 3D를 표시하고 경로는 1번 출발지부터 이동·적재·하역을 안내합니다. 설정·선택한 계약 근거가 바뀌면 350ms 후 자동 재계산하며 이전 작업을 폐기합니다. 3D를 닫으면 예약 계산과 렌더러를 해제합니다.
6. 지도·적재를 나란히 보거나 하나만 표시할 수 있습니다. 방문 목록과 이전/다음 단계가 지도 구간 및 적재 배치를 함께 바꿉니다. 점프 단계는 앞 단계의 화물을 유지하며 도착지 하역을 미리 적용하지 않습니다. 지도 검색 후 「선택 지점에서 출발」을 누르면 출발지가 변경됩니다.

## 구현 범위

| 기능 | 상태 |
|---|---|
| 로그 증분 감시·실행 계약 구분 | 구현. 파티 공유 알림과 본인 참여 근거를 구분합니다. |
| 여러 계약의 경로·적재 미리보기 | 구현. 한 번에 계약 12개, 주문 64개, 미리보기 상자 2,048개까지이며 초과분을 누락시키지 않고 안내합니다. 계산 Worker는 8초를 넘으면 종료합니다. |
| 파트너별 탐색 | 수석 항해사 묶음 탐색과 오퍼레이터 완료 우선·짧은 경유 탐색을 각각 연결했습니다. 브로커 운송/무역 계산은 없습니다. |
| 출발지·그리드 설정 | 계약과 무관한 출발지를 선택하고, 함선별 그리드를 제외할 수 있습니다. 새 계획 설정은 전용 키로 저장하며 로그인하면 기존 계정과 동기화합니다. 로그 계약/초안은 저장 대상이 아닙니다. |
| 로그 갱신 시 입력 보존 | 선택한 계약에 변화가 없으면 열린 3D·계산을 유지합니다. 근거가 바뀌면 입력은 남기되 결과와 해당 계약의 확인 표시를 무효화합니다. |
| 새로고침 | 같은 로컬 주소에서는 함선·제외 그리드·출발지·파트너를 복원합니다. 계약 선택과 주문 입력은 메모리에만 둡니다. 실행기를 재시작해 포트가 바뀌면 다른 브라우저 저장소이므로 게스트 설정의 자동 이전은 아직 되지 않습니다. 계정에 저장했다면 다시 로그인해 불러올 수 있도록 연결했으며 실제 계정 검증은 남아 있습니다. |
| 대형 유형 정확한 원래 조합 | 관측 빌드의 검증된 유형 1개: 탄약16×4, 수소16×4, 의약용품2×20. 목적지별 원래 명세까지 연결합니다. 실제 현재 인벤토리가 아닙니다. |
| 모든 운송 유형의 실제 상자 구성 | **미완료.** Or/특수 개체 등 미지원 주문은 보류합니다. 중형의 예상 조합을 실물 확인으로 바꾸지 않습니다. |
| 실제 적재·배송 진행 동기화 | **미연결.** 이번 화면은 원래 요구량을 계획합니다. 부분 배송량이나 현재 aboard를 추정하지 않습니다. |
| 기존 운항 재계산 보호 | 저장된 aboard 위치가 누락·충돌하거나 그리드가 꺼져 있으면 재계산을 멈춥니다. 다른 자리로 자동 재배치하거나 삭제된 진행 계약의 화물을 버리지 않습니다. |
| 적재 3D | 기존 카메라·유휴 중지·자원 해제를 재사용합니다. 전체 화물과 단계 배치는 가능한 경우 같은 결과를 사용합니다. 전면 디자인 재설계 완료는 아닙니다. |
| 지도·파트너 초상화 | 새 관제 화면에 연결했습니다. 기존 천체/궤도/부드러운 카메라와 두 파트너 사진을 재사용하며 새 지도는 영문 지명으로 표시합니다. 사진을 누르면 파트너 설정을 엽니다. |
| 지도 렌더링·화질 | 기본/상세 화질을 별도 설정으로 저장합니다. 새 지도는 카메라·경로 표시가 안정되면 렌더를 멈추고, 숨긴 지도도 그리지 않습니다. 라벨 텍스처와 공유 구체의 해제를 보완했습니다. |
| 로그인·동기화·기록 | 새 계정 카드와 기존 기록/통계/삭제 연결. 기존 키 보존, 새 계획 설정 allowlist 동기화. 실패·충돌 시 정지하며 원자적 저장 비교. 실제 Firebase/Google·다른 기기 검증은 남았습니다. |
| 언어·번역 이전 | 기존 패치 기반 데이터 제거와 새 SC-KoChat 사용 방식 확인·연결이 남아 있습니다. 새 번역 파일을 무단 복사하지 않았습니다. |

## 검증과 한계

Node22/26 및 Windows·Ubuntu CI 결과는 최신 PROJECT_STATUS.md와 브랜치 Actions를 확인해 주세요. Chromium에서 제공된 실제 로그 재생, New Babbage 출발, 대형 28상자/168 SCU, 수동 확인한 예상 중형을 포함한 218 SCU 계획, 무관한 로그 갱신 시 화면 유지, 해당 근거 변경 시 확인 해제, 그리드·설정 새로고침 복원, 390px 레이아웃을 검사했습니다. 추가 이벤트는 원본 로그가 아닌 검사 복사본에 합성했습니다.

실게임을 동시에 실행한 Windows GPU/게임 FPS, 모든 게임 빌드와 모든 미션, 자동 실물 인벤토리 관측은 **미확인**입니다. 정지/숨김 렌더 중지와 Worker 제한이 실제 PC의 무부하를 보장하지는 않습니다.
