# 화물 엘리베이터로 상자 구성을 보정하는 방안

2026-11-03 사용자 제안: 수락 시 최대 상자 크기 기반의 예상 배치를 만들고, 엘리베이터에서 실제 구성을 얻으면 다시 계산한다. **예상임을 명시하는 미리보기**를 허용하는 요청이며, 추정값을 실제값으로 저장하거나 다른 계약의 실물 확인을 빌려 쓰라는 뜻은 아니다.

## 현재 자료에서 확인한 것

사용자가 제공한 로그 34개를 다시 검색했다. 아래 수치는 중복 파일/반복 이벤트를 제거한 실제 작업 횟수가 아니라 **원문 줄 수**다. 원문·계정 정보·실행 계약 ID는 커밋하지 않는다.

| 기록 | 관측 | 얻을 수 있는 범위 |
|---|---:|---|
| `CSCLoadingPlatformManager::OnLoadingPlatformStateChanged` | 6,047줄 | OpenIdle / ClosedIdle / 상승·하강 등 플랫폼 상태. 내 플랫폼·내 화물이라는 보장은 없음 |
| `CEntityComponentFreightElevatorUIProvider::FillUnstowRequest` | 144줄 | 반출 요청 관련 106줄과 EntityId 없음 오류 38줄. 요청/위치/Entities/ItemBank 필드. 품목·SCU 크기별 명세가 아님 |
| `SMarkerHandler_Hauling::OnItemRegistered` | 63줄 | 작은 배송 물품·특수 물품의 클래스, 아이템 ID, 계약/목표 ID 연결. 일반 SCU 상자 목록으로 사용할 수 없음 |
| `UnstowPendingEntities` | 179줄 | 생성된 아이템 클래스/ID가 나오는 예가 있으나 장비·음료 등 개인 인벤토리도 섞임. 이를 모두 화물 엘리베이터 반출로 해석할 수 없음 |
| `SBindings_InventoryView::TryAddItemPlatformImpl` | 3줄 | BoxesCantFit 실패. 아이템·인벤토리 식별자만으로 크기/개수를 확정할 수 없음 |
| `CargoSystemUtilities::FindBoxSize` | 11줄 | 냉동포드의 resource container 없음 오류. 실제 크기별 명세가 아님 |

주변 `Query Inventory` / `InventoryManagement` 기록도 조회 대상·성공·페이지 범위 중심이다. `Entities`와 조회 개수를 해당 계약의 실제 상자 수로 치환하지 않는다. 로그에서 일반 운송의 품목·크기별 개수·계약 연결이 모두 갖춰진 엘리베이터 목록은 아직 확인하지 못했다. **모든 버전/모든 상황에서 불가능하다는 결론은 아니다.**

## 설계에 반영할 구분

1. **검증된 고정 조합:** 해당 유형·빌드의 확인된 구성을 사용한다. 다시 최대 크기 분해로 바꾸지 않는다.
2. **예상 배치:** 품목/총량/배분이 확인됐고 크기별 개수만 모르는 경우에 한해 품목별 허용 상한을 적용할 수 있다. 함선 최대 상자나 미션 전체 최고 상한을 모든 품목에 적용하지 않는다. 눈에 띄는 예상 표기, 실제 구성과 별도 저장, 수입/완료/실제 적재 자동 갱신 금지. 미확인 총량·배송지는 생성하지 않는다.
3. **실제 구성 보정:** 품목·크기·수량 및 실행 계약을 연결할 근거가 확보되면 원자적으로 교체한다. 이벤트 재생/중복/부분 반출을 구분하고 원래 계약 전체와 이번 반출분을 혼동하지 않는다. 이미 함선에 실은 상자는 현재 위치와 소유권을 유지하고 남은 배치만 다시 계산한다.

예상 배치 UI 및 엘리베이터 파서는 **이번 변경에 아직 구현하지 않았다.** 현재 구현은 검증된 대형의 원래 명세 연결과 기존 적재 엔진 입력 어댑터까지다.

## 다음에 필요한 최소 자료

다음 실제 픽업 때 다른 품목을 섞지 않고, 구성이 이미 확인된 한 품목(예: 2 SCU 의약용품)만 엘리베이터로 올린 직후 Game.log를 보존한다. 조작 시각·거점·실제로 요청한 크기와 개수를 함께 알려주면 요청 전후와 아이템 생성/계약 연결을 대조할 수 있다. 화면을 반복 촬영하거나 게임 설정/로그 수준을 바꾸거나 명령을 자동 입력할 필요는 없다. 새 설치도 필요 없다.

이 시험에서도 크기별 명세가 안 나오면 일반 SCU의 정확한 자동 보정 출처로 로그 엘리베이터 이벤트를 사용할 수 있다고 주장하지 않는다.
