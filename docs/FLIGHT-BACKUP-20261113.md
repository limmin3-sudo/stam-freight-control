# 전체 운항 백업·복원 — 2026-11-13 검토본

브랜치 `feature/graphics-functional-audit-20261113`, 공개 기준 beta 2.7.0 `fa647d0a6077c200897eb1a43e4b4bb5f2242eec`. 기능 보존 `342a5fa`에 커밋했고 현재 `integration/freight-division-20261113`에서 연출과 통합했다. 아직 미배포이며 공개 버전의 완료로 보지 않는다.

## 사용 방법

1. 미션 콘솔 아래 또는 관제 콘솔의 운항 진행 아래에서 **운항 백업 · 복원**을 펼친다.
2. **운항 백업 저장**으로 JSON 파일을 받는다. 운항 중에도 가능하다.
3. **운항 백업 파일 선택**에서 파일을 고른다. 계약 수·파트너·함선·진행·현재 위치·선적 상자를 확인하고 **이 백업으로 복원**을 누른다. 취소/Esc는 현재 운항을 바꾸지 않는다.
4. 복원한 진행 중 운항은 일시정지 상태다. 관제 콘솔에서 확인 후 타이머를 재개한다.
5. **복원 전 운항 확인**으로 바로 전 운항을 미리 보고 되돌릴 수 있다. 복원마다 바로 직전 사본 하나를 교체한다. 장기 보관에는 파일 다운로드를 사용한다.

기존 **계약 백업 · 불러오기**는 목록에 계약을 추가하는 기능으로 그대로 유지한다. 전체 운항 복원은 목록 추가와 달리 현재 세션을 교체한다.

## 보존/제외 범위

- 계약과 보상·수량 근거·예약 총량, 선택한 파트너와 함선/사용자 정의 그리드, 계산된 경로와 경유 순서, 현재 위치/점프/픽업·배송 진행, 상자 소유권과 셀 좌표, 작업 되돌리기 이력과 운항 로그를 보존한다.
- 경로를 다시 계산하거나 상자를 재배치하지 않는다. 오퍼레이터는 경로 전용으로 복원하고 적재 3D를 마운트하지 않는다.
- 신규 파일은 `format: stam-flight-backup`, `version: 1`, `exportedAt`, `session` 구조다. 기존 `{version:1,draft,plan,run}` 원시 세션 파일도 지원한다. 계약 배열 파일은 전체 운항 복원 대상으로 받지 않는다.
- 신규 내보내기는 다운로드 시점의 경과 시간을 담고 타이머를 정지시킨다. 이전 원시 파일은 내보낸 시점을 알 수 없으므로 저장된 `elapsed`와 마지막 작업 기록 시각 중 큰 값을 유지한다. 파일 보관 시간을 추측하지 않으면서 완료된 작업보다 시간이 뒤로 가지 않게 한다. 파일 보관 중 경과 시간을 운항 시간에 더하지 않는다. 되돌리기도 자동으로 타이머를 재개하지 않는다.
- 로그 원본/자동 수신 핸들, 계정/운송 완료 기록, 전역 지도·음향 설정은 이 파일에 포함하지 않는다. 실제 다른 기기·Windows 파일 선택기 검수는 별도다.

## 실패 시 보존

- 형식/버전, 주요 필드, 수량·좌표, 상자 중복/겹침/그리드 범위, 계약 소유권, 경유·점프 인덱스, 선적 상태/이력과 경로의 일치를 확인한다. 20 MB 이하, 중첩/항목 수에 상한을 둔다. 미지의 부가 근거 필드는 삭제하지 않는다.
- 미리보기 이후 진행이 바뀌거나 다른 탭이 세션을 저장했으면 확인을 다시 요청한다. 계산 중에는 복원을 시작하지 않는다.
- 직전 사본을 `stam.control-room.flight.previous.v1`에 저장하고 새 세션 저장이 성공한 뒤에만 화면 상태를 교체한다. 어느 쓰기 단계에서든 실패하면 현재 화면과 세션 키를 유지한다.
- 기존 로컬 저장이 손상되어 편집이 잠긴 경우에도 검증된 파일로 명시 복원할 수 있다. 손상 원문은 직전 사본 키에 보존한다. 손상 사본 자체는 복원 검증을 통과하지 않는다.
