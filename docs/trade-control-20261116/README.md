# 무역 관제 기록 연결 — 2026-11-16, 미배포

사용자 “다음”에 따라 교역 계획실의 검토 후보를 무역 관제에 인계하고, 게임에서 확인한 실제 매입·출발·도착·판매·비용을 기록하는 흐름을 구현했다. 기존 기능/연출 미커밋 작업을 보존했으며 커밋·푸시·배포는 하지 않았다.

## 사용 흐름

1. 계획실에서 함선·출발지·자본과 위험/위법 조건을 선택해 후보를 검토한다. 기본 예비금은 이전 사용자 결정인 10%다.
2. ‘무역 관제로 인계’를 누르면 예상값과 출처 날짜를 사본으로 보관한다. 아직 매입·화물·매출을 생성하지 않는다. 이미 진행 중인 교역이 있으면 덮어쓰지 않고 기존 관제로 안내한다.
3. 실제 매입 수량과 **단가가 아닌 합계 결제액**을 입력하고 확인창에서 기록한다. 여러 번 나누어 매입할 수 있다. 계획과 다른 실제 금액도 기록하며, 기록 기준 잔액이 예비금 아래로 내려가면 차이를 표시한다.
4. ‘출발 기록’ → ‘도착 기록’ 후 실제 판매 수량과 합계 판매액을 확인해 기록한다. 일부만 판매한 수량은 남는다. 별도 실제 비용은 사유와 함께 기록한다.
5. 실제 화물 손실도 수량·사유를 명시해 확인한 경우만 기록한다. 판매 매출을 만들지 않고 해당 수량의 원가를 손실에 반영한다.
6. 기록상 화물이 모두 없어지면 교역을 마감한다. 한 번도 매입하지 않은 계획은 취소할 수 있다. 마감·취소한 기록도 보관한다.
7. 잘못 입력한 내용은 마지막 기록부터 되돌린다. 원본을 삭제하지 않고 되돌림 날짜와 내역을 남긴다. 마감도 되돌릴 수 있지만 다른 교역이 이미 진행 중이면 두 개를 동시에 진행 상태로 만들지 않는다.

## 계산·보존

- 합계 금액은 정수 센트로 처리한다. 매입 원가는 현재 재고의 평균 원가로 배분하고, 마지막 판매/손실이 나머지 센트를 정확히 해소한다. 큰 값의 비례 배분은 BigInt로 계산한다.
- 실현 손익 = 실제 매출 − 판매/손실 화물의 매입 원가 − 기록한 비용. 아직 선내에 남은 화물 원가는 따로 표시한다.
- 기록 기준 잔액 = 최초 자본 − 실제 매입 − 비용 + 실제 매출. 예상 비용을 실제 비용으로 자동 중복 차감하지 않는다. 수량/잔액은 해당 교역만 반영하고 운송 미션 화물·계정 총수입과 합치지 않는다.
- 계정 소유자별 `stam.trade-book.v1:<owner>` 한 키에 별도 저장한다. 실제 계정 동기화나 기존 운송 기록 저장 키는 수정하지 않는다. 현재 범위는 브라우저 저장이다.
- 저장 성공 후에만 화면에 반영한다. 저장 실패·손상 자료·다른 탭의 오래된 수정·계정 전환 시 기존 기록을 덮어쓰지 않는다. Web Locks로 같은 origin의 교역 쓰기를 직렬화하고 저장 원문을 다시 비교한다. 미지원 브라우저는 쓰기를 차단하고 읽기/백업을 유지한다.
- 다른 탭에서 기록이 바뀌면 최신 기록을 읽고 이전 확인창을 닫아 다시 검토하게 한다. 계정 확인 중/변경 시 이전 소유자의 화면 기록을 숨긴다.
- 백업은 동일 소유자의 빈 교역 기록에만 명시 확인 후 복원한다. 기존 기록을 덮어쓰거나 다른 계정으로 자동 채택하지 않는다. 복원은 형식·재생 가능한 이벤트·중복·수량/금액을 검증한다.
- 입력할 때마다 전체 장부를 재계산하지 않도록 저장 장부 기준 집계를 메모이제이션했다. 관제 모듈은 방문 시 지연 로드한다. 승인 유리 버튼, 기존 폰트와 금빛 강조를 재사용했다.

## 검증

- 타입 검사·생산 빌드 통과. 기존 초기 번들 크기 경고 유지.
- 앱 **123개**, 루트 **271개** 테스트 통과. 새 교역 테스트 12개는 인계/중복 진행, 부분 매입·판매, 실제 예비금 침범, 단계/수량 방어, 손실 원가, 큰 금액·잔여 센트, 되돌림, 마감 보존, 잘못된 백업, 계정 분리, 동시 수정·저장 실패, 손상 자료 보존을 다룬다.
- [브라우저 보고서](runtime-review/report.json): 실제 저장 UEX 후보 인계 후 합성 거래로 매입→비용→출발→도착→부분 판매→되돌리기→화물 손실→잔여 판매→마감까지 실행. 5 SCU/100 aUEC 매입, 4 SCU/180 aUEC 매출, 1 SCU 손실, 비용 9.25 aUEC의 최종 실현 손익 **70.75 aUEC**를 확인했다.
- 새로고침 복원, 확인창 Escape, 저장 용량 실패 시 원문 보존, 두 실제 브라우저 탭의 동시 변경, 별도 브라우저의 백업 복원, 복원 후 마감 되돌리기, 영어/390px 모바일 확인.
- 계정 경계는 합성 소유자 변경으로 기존 내용을 숨기고 guest 복원/새로고침 후 원문이 남는 것을 확인했다. **실제 Firebase 로그인이나 교역 클라우드 동기화 검증이 아니다.**
- 실제 예시 운송 계약을 넣은 운송·계정 저장 키가 교역 전후 동일한지 확인했다.
- 검수 중 인계 후 제목이 잘리는 문제를 발견해 로비 stage의 잔류 스크롤을 초기화하고 해당 콘텐츠 stage를 overflow:clip으로 바꿨다.

## 남은 범위

이 화면은 **수동 확인 거래 장부와 진행 관리**다. 게임 거래/이동을 자동 실행하지 않는다. 시세 변경이 이미 인계한 예상값이나 실제 거래 내역을 덮어쓰지 않는다. 실제 게임과 실거래는 미검증이다.

행성계 이동 순서와 두 거래소는 표시하지만, 거래소 좌표를 확정한 상세 지도·실제 상자별 적재 3D·게임 로그 기반 교역 자동 반영·교역 기록의 기기 간 클라우드 동기화는 아직 연결하지 않았다. 아카데미 교육/사례 및 새 통합 둘러보기·분리 튜토리얼도 후속이며 이번 기능 완료에 포함하지 않는다.
