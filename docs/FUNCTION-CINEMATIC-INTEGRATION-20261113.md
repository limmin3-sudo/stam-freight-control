## 공유 코드에서 함께 보존한 조건

- `SpaceExperience.tsx`: #28의 `{screen, returning, focus}` 도착 상태와 #31의 `view=missions`를 함께 전달한다. 복귀에는 점등음을 내지 않으며 일반 진입과 내부 아카이브 전환은 250ms 점등음이다.
- `ConsoleArrival`의 복귀 축소와 아카이브 본문 전용 전환을 구분한다. 고정 상단바/사이드바, 가이드 영상/일반 게이트/승인 셔틀 흐름을 유지한다.
- 서비스센터의 안내 중복 카드를 제거한 #29 결과를 유지한다. 계정 버튼은 새 인증을 만들지 않고 기존 singleton을 재사용한다.
- 상단 **STAM** / 작은 **FREIGHT DIVISION** 위계와 제목/메타/소개 문구를 유지한다. 공간 이름 FLIGHT CONSOLE / SPACEPORT LOUNGE / CONTROL CENTER는 연출 인계의 고정 영문 규칙을 따른다.
- 오퍼레이터는 적재 3D 없이 경로 전용, 항해사는 지도:적재 1.3:1 상시 배치와 현재 목적지/작업을 유지한다.
- 자료 정책은 SCMDB 우선 + 동일 정의 UUID의 누락만 Wiki 보완이다. 수주 로그/입력값과 목록의 최대값·보상을 혼동하지 않는다. 아카이브 탐색은 운항/계약 데이터를 수정하지 않는다.

## 통합 중 보완

아카이브 개요에 들어가기만 해도 네 자료 JSON을 미리 받던 처리를 제거했다. 실제 미션 자료 진입에서 기존 loader/cache를 사용한다. 내부 화면에 아직 없는 필드별 출처·서로 다른 값 비교는 기존 `operations-intel.html`로 연결해 접근을 보존했다. 기존 데이터나 검색 기능을 줄인 것이 아니다.

새 아카이브 하위 링크 때문에 기존 브라우저 검사의 부분 문자열 선택자가 두 메뉴를 가리켰다. 검사 선택자를 부모 공간 링크로 구체화했고 점등음 확인은 110ms에서 승인된 250ms로 변경했다. 전체 운항 백업이 추가되면서 기존 계약 파일 입력 선택자도 두 입력을 가리켜, 계약 백업 영역 안으로 범위를 지정했다. 실제 사용자 흐름의 검증 조건을 완화하지 않았다.

## 검증

최종 결과와 캡처는 [통합 검수 기록](function-review-20261113/integration/README.md)에 저장한다. 루트 238개 + 앱 58개 테스트 및 TypeScript/Vite 빌드 통과. 브라우저는 production preview `http://127.0.0.1:5188/`, 실제 개인 로그 Worker 재생은 dev server `http://127.0.0.1:5186/`에서 수행한다.

첫 아카이브 녹화 실행은 Playwright ffmpeg 경로 누락으로 페이지 실행 전 중단됐다. 시스템 ffmpeg를 지정한 재실행에서 통과했다. 첫 백업 검증은 summary 클릭에서 시간 초과했으며 코드 변경 없이 재실행해 전체 검증이 통과했다. OCR 첫 실행은 CDN 인증서 신뢰 오류로 중단됐다. 기존 `STAM_OCR_SYSTEM_FETCH=1` 검수 옵션으로 동일 공개 OCR 파일을 시스템 CA를 신뢰하는 curl로 가져와 실제 Tesseract를 재실행했고 통과했다. TLS 검증을 끄거나 인식 결과를 모의하지 않았다. 클라우드 Chromium은 소프트웨어 GPU이므로 이 결과를 실물 GPU의 프레임 성능 보장으로 해석하지 않는다.

## 바로 확인할 동선

1. `#/information?lang=ko` → 왼쪽 아카이브의 **미션 자료** → 검색/회사·수량·보상 필터/상세 → Esc로 개요 복귀. 브라우저 뒤로/앞으로와 새로고침에서도 하위 경로를 보존한다.
2. `#/mission?lang=ko` → 파트너 선택 → 예시 계약 선택 → 경로 계산 → 관제 콘솔. 항해사는 지도와 적재가 함께, 오퍼레이터는 적재 없이 표시되어야 한다.
3. 왼쪽 FLIGHT CONSOLE을 펼쳐 요약/현재 목적지를 확인한다. 운항 중 함선 변경은 준비 화면으로 이동하되 기존 잠금을 우회하지 않는다. 초기화 취소는 유지, 확인은 계획/진행을 해제하고 계약/함선/파트너를 남긴다. 기존 stop 규칙대로 검토 완료 표시(reviewed)는 false로 되돌려 재계산 전 검토를 요구한다.
4. 미션/관제의 **운항 백업·복원** → 저장 → 복원 파일 미리보기 → 취소/확인. 실제 개인 자료 대신 예시 계약으로 먼저 확인한다.

## 남은 범위

- **후속 기능**: 아카이브 필드별 출처 대조의 내부 이식, 운송 팁·가이드 본문, 안내/서비스/시네마의 미완료 하위 페이지. 기존 상세 자료 접근은 유지한다.
- **계획만 확정**: 운송사업부 시설의 입체 상위 메뉴 → 라운지/관제센터/추가 시설. 우주 항성계 지도와 별개다. 현재 시작 경로나 장면을 교체하지 않았다.
- **연출 담당**: 2.5D 인물 클릭 선택과 전체 튜토리얼/셔틀 연결. 이번 네 PR로 전체 연출이 완료된 것은 아니다. 미확정 영상/최종 음향은 연결하지 않는다.
- **사용자 보류**: 로그 수집 앱 개편. 기존 브라우저 파일 수신과 앱 자체를 구분한다.
- **사용자 제외**: 사용자 정의 적재 그리드 좌표/크기 직접 편집 UI. 기본 함선·그리드 켜기/끄기·기존 customShip 저장/복원 호환성은 유지한다.
- **실사용 미검증**: 실제 계정 로그인/기기 간 동기화, Windows 파일 권한/게임 실행 중 감시, 실제 게임 이미지의 OCR 정확도, 사용자 GPU/실물 모바일 및 장시간 성능. 지도/적재 고해상도 원본 추가는 별도 작업이다.
