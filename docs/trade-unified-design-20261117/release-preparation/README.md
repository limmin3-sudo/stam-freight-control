# 최종 범위 기준 배포 준비 — 2026-11-17

현재 작업본에 대한 배포 구성이다. 공개 릴리스/운영 연결 완료 기록이 아니며 새 배포 버전이나 통합 SHA를 임의 지정하지 않는다. 취소한 다섯 기능은 추가하거나 후속 과제로 되살리지 않는다.

## 포함할 내용

- 웹: 가격 중심 개인 관제·재고·정산, 계획 후보 비교/조건 전달, 계정별 탭 초안, 개인/함대 전환, 기존 초대 코드 공동 교역·함장 승인·정산, 공동 대화·공지·화물 배정·매매 게시판.
- 아카데미: 기존 자료와 학습→도구 연결. 공개 모집/오피서 설명을 삭제하고 초대 코드→참여 요청→함장 승인 흐름으로 한/영 수업을 수정했다. 기존 읽음 표시와 사례는 보존한다.
- 로그 앱1.5: 표시 요약·오버레이·전역 단축키·선택형 로컬 음성. 실제 거래 확정과 게임 입력 자동화는 포함하지 않는다.
- 기존 로그인·운항 저장·운송·개인 무역·승인 에셋/테마 보존. 별도 연출의 미승인 후보 자산을 자동 게시하지 않는다.

## 실제 남은 순서

1. 웹 변경과 필요한 추적/미추적 파일을 선별해 하나의 검토 가능한 커밋으로 보존한다. 전체 작업 폴더를 무조건 stage하지 않는다. 제외된 초안 코드는 별도 보존하고 공개 연결/패키지로 다시 넣지 않는다.
2. 이미 Windows에서 생성한 앱1.5 설치 파일/ZIP을 가져와 해시와 캡처를 확인한다. 마지막 시도는 아티팩트 다운로드403으로 미완료였다. `windows-source-check.json`에서13개 파일이 검증 커밋과 일치함을 재확인했으므로 동일 Windows 검사를 반복할 필요는 없다. 실제 마이크·게임 검증은 사용자 실환경 검증 제한으로 남긴다.
3. 운영 Firebase 규칙을 새로 읽어 동시 변경을 대조한 뒤, 공동 대화와 매매 게시판 규칙/게시판 인덱스만 기존 v1 위에 반영한다. 저장된 직전 운영 v1 대비 차이는 `retained-rules.patch`다. 이는 현재 원격 규칙의 실시간 확인을 대신하지 않는다. 기존 초대/정산 규칙을 새 기능으로 다시 구현하지 않는다. Functions·Blaze·UEX 토큰·VAPID가 필요하지 않다.
4. 확정 커밋으로 웹/앱 산출물을 게시하고, 앱 다운로드 버튼과 공개 페이지의 실제 버전·초기 로딩·유지 기능 연결만 확인한다. 원본 운항/교역 데이터는 이관·초기화하지 않는다.

## 완료된 근거 / 검증 한계

기존 타입·빌드·관련 단위8개·Firestore 에뮬레이터9흐름·합성2계정 브라우저 검증은 ../cancelled-review/에 있다. 이번 한/영 설명 변경 후 TypeScript 검사도 통과했다. 서버 배포를 새로 한 것이 아니므로 대화/게시판이 현재 공개 서비스에서 동작한다고 주장하지 않는다. 코드/규칙 검증과 운영 반영은 별개다.

이번 턴에서는 코드 설명 수정과 배포 범위/규칙 차이/앱 소스 일치를 정리했다. 커밋·푸시·운영 규칙 게시·웹/앱 릴리스·결제 변경은 하지 않았다.
