## 2026-11-17 최종 사용자 결정 — 추가 5개 항목 제외

검증 완료: 타입·빌드, 관련 단위 검사8개, 실제 Firestore 에뮬레이터9흐름, 합성2계정 Chromium/모바일 검사 통과. 결과: `docs/trade-unified-design-20261117/cancelled-review/`.

사용자가 **“5개 항목 전체 추가하지 않기”**로 확정했다. 함대 조직 생성·가입·공개 모집, 오피서 권한 위임 및 새 승인/정산 구조, 사이트 종료 후 가격 알림, 참여/정산 푸시 알림, UEX 가격 직접 제출은 이번 범위에서 제외한다. 무료 대체 구현·인증/소유자 답변·Blaze 승인 대기로 남기지 않으며 새 지시 없이 재개하지 않는다.

기존 로그인·운항 저장·개인 교역·초대 코드 공동 교역·함장 승인/정산은 유지한다. 개인/함대 화면 전환, 기존 가격 조회·관심가격 화면 내 확인, 별도 공동 대화·화물 배정·매매 게시판 작업도 보존한다. 제외 항목의 메뉴와 런타임 연결을 제거하고 서버 명령을 차단했다. 기본 Firebase 배포 설정에서 Functions를 제외하고 공개 패키지에서 무료 대체/UEX 제출 모듈과 푸시 워커를 제외했다. 기존 v1 규칙을 기반으로 보존 기능만 남겼으며 신규 조직/모집/위임 규칙은 제외했다. 초안 소스·자료는 보존하며 운영 데이터 자동 전환/삭제는 하지 않았다.

이번 정리는 작업본에만 적용했다. 운영 규칙·사이트·로그 앱 배포, 결제 변경, 커밋·푸시는 하지 않았다. 아래의 무료 대체 설계·구현·추가 인증 대기 기록은 이 결정 이전의 기록이다.

# 무역·아카데미·로그 앱 통합 구현 기록

2026-11-17, 기능 작업본. 공개 기준은 beta 3.0.0 `2c637afa21c9de904b3ad58b289215f3508670ec`이며 웹 통합 작업은 아직 미커밋·미배포다. 로그 앱 검증 소스만 별도 브랜치에 커밋·푸시했으며 공개 앱 릴리스는 하지 않았다. 기존 미커밋 기능·연출 후보 자산·운항 데이터를 보존했다. 이전 문서의 ‘구성만 작성’은 이전 단계 기록이다.

## 화면과 사용 흐름

- 기존 방·모니터·상단바·사이드바를 유지하고 같은 무역 관제실에서 개인/함대를 전환한다. 비활성 모드는 마운트와 구독을 해제한다.
- 개인 관제는 현재 작업/재고/기록·정산으로 나눴다. 가격표→실제 거래 입력→확인→장부의 기존 경로를 재사용한다. 잔여 매입, 부분 판매, 보관/회수, 원가, 실제 비용, 마감과 CSV를 보존했다.
- 계획실은 조건/후보를 나눠 표시한다. 최대 세 후보 비교, 활성 조건 해제, 첫 거래의 가격 하락/부분 판매 민감도, 담당자별 명시적 추천 조건 적용을 추가했다. 시장에서 품목/거점을 계획으로 넘길 수 있다.
- 계획 초안·개인/함대 보기·선택 교역·검색/정렬은 계정별 현재 탭에서 복원한다. 거래 확인창을 자동 복원하거나 실행하지 않는다. 목록 스크롤 위치는 저장하지 않는다.
- 함대는 참여 중인 교역/함대·모집/새 교역/알림, 선택 교역 안에서는 현재 작업/구성·배정/대화·공지/정산/기록/모집·권한으로 구성했다. 일반 참여자는 내 담당부터 확인하고 전체 담당을 펼쳐 볼 수 있다.
- 기존 초대 방식의 교역은 계속 조회·처리할 수 있다. 모집·권한에서 함장이 원장 사본을 남기고 서버 명령 방식으로 연결한다. 자동 일괄 변환은 없다.
- 아카데미 기존 세 방과 Hull B 사례를 유지하고 공동 교역 역할·시장 판단 수업에서 실제 도구로 연결한다. 새 둘러보기/튜토리얼과 시설 이동 연출은 이번 구현에 끼워 넣지 않았다.

## 서버와 계산

`server/freight-domain.mjs`는 인증된 UID와 현재 revision으로 명령을 처리한다. 함대 가입과 교역 참여는 별개다. 모집은 로그인 공개/승인된 소속 함대/초대 전용을 지원하고 공개 요약에 장부를 넣지 않는다. 오피서는 배정·보고 승인이 가능하며 비율 변경·최종 정산은 함장 전용이다. 실제 승인자를 원장에 남긴다. 미처리 보고와 남은 화물은 정산을 막는다.

v2 원장·보고·대화는 브라우저의 직접 쓰기를 막고 Cloud Functions 명령으로 처리한다. 요청 ID 영수증과 Firestore 트랜잭션으로 동일 요청 중복 적용 및 revision 충돌을 방어한다. v1 규칙/데이터 호환은 유지한다. 공식 STAM 이름은 운영자 UID가 지정되기 전에도 임의 선점할 수 없다.

함선별 배정은 Worker에서 제한 탐색하며 현재 공동 자금·공급·수요를 함께 차감한다. 다른 함선의 미래 판매대금은 사용하지 않는다. 미완료 배정이 있는 함선과 진행 화물은 새 자동 배정에서 방어한다. 계산 결과는 제안이며 사용자가 확인한 뒤 새 배정만 추가한다. 전역 최적해나 실제 재고 예약을 보장하지 않는다.

수동 적재는 기존 그리드 안의 위치 버튼·회전·되돌림·현재 탭 저장이다. 상자 식별자/수량/소유권 보존과 충돌·경계·지지를 검사한다. 그리드 자체 편집과 드래그 조작은 없다.

매입/판매 게시판은 로그인 이용자의 24시간 제안이며 실제 재고나 체결 자료로 채택하지 않는다. 디렉터리·모집·게시판은 한 번에 100개씩 읽고 커서 기반 더 읽기를 제공한다. 대화는 최근50개를 구독하고 이전 대화는100개씩 읽는다. 같은 시각의 대화도 문서 커서를 사용해 중복/누락을 방어한다. 검색은 불러온 목록 안에서 작동한다.

## 외부 보고·알림

UEX 공식 `POST /2.0/data_submit` 명세를 확인했다. 전송 화면은 내부 확정 관측값에서 한 품목·한쪽 가격을 골라 SCU 단위와 원본 이미지, 시각, 공개 범위를 검토한다. 기본은 테스트 모드이며 실제 공개 제출은 별도 선택이다. 앱 토큰은 서버 Secret Manager, 개인 secret와 원본 이미지는 해당 요청에서만 사용한다. 실제 외부 제출은 실행하지 않았다. 실패/시간 초과 후 자동 재전송하지 않는다.

관심 가격은 사용자가 서버에 조건 복사를 선택한다. 15분 주기의 작업은 최대 10계정/계정당 2품목을 순환하고 공개 원천의 패치/수정 시각/유효 가격을 확인한다. 같은 조건 충족을 반복 알리지 않으며 실패/오래된 자료로 기존 충족 상태를 해제하지 않는다. 계정 수와 브라우저 백그라운드 정책에 따라 도착이 늦어질 수 있다.

참여/거래 승인·정산·관심 가격 알림은 개인 알림함과 선택한 기기의 Web Push를 사용한다. 푸시에는 계정명·금액·전체 장부를 넣지 않는다. 실제 푸시 발송은 하지 않았다. 설정은 [CLOUD-SETUP.md](CLOUD-SETUP.md).

## 로그 앱 1.5 작업본

기존 로그 protocol 1을 유지하고 표시2/명령1 capability를 추가했다. 웹 운송/개인/함대 화면에서 켜면 제목과 최대 6줄만 인증된 루프백으로 전달한다. 전체 장부·원본 로그·Firebase 토큰은 표시 메시지에 넣지 않는다. 다른 탭의 표시 세션, 순번 재전송, 만료를 검사하고 연결 해제/웹 종료 후 내용을 지운다.

Windows WinForms 오버레이는 승인 패널 에셋·Barlow/SUIT를 재사용한다. 클릭 통과/조작 전환, 화면 위치 보정, Ctrl+Alt+O/P/W 기본 단축키 및 키 변경, 선택형 로컬 음성 명령을 추가했다. 한국어/영어 음성 엔진이 없으면 설치 안내를 표시한다. 음성·단축키는 조회/화면/표시만 조작하며 거래 확인과 게임 키 입력은 지원하지 않는다.

실제 Windows에서 컴파일·동봉 런타임·오버레이·전역 단축키·설정 복원·설치/덮어설치/제거까지 통과하고 설치 EXE와 ZIP을 생성했다. 검증 브랜치 `3ddc89b`만 푸시했으며 공개 다운로드는 바꾸지 않았다. 이 환경의 아티팩트 다운로드403으로 로컬 해시·캡처 시각 확인은 미완료다. 마이크·실제 게임/배타적 전체 화면 검증과 서명은 포함하지 않는다. [Windows 근거](operational-review/WINDOWS.md).

## 검증 결과

- 루트 자동 테스트 **290개**, control-room **172개** 통과. 원장/권한/동시 변경/알림 시세 조건/상자 충돌/공동 자금 배정/로그 서비스 보존을 포함한다.
- TypeScript 검사와 Vite 배포 빌드 통과. C#5/net48 컴파일 통과, 서버 Functions 모듈 import/export 확인.
- Firestore 에뮬레이터 v1 기존 흐름8항목과 v2 규칙·페이지 조회6항목 통과. 테스트 계정/프로젝트를 사용했고 운영 규칙은 변경하지 않았다. v2는 실제 Firestore 규칙과 도메인 명령을 검증했으며 Functions HTTP 인증·운영 인프라 실행 검증을 대신하지 않는다.
- 실제 앱 Chromium, 격리된 합성 2계정: 공개 모집→참여 승인→오피서 위임→출자 보고 승인→정산 권한 구분→공유 대화→390px 화면→개인/함대 전환 초안 및 운송 저장값 보존 통과. [결과](runtime-review/unified-browser.json), [규칙](runtime-review/server-rules.json).
- 실제 앱 개인 교역8흐름: 부분 매입·확인 취소·출발/도착·부분 판매·비용·보관/회수·37aUEC 최종 손익·한/영 검색·CSV·390px 영어·새로고침 보존. 실제 공개 UEX 이력은 요청 시에만 조회하고 재개방 시 캐시 사용을 확인했다. `docs/trade-workflow-audit-20261117/runtime-review/report.json`.
- 실제 HTTP 루프백: pairing/기존protocol/허용 origin/토큰/4KB 상한/세션 점유/순번/허용 명령/게임 로그 불변 검사 통과.

후속 실제 Functions/Auth/Firestore HTTP 에뮬레이터5항목도 통과했다. [결과](operational-review/http-emulator.json). 사용자는 이후 과금을 거절했다. Blaze는 승인 대기가 아니라 사용하지 않는 것으로 확정됐으며 Functions 배포를 차단했다. 새 함대 기능의 무료 대체 어댑터·보안 규칙은 재설계가 필요하다. 운영 Functions·인덱스·v2 규칙 및 Web Push/예약 작업 연결은 미완료다. [운영 연결 확인](operational-review/BILLING-AND-CONNECTION.md). 원천이 없는 서버 예측 수요·실제 로그의 자동 교역 확정은 구현 완료로 표시하지 않는다. 검색은 불러온 목록 기준이며 목록 스크롤 복원은 구현하지 않았다.
