# 통합 구현 명세 · 설계 기준

실제 구현 상태는 [구현·검증 기록](IMPLEMENTED.md)을 따른다.

이 문서는 한 기능씩 화면 아래에 붙이는 방식 대신, 공통 구조를 정한 뒤 한 묶음으로 완성하기 위한 명세다. 내부 구현은 의존 순서대로 진행하지만 사용자에게 매번 미완성 메뉴를 추가 배포하지 않는다. 기존 동작을 유지한 작업본에서 통합 검증한다. 이번 사용자 요청은 구성·구현 범위 확정이며 별도 배포 명령으로 해석하지 않는다.

## 공통 상태와 경로

- 모드: 개인/함대. 범위: 행성계 내부/행성계 간. 장소: 시장/계획/관제. 세 축을 서로 다른 값으로 유지한다.
- 모드 전환은 선택 화면만 바꾼다. 실제 실행 중인 개인 교역과 공동 교역은 각각 보존한다. 이전에 선택한 교역ID를 소유자별로 복원한다.
- 공통 보기 상태는 품목·거점 검색, 정렬·필터, 선택 행, 활성 상세, 목록 스크롤이다. 바뀌는 자료의 유효성은 복원 시 다시 확인한다.
- URL에는 공유 가능한 비민감 조건과 방/보기 식별자만 넣는다. 실제 자본·원가·인증·초대 비밀·계정 데이터는 공개 링크에 넣지 않는다.
- 시장→계획은 조회 조건/출처 시각을 전달한다. 계획→관제는 검토한 제안 사본을 전달한다. 관제→계획은 현재 잔여 화물과 제약을 참조하되 실제 장부를 덮어쓰지 않는다.
- 초안은 소유자 경계를 유지한다. 동일 계정의 다른 탭/기기에서 최신값이 달라지면 이전 확인창을 취소하고 비교한다. 읽기 상태와 실제 거래 실행을 구분한다.

함대 가입과 교역 참여를 별도 모델로 두므로 한 사용자가 여러 함대/교역에 속해도 같은 자금과 화물이 섞이지 않는다. 함대 탈퇴만으로 이미 출자한 원금이나 진행 화물을 삭제하지 않는다. 기존 교역의 접근·정산 처리와 탈퇴 제한을 연결한다.

| 조작 | 함대원 | 교역 오피서 | 교역 함장 |

| 모집 공개 범위·오피서 지정 | 불가 | 불가 | 가능 |

참여자 표시를 숨기는 것으로 권한 검증을 대신하지 않는다. 새 오피서 기능에서는 기존 ‘함장만 JSON 원장 작성’ 구조를 그대로 허용하면 권한별 변경을 분리하기 어렵다. 따라서 서버에서 인증/역할/명령/현재 revision을 검사하고 기존 `crew-trade` 계산으로 원장을 갱신하는 명령 처리 계층을 둔다. 클라이언트가 보내는 완성 원장/정산 합계는 정답으로 신뢰하지 않는다.

명령은 배정/멤버관리/보고승인/반려/비율변경/검토/확정 등으로 나누며 허용된 필드만 적용한다. 동일 요청 재전송은 같은 결과를 돌려준다. 확정 정산과 지급/수령 확인은 서로 다른 기록이다. 기존 schema1 교역은 백업·검증된 사본을 만든 뒤 명시적인 변환 경로로 새 구조에 연결한다. 임의 일괄 삭제나 데이터 손실형 교체는 없다.

서버 명령 실행 환경의 배포·요금제·권한 조건은 구현 준비 단계에서 확인한다. 필요한 권한/요금 설정 변경이 있다면 실제 설정과 이유를 확인한 뒤 사용자에게 구체적으로 안내한다. 새 서버 없이 브라우저 UI만으로 역할 위임을 완료했다고 표시하지 않는다.

## 함대 배정 엔진

입력은 참가 함선별 확인된 프로필/모듈·사용 가능한 용량·상자 제약·현재 위치, 공동 자금·예비금, 화물/시설/위법/위험 조건, 출발/도착 선호다. 후보는 기존 계획 엔진으로 만들고 공급·수요·자본을 공유하는 배정 단계에서 중복 차감한다.

결과에는 함선별 매입/배송/빈 이동, 예상 소요·비용, 남는 자본·화물·미배정 이유를 보여준다. 계산 예산과 취소/진행 표시를 두고 항상 전역 최적해라는 문구를 쓰지 않는다. ‘전체 이익 / 짧은 완료 / 적은 자본’ 목표는 명확히 선택한다. 배정 확정은 실제 매입과 구별한다. 도중의 수요 변화는 대체안을 제안하며 진행 기록은 보존한다.

## 로그 앱 연동

현재 앱은 공개 사이트 로그인과 기록을 사용하며 로컬에 또 하나의 웹 앱을 제공하지 않는다. 이 경계를 유지하고 표시·명령 통로를 확장한다.

1. 기존 로그 API와 프로토콜1 읽기를 유지한다. 새 표시·명령 기능은 capabilities/version 협상 후 활성화한다. 오래된 앱에는 기존 수주/연결 기능이 계속 동작한다.
2. 웹이 사용자가 선택한 현재 운송/교역의 최소 요약을 인증된 루프백 통로로 전달한다. 세션/소유자 세대·증가 순번·수신 시각으로 늦은 응답을 버린다. Firebase 토큰·전체 장부·원본 로그를 오버레이 메시지에 넣지 않는다.
3. C# 오버레이는 Node bridge가 전달한 요약을 그린다. STAM 공용 색/글꼴/승인 패널 에셋을 재사용한다. 클릭 통과/입력 모드와 트레이 복귀는 분명하게 구분한다.
4. 단축키·음성은 고정 허용 명령을 웹/앱에 전달한다. 임의 JavaScript·셸·게임 입력을 실행하지 않는다. 웹이 닫혀 있으면 자동 거래/추가 로그인 없이 연결 안내나 명시적 웹 열기를 제공한다.
5. 창/모니터 크기 변경 시 패널이 화면 밖에 남지 않게 보정한다. 앱 종료/업데이트 후 위치와 사용자 지정 단축키는 보존한다.
6. 음성은 사용자 활성화와 명시적 명령 인식 상태를 제공한다. 초기 구현은 Windows의 사용 가능한 로컬 음성 기능을 확인한다. 한국어/영어 언어 엔진이 없는 환경을 조용히 성공 처리하지 않는다.
7. 네이티브 오버레이는 일반/테두리 없는 창 환경을 우선 대상으로 검증한다. 게임 프로세스에 주입하거나 렌더링을 가로채는 방식으로 배타적 전체 화면 호환을 꾸미지 않는다.
8. 게임→로그는 읽기 전용으로 유지한다. 앱과 웹 사이의 표시·조회 조작이 가능해져도 게임 데이터 수정/키 입력 기능은 포함하지 않는다.

## 수동 적재 조정

기존 승인 함선 그리드와 상자 소유권/좌표 형식을 재사용한다. 자동 배치 결과를 복사한 미리보기 초안에서 이동·회전·되돌리기를 제공하고, 충돌/경계/쌓기 제약을 통과한 계획만 저장한다. 실제 운송·무역 선내 수량이나 소유권은 배치 편집으로 바꾸지 않는다. 키보드 이동/선택과 모바일의 선택 후 위치 지정도 지원하며 드래그만을 유일한 조작으로 두지 않는다. 그리드 자체 편집은 범위에 추가하지 않는다.

## 자료 수집·외부 연결

UEX 시세/터미널, SCMDB 미션 정의+동일ID Wiki 보완, 기존 함선/그리드/위치를 유지한다. 원천이 같은 다른 웹 도구를 독립적인 복수 검증으로 세지 않는다. 기존 일별 수집과 사용 중인 품목 갱신을 재사용하며 기록 시각/수집 시각/게임 패치를 분리한다.

가격 이력은 선택한 항목에만 조회하고 캐시한다. 관심 가격은 실제 원천 갱신 이벤트 기준으로 평가한다. 알림을 받았다고 시장 수요를 예약하거나 실제 거래를 생성하지 않는다. 호출 실패에는 마지막 자료와 시각을 보존하고 재시도/백오프·중복 요청 합치기를 적용한다.

외부 공개 보고는 원본·단위·근거·전송할 필드를 검토한 명시적 제출이다. API/토큰이 준비되지 않으면 내부 자료 검토와 외부 제출을 분리해 상태표에 남긴다. 공급자 인증/연결 설정은 실제 어댑터와 검토 화면을 만든 뒤 필요한 정보만 요청한다.

## 성능 기준

- 개인/함대 비활성 화면의 구독·무거운 차트·WebGL을 중지한다. 권한/알림 요약에 필요한 최소 구독만 유지한다.
- 계획/함대 배정은 Worker와 중단 신호를 사용한다. 입력 변경 시 이전 결과를 폐기하고 원가/개인 장부는 반복 계산하지 않는다.
- 가격·구성원·대화·기록은 제한 조회와 페이지 단위로 읽는다. 같은 시장 자료/계정 세션의 중복 fetch/구독을 만들지 않는다.
- 작은 SVG 그래프와 숫자 중심으로 유지한다. 정산/대화/가격 이력 라이브러리를 첫 로비 진입에 모두 적재하지 않는다.
- 클릭과 거래 승인에 네트워크 상태·중복 방지를 제공하되 계산/구독 지연 때문에 화면 전체가 반복 점멸하지 않게 한다.

## 한 묶음으로 구현하는 순서

1. 기능 대장/URL/상태/데이터·권한 계약을 기준으로 기존 모듈 재사용 경계를 고정한다. 외부 연결/네이티브 실행에 필요한 환경을 확인한다.
2. 공유 상태·시장/계획/개인 관제의 화면 구조를 만든다. 기존 계산/장부/백업과 모든 기존 진입점을 연결한다.
3. 함대 디렉터리·모집·교역 참여·서버 명령/역할을 구현하고 공동 관제·대화·배정·정산을 같은 모니터에 연결한다.
4. 아카데미의 관련 기능 링크·공동 교역/시장 판단 사례를 연결한다. 내용은 출처/가정과 함께 검토한다.
5. 앱 표시 프로토콜·오버레이·단축키·음성·알림을 연결하고 새 Windows 패키지/기존 웹 호환을 확인한다.
6. 아래 사용자 시나리오를 통합 실행하고 기능 대장의 각 행을 실제 진입점/검증 결과에 대응시킨다. 배포는 별도 승인된 시점에 같은 호환 묶음으로 수행한다.

## 완료 판정

| 사용자 흐름 | 확인할 결과 |
|---|---|
| 시장 조사→계획→부분 매입→이동→부분 판매→대안→마감 | 조건·선택 유지, 동일 입력 중복 없음, 원가/현금/남은 화물 보존 |
| 보유 화물만 판매·왕복·경유·혼합·수동 방문 | 기존 모드와 제약 전부 접근 가능, 신규 입력 구조로 기능 소실 없음 |
| 개인↔함대↔다른 교역 전환 | 소유자/교역별 초안·수량·원금 혼합 없음, 새로고침 복원 |
| 공개/함대원/초대 모집 | 공개 요약과 내부 장부 분리, 함대 가입/교역 참여 권한 분리 |
| 함장/오피서/함대원 | 실제 서버에서 위 표의 허용/거부를 강제, 오피서 최종 정산 불가 |
| 여러 함선 배정·수요 부족·취소·재계산 | 공급·수요·자금 중복 사용 없음, 담당/기록 보존, 미배정 이유 표시 |
| 공동 보고→승인→정산→지급/수령 | 한 번만 반영, 미처리/잔여 화물 차단, 센트 합계 보존, 확정 후 잠금 |
| 계정 교체·다른 기기·오프라인·충돌 | 기존 운송/무역 자료 보존, 잘못된 계정 요약/알림/오버레이 잔류 없음 |
| 웹↔앱·앱 재시작·오래된 버전 | 프로토콜 협상/회복, 현재 작업 표시, 버전 혼합에서 기존 로그 기능 유지 |
| 단축키·음성·오버레이 | STAM 조회/화면만 조작, 거래 확정/게임 입력 미실행, 지원 안 되는 환경 표시 |
| 실제 교역 로그/외부 제출 | 실제 입력 근거와 인증이 있는 범위만 연결 완료로 인정 |
| 아카데미·모바일·키보드·동작 줄이기 | 학습에서 실제 도구로 연결, 읽을 수 있는 크기, 원위치/포커스 복귀 |

기존 통과한 테스트를 무조건 반복 추가하지 않는다. 기존 테스트 재사용+변경 경계의 회귀+위 통합 흐름을 확인한다. 실제 게임이 불가능한 동안은 합성/보존 로그와 네이티브 검증을 구분하고 실게임 성공으로 보고하지 않는다. 구성 단계 이후 구현과 필요한 회귀 검증을 수행했다. 결과와 실환경 검증의 한계는 구현 기록에 남긴다.
