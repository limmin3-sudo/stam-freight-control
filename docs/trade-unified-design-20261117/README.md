## 화면 배치

### 공통 틀

기존 사이트 상단바·공간 사이드바·승인 모니터를 사용한다. 새 전역 내비게이션이나 장식용 콘솔 상단바를 추가하지 않는다. 모니터 내용 첫 줄은 장소 제목, 개인/함대 전환(관제), 활성 교역, 저장 상태다. 저장 상태를 누르면 기존 계정 저장/충돌 비교/백업으로 이어진다. 로그인과 로그 연결은 기존 상단바에서 유지한다.

큰 글자는 제목보다 **실제 수량·가격·다음 행동**에 배정한다. 본문/표는16px 기준, 보조 텍스트14px 이상, 핵심 수치는18~22px, 200% 확대/390px에서도 조작 가능하게 한다. 색만으로 위험·수익·선택 상태를 구분하지 않는다. 외형 변경이 필요한 신규 에셋은 별도 시안을 승인받고 적용하며, 구성 검토 HTML은 새 에셋 승인 요청이 아니다.

### 시장정보실

- 첫 줄: 한글/영문 품목·거점 검색, 보기 `품목 / 거래소 / 관심 목록 / 게시판`, 현재 패치·자료 시점.
- 왼쪽 약22%: 품목 목록. 중앙: 거래소별 **내가 사는 가격 / 내가 파는 가격**, 보고 공급·수요, 자료 연령, 시설 적합.
- 항목 선택 시 오른쪽 또는 같은 행 아래 상세를 연다. 좁은 화면에서는 상세 한 화면으로 전환하고 목록 위치로 돌아온다. 상세를 위해 가격표를 지나치게 좁히지 않는다.
- 작은 그래프는 가격 범위·차익·비교 가능 수량만 표시한다. 실제 시계열은 선택한 거래소 상세에서 펼친다. 날짜가 비는 구간의 가짜 추세를 만들지 않는다.
- 주요 행동은 `이 조건으로 계획`과 `관심 등록`. 직접 관측/OCR/CSV는 `내 시세 자료`로 통합한다. 주간 통계·현재 탭 조회·실제 보고 이력은 출처가 다른 표시다.
- 루트/시설 정보를 이 방 안에서 연결한다. 루트 정보실을 추가로 만들지 않는다.
- 거래 게시판은 가격표와 분리된 탭이다. 사용자 제안·실측 시세·체결된 거래를 혼합하지 않는다.

### 교역 계획실

- 사용 목적은 `새 교역 / 보유 화물 판매 / 목적지 가는 길`. 왕복·연속/직접 방문은 새 교역의 방식에서 선택한다. 기존5계산 모드는 유지한다.
- 첫 화면 기본값은 함선·현재 위치·자본 또는 화물과 위험/위법, 예비금이다. 자주 바꾸는 범위/목표 정렬은 결과 바로 위에 둔다.
- 데스크톱은 입력 약30%, 결과70%. 결과에서 후보 최대3개를 체크해 같은 조건의 비교 표를 연다. 큰 카드가 세로로 끝없이 이어지지 않도록 기본은 요약 행이다.
- 결과는 매입금·예상 순이익·예상 시간·시간당 수익·잔여 화물·자료 연령·제약 사유를 비교한다. 비용이 미입력이면 비용 미차감, 시간 미확인이면 시간당 값도 미확인이다.
- 조건은 `방문·경유 / 화물·시설 / 비용·시간 / 자료·제외` 네 묶음으로 펼친다. 활성 조건 요약과 개별 해제 제공. 결과0일 때 해제 가능한 조건을 제안하되 자동으로 위험/위법 조건을 풀지 않는다.
- 선정 후보 상세에서는 기존 지도·적재 함께 보기를 유지하며 구간별 손익·근거·함선 적합을 본다. 관제의 지도·적재는 기존처럼 필요할 때 연다. 관제로 인계하기 전 최종 참고가를 다시 확인하고 변경 영향을 표시한다.
- 함대 계획은 각 구성원의 함선·위치·가용량·공동 자금을 받아 배정안과 병목을 보여준다. 공급/수요는 함선끼리 공유하며 중복 배정하지 않는다. 제안은 검토 후 확정하고 실제 화물은 만들지 않는다.

### 개인 관제

```text
현재 교역  [개인 | 함대]                          저장 상태
현재 위치 · 기록상 현금 · 선내 SCU · 실현 손익
다음 작업: 목적지 / 매입·판매·이동 / 남은 수량    주요 행동
┌ 내 화물 25% ──────┬ 가격 비교 75% ────────────────────┐
│ 품목·수량·원가     │ 거래처·단가·수요·비교 수량·차익·시점 │
│ 품목 검색·선택     │ 선택 거래처 → 실제 거래 입력         │
└──────────────────┴───────────────────────────────────┘
[현재 작업] [재고·창고] [기록·정산]      지도 / 적재 / 담당자
```

가격 선택과 기존 수동 거래 입력을 **동일한 폼**으로 연결한다. 조회한 가격은 참고값이며 실제 수량·단가·합계는 수정 가능하다. 현재 거래 위치·소유권·상자 조건을 검사하고, 기록 후 잔액/화물 변화와 확인 버튼을 함께 보여준다. 거래 완료 후 선택 품목/검색/다음 작업이 이어진다.

현재 위치의 수요가 부족하면 남은 화물과 대체 판매처로 이어진다. 자동 이동/매입/판매는 없다. 비용·손실·자금 보정·취소 기록은 해당 상태에서 찾기 쉽게 하되 가격표를 덮는 상시 폼으로 늘어놓지 않는다.

### 함대 관제

개인 관제 아래에 긴 부가 패널을 붙이지 않고, 같은 모니터의 함대 모드로 전환한다. 해당 교역의 함장/오피서/함대원에 따라 첫 화면의 강조가 달라진다.

```text
함대 · 활성 교역   [개인 | 함대]               내 역할 · 연결 상태
내 다음 작업 / 담당 화물 / 보고 중인 수량        [거래 보고]
┌ 기본 작업 영역 ─────────────────┬ 진행·승인 요약 ───────┐
│ 내 품목과 필요한 거래처 가격     │ 승인 대기 · 문제 발생 │
│ 함장: 전체 현황/배정/병목        │ 자금 · 화물 · 진행률  │
└────────────────────────────────┴─────────────────────┘
[진행] [구성·배정] [대화·공지] [기록·정산]      모집·초대
```

- 일반 함대원: 내 담당 화물/다음 작업/보고 상태가 먼저다. 전체 현황은 별도 보기로 접근한다.
- 함장/오피서: 미처리 보고·참여 요청·문제 발생을 수로 표시한다. 승인 검토에는 보고 원문과 반영 후 장부 변화가 함께 나온다.
- 대화는 작업 옆 보조 영역으로 열고 닫는다. 보고·승인·정산은 구조화된 기록으로 남기며 채팅만으로 승인하지 않는다.
- 모집 화면에는 목적·일정·출발지/행성계·역할/함선 조건·모집 인원·공개 범위만 공개한다. 상세 자금·원가·대화·출자·지급은 참여 승인 후 해당 교역 권한으로 읽는다.
- 함대 가입과 개별 교역 참여는 별개다. 소속 함대원 전용 모집도 해당 교역 참여 승인을 거친다.
- 정산은 `검토 시작 → 남은 화물/보고 해소 → 원금·이익 확인 → 함장 확정 → 지급/수령 확인`. 미완료 항목에는 해당 작업으로 가는 버튼을 둔다. 마감 후 변경 불가/기존 보존 규칙을 유지한다.

### 아카데미

정보실은 검색과 출처, 교육실은 이해와 선택, 연구실은 비교 계산에 집중한다. 새로운 방을 늘리지 않는다.

- 정보실: 미션·함선·화물·시설/운송 규칙·현 패치 변경과 자료 시각. 아카이브 원천을 재사용한다.
- 교육실: `처음 시작 / 평판·미션 조합 / 경로·적재 / 개인 무역 / 함대 교역`. 짧은 핵심 설명 → 작은 예시 → 자세한 근거 → 관련 도구 열기. 교역 원가·수요·예비금·부분 판매·위험/위법·공동 정산을 포함한다.
- 연구실: 실제 Hull B 사례, 선택 계약 조합, 함선 변경과 방문 전략 비교. 추가로 교역/공동 배정 사례를 같은 비교 틀에 확장한다. 사례는 개인 장부로 자동 전송하지 않는다.
- ‘평판 올리기 좋은 조합’은 발주처·공통 거점·상자/적재·왕복 부담의 확인 가능한 근거로 설명한다. 실측 없는 평판 수치/최고 효율 순위는 만들지 않는다.
- 둘러보기/튜토리얼 연결 지점은 등록형으로 두고 신규 기능에서 재사용한다. 최종 전체 여정과 캐릭터 이동 연출은 시설 기능/연출 인계와 맞춘다.

### 로그 앱·오버레이·단축키·음성

- 기존 STAM 아이콘 하나와 로그 자동 탐색/트레이/재연결/공개 사이트 열기를 유지한다. 웹 기능을 오래된 별도 로컬 웹사이트로 복제하지 않는다.
- 앱 기본 화면: 로그 상태·웹 연결 상태·표시할 운송/개인 교역/함대 교역 선택·오버레이 on/off. 설정은 `화면 / 단축키 / 음성 / 알림`으로 묶는다.
- 오버레이는 작은 투사 패널: 목적지/다음 행동, 핵심 품목·수량, 가격 참고 시점, 보고/알림 수. 드래그 위치·크기·투명도·클릭 통과 전환·모니터 변경 보존. 큰 지도·3D·전체 장부는 웹에서 연다.
- 전역 단축키: 오버레이 표시/숨김, 입력 모드 전환, 현재 작업, 가격 조회, 웹 관제 열기. 충돌을 확인하고 사용자 지정한다. 게임 조작 키를 임의로 가로채지 않는다.
- 음성: 사용자가 켠 경우에만 STAM 명령을 인식한다. ‘현재 작업’, ‘가격 보기’, ‘오버레이 닫기’ 같은 제한된 명령 목록, 인식 결과와 실행 취소 가능한 화면 동작을 표시한다. 매입/판매/보고 승인/정산 확정은 음성으로 실행하지 않는다.
- 지원 음성 엔진/언어가 없으면 설치·언어 설정 안내와 단축키/버튼 대안을 제공한다. 별도 외부 음성 서비스로 음성을 전송하는 경로는 기본에 넣지 않는다.
- 앱이 켜져 있고 웹이 연결돼 있으면 최신 표시 상태를 전달한다. 웹 연결이 끊기면 마지막 수신 시각과 연결 끊김 표시; 최신이라고 주장하지 않는다. 앱 자체 종료 상태의 알림은 별도 서버 Web Push/OS 지원 경로가 필요하다.
- 로그에서 근거가 확인되는 거래 정보만 ‘확인할 제안’으로 받을 수 있다. 로그에 없는 가격·수량은 추정 체결하지 않는다. 실게임 로그의 교역 필드 확인 전에는 자동 거래 감지 완료로 표시하지 않는다.

## 세부 기능을 잃지 않는 위치

수동 상자 배치는 계획실의 `적재 상세 → 배치 조정` 안에 둔다. 확인된 함선 그리드에서만 상자를 움직이고 겹침·경계·지지·소유권을 검사한다. 기존 자동 배치로 돌아갈 수 있게 하며 사용자 정의 그리드 크기/좌표 편집은 추가하지 않는다. 무역 관제의 기본 가격 화면에는 이 편집을 상시 노출하지 않는다.

왕복·연속·직접 방문·재투자·수급 대기·드라이브/시간·시설/세력 제외·혼합 상자·화물에 맞는 함선 찾기는 모두 계획실 세부 조건/결과에 남는다. 창고·태그·보관/회수·외부 자본 보정·비용/손실·이전 장부·되돌림·JSON/CSV는 관제의 재고/기록에 남는다. 즐겨찾기·가격 이력·개인 관측·OCR/CSV·시세 재확인은 시장정보와 관제에서 같은 기능으로 연결한다.

## 스마트폰과 접근성

390px에서는 요약→현재 작업→가격/배정 목록→상세 순서로 한 열을 사용한다. 개인/함대 전환은 유지하고 3열 축소판을 만들지 않는다. 표 행은 핵심 수치가 함께 보이는 카드로 바꾼다. 터치 목표44px, 키보드 포커스와 Escape 복귀, 동작 줄이기, 금빛 강조와 텍스트 상태를 함께 쓴다. 메뉴/상세를 닫아도 입력·필터·선택이 남는다.

## 구현 범위와 준비가 필요한 연결

이번 구성에는 전체 기능을 배치한다. 웹+로그 앱은 하나의 호환 명세와 통합 검증을 기준으로 구현한다. 다음 조건을 기능 삭제나 ‘완료’로 감추지 않는다.

| 항목 | 구성상 위치 | 실제 연결에 필요한 조건 |
|---|---|---|
| 외부 공개 시세 제출 | 시장 / 내 관측자료 | 공급자 제출 API·권한·인증·공개할 필드 검토. 프런트에 서비스 비밀키를 넣지 않음 |
| SCT 인증 API/MCP | 데이터 어댑터 | 유효한 인증/허용된 API. UEX 기반 계산은 계속 사용 가능 |
| 공급자와 동일한 예측 수요 | 계획 / 수급 가정 | 사용할 수 있는 원천/정의. 현재 보고·주간 평균·사용자 가정과 구분 |
| 실제 교역 로그 감지 | 관제 / 확인할 제안 | 해당 패치 실제 Game.log의 확인 가능한 거래 필드. 없는 값을 임의 생성하지 않음 |
| Windows 오버레이·음성 | 로그 앱 | 네이티브 빌드/OS 언어 엔진/화면 모드 확인. 배타적 전체 화면 지원을 미리 보장하지 않음 |
| STAM 대표 함대 운영 권한 | 함대 디렉터리 | 초기 운영자 계정 지정. 명칭만 입력한 이용자가 공식 함대를 소유할 수 없게 함 |

실행 명세에는 각 기능의 완료 조건을 둔다. 사용자 화면에는 아직 연결되지 않은 서비스를 작동하는 메뉴처럼 진열하지 않는다. 전체 기능 대장에는 필요한 조건과 진행 상태를 계속 남긴다.
