## 2026-11-17 최종 사용자 결정 — 추가 5개 항목 제외

사용자가 **“5개 항목 전체 추가하지 않기”**로 확정했다. 함대 조직 생성·가입·공개 모집, 오피서 권한 위임 및 새 승인/정산 구조, 사이트 종료 후 가격 알림, 참여/정산 푸시 알림, UEX 가격 직접 제출은 이번 범위에서 제외한다. 무료 대체 구현·인증/소유자 답변·Blaze 승인 대기로 남기지 않으며 새 지시 없이 재개하지 않는다.

기존 로그인·운항 저장·개인 교역·초대 코드 공동 교역·함장 승인/정산은 유지한다. 개인/함대 화면 전환, 기존 가격 조회·관심가격 화면 내 확인, 별도 공동 대화·화물 배정·매매 게시판 작업도 보존한다. 제외 항목의 메뉴와 런타임 연결을 제거하고 서버 명령을 차단했다. 기본 Firebase 배포 설정에서 Functions를 제외하고 공개 패키지에서 무료 대체/UEX 제출 모듈과 푸시 워커를 제외했다. 기존 v1 규칙을 기반으로 보존 기능만 남겼으며 신규 조직/모집/위임 규칙은 제외했다. 초안 소스·자료는 보존하며 운영 데이터 자동 전환/삭제는 하지 않았다.

이번 정리는 작업본에만 적용했다. 운영 규칙·사이트·로그 앱 배포, 결제 변경, 커밋·푸시는 하지 않았다. 아래의 무료 대체 설계·구현·추가 인증 대기 기록은 이 결정 이전의 기록이다.

# 운영 연결 확인 — 2026-11-17

실제 Google Cloud API 조회 결과 `stam-freight-control`의 결제 연결은 꺼져 있다. Cloud Functions와 Secret Manager 조회의403은 `SERVICE_DISABLED`이며, 계정에 함수 생성/조회·API 활성화·Firestore 인덱스 생성·규칙 게시 권한은 이미 있다. 추가 관리자 권한을 요청할 문제가 아니다. [원본을 비밀값 없이 요약한 결과](server-readiness.json).

새 함대 명령 서버와 예약 가격 알림에는 Firebase Blaze의 사용량 기반 과금 연결이 필요하다. 결제 수단을 임의로 연결하거나 유료 요금제로 전환하지 않았다. 사용자에게 전환 방향, 공식 STAM 함대 소유자 아이디, UEX 앱 토큰 보유 여부를 질문했고 답변 전까지 해당 운영 변경은 대기한다. 기존 계정/운송/개인 무역/v1 공동 교역 데이터와 운영 규칙은 변경하지 않았다.

## 비용과 설정 범위

- Blaze에는 서비스별 무료 할당량이 있지만 월0원을 보장할 수 없다. 실행량 외에도 빌드/이미지 보관/이벤트·예약 작업/네트워크가 과금 대상이 될 수 있다.
- 현재 코드는 명령 서버 최대3인스턴스/256MiB/60초, 외부 제출 최대1/256MiB/40초, 푸시 최대2인스턴스, 가격 확인 최대1/256MiB/180초로 제한한다. 상시 최소 인스턴스를 지정하지 않았다.
- 가격 확인은15분 주기, 실행당 최대10계정×2품목이며 API 동시성4/요청8초 제한이다. 사용자가 서버 알림을 켠 조건만 대상으로 한다.
- 인스턴스 수 제한은 금액 상한이 아니다. Cloud Billing 예산 알림도 자동 비용 차단 기능이 아니다.
- Firebase 콘솔의 프로젝트 요금제에서 Blaze와 본인 결제 계정을 연결한 뒤, 필요 서버 API/Functions/인덱스/v2 규칙을 같은 호환 묶음으로 연결한다. API 권한을 새로 넓힐 필요는 없다.
- UEX 앱 토큰은 Secret Manager에 보관하고 개인 Secret Key는 이용자 제출 요청에서만 사용한다. 키를 채팅이나 Git에 올리지 않는다. `server/cloud/.env.example`은 비밀값 없는 설정 예시다.

공식 안내: [Firebase 요금제](https://firebase.google.com/pricing), [프로젝트 요금제/사용량](https://console.firebase.google.com/project/stam-freight-control/usage/details), [Google Cloud 예산 알림](https://cloud.google.com/billing/docs/how-to/budgets).

요금제 연결 전 가능한 검증은 마쳤다. 실제 Functions/Auth/Firestore 에뮬레이터의 HTTP 인증·권한·동시 중복 승인·rev 충돌·삭제한 계정의 이전 토큰 거부를 확인했다. [결과](http-emulator.json). 운영 함수 배포/외부 UEX 제출/실제 Web Push 수신을 대신하는 결과는 아니다.
