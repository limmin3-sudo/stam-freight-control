## 2026-11-17 최종 사용자 결정 — 추가 5개 항목 제외

사용자가 **“5개 항목 전체 추가하지 않기”**로 확정했다. 함대 조직 생성·가입·공개 모집, 오피서 권한 위임 및 새 승인/정산 구조, 사이트 종료 후 가격 알림, 참여/정산 푸시 알림, UEX 가격 직접 제출은 이번 범위에서 제외한다. 무료 대체 구현·인증/소유자 답변·Blaze 승인 대기로 남기지 않으며 새 지시 없이 재개하지 않는다.

기존 로그인·운항 저장·개인 교역·초대 코드 공동 교역·함장 승인/정산은 유지한다. 개인/함대 화면 전환, 기존 가격 조회·관심가격 화면 내 확인, 별도 공동 대화·화물 배정·매매 게시판 작업도 보존한다. 제외 항목의 메뉴와 런타임 연결을 제거하고 서버 명령을 차단했다. 기본 Firebase 배포 설정에서 Functions를 제외하고 공개 패키지에서 무료 대체/UEX 제출 모듈과 푸시 워커를 제외했다. 기존 v1 규칙을 기반으로 보존 기능만 남겼으며 신규 조직/모집/위임 규칙은 제외했다. 초안 소스·자료는 보존하며 운영 데이터 자동 전환/삭제는 하지 않았다.

이번 정리는 작업본에만 적용했다. 운영 규칙·사이트·로그 앱 배포, 결제 변경, 커밋·푸시는 하지 않았다. 아래의 무료 대체 설계·구현·추가 인증 대기 기록은 이 결정 이전의 기록이다.

# 무료 운영으로 전환 — 기존 Functions 인계는 아래 이력

사용자가 과금을 거절했으므로 아래 Blaze 연결/Functions 배포 순서는 현재 실행 지침이 아니다. `deployment-policy.json`의 free-only와 Functions predeploy 차단을 적용했다. Firebase Spark·기존 계정/운항/교역 저장을 유지한다.

무료 대체에서는 공개 모집·함대 구성과 거래 권한을 구조화된 Firestore 문서 및 보안 규칙으로 검증해야 한다. 현재 `payload` JSON 원장에 오피서 쓰기를 열면 정산과 구성원 권한까지 바꿀 수 있으므로 단순 권한 완화로 대체하지 않는다. 보고 원본·승인 이벤트·정산·구성원 권한 분리와 원자적 처리/중복 방어가 필요하며 아직 구현 완료가 아니다. 웹/로그 앱 모두 종료 후 예약 알림은 무료 실행 주체가 마련되기 전까지 미연결로 유지한다. 무료 서비스 사용 한도 소진은 유료 자동 전환 대신 오류/재시도로 처리한다.

비용 정책 검사는 저장소의 배포 경로용이며 클라우드 계정 수준의 잠금은 아니다. 로컬 에뮬레이터와 기존 Functions 소스는 비교·회귀 검증용으로 보존한다. UEX 조회는 계속 사용하며 공개 제출 인증은 별개다.

# 신규 서버 연결 인계 — 아직 운영 적용 안 함

이 문서는 구체적인 구현에 필요한 운영 설정이다. 이번 작업에서 배포/실제 UEX 제출/푸시 발송은 수행하지 않았다. 과거 v1 공동 교역 규칙의 운영 연결은 이미 완료됐으므로 반복할 작업이 아니다. 새 오피서·모집·함대·알림은 v2 함수와 규칙을 함께 검증한 뒤 공개한다.

2026-11-17 실제 조회 결과: 배포 권한은 충분하지만 결제 연결이 없고 Functions/Secret Manager API가 비활성화돼 있다. 사용량 과금 전환을 사용자에게 확인 중이며 임의 전환하지 않는다. [현재 차단 조건과 비용](operational-review/BILLING-AND-CONNECTION.md). 실제 Functions/Auth/Firestore HTTP 검사는 에뮬레이터5항목 통과, 운영 서버 검사는 별도다.

## 구현 파일

- `firebase.json`, `firestore.rules`, `firestore.indexes.json`
- `server/cloud/index.mjs`, `server/cloud/package.json`, lockfile
- `server/freight-domain.mjs`, `server/price-alerts.mjs`, `uex-submit.mjs`
- `scripts/prepare-cloud.mjs`가 Functions 전용 `lib`에 서버 의존 파일만 복사한다. 소스 전체/원본 로그/자격증명을 포장하지 않는다.

Node22, Firebase Functions2세대, us-central1. Firebase Functions/Cloud Run/Eventarc/Cloud Scheduler/FCM 및 요금제의 사용 가능 상태를 운영 프로젝트에서 확인해야 한다. 에뮬레이터 통과만으로 요금제·HTTP 인증·실제 배포 완료로 취급하지 않는다.

## 운영자가 지정할 값

| 값 | 용도 | 보관 |
|---|---|---|
| `STAM_OWNER_UID` | 공식 STAM 함대를 생성할 실제 계정 UID | Functions 환경 설정. 이름/이메일을 UID 대신 쓰지 않음 |
| `STAM_PUSH_VAPID_PUBLIC` | 브라우저 FCM 웹 푸시 공개 키 | Firebase 콘솔 프로젝트 설정→Cloud Messaging→Web Push certificates. 개인 키를 웹에 넣지 않음 |
| `STAM_UEX_REPORTS_ENABLED=true` | 검토한 외부 보고 제출 기능 활성화 | Functions 환경 설정 |
| `UEX_API_TOKEN` | UEX의 승인된 앱 Bearer token | Firebase Secret Manager. Git·브라우저·문서·채팅에 토큰을 적지 않음 |
| `STAM_PRICE_ALERTS_ENABLED=true` | 15분 주기 관심 가격 확인 활성화 | Functions 환경 설정. 미설정 시 예약 함수는 조회하지 않음 |

개인 UEX `Secret Key`는 이용자가 제출 화면에 직접 입력하며 서버에 보관하지 않는다. 외부 API의 개인 권한과 앱 토큰은 서로 다른 값이다. 신규 데이터러너가 요구받는 원본 스크린샷을 검토 화면에서 선택한다.

함수별로 필요한 설정이 다르므로 UEX 인증이 없으면 `submitUexReport`까지 배포할 이유가 없다. 핵심 `freight`와 필요한 이벤트 함수만 선택 배포할 수 있다. 비밀값은 별도 보안 설정 단계에서 지정한다.

## 운영 반영 순서

1. 기존 v1 교역/개인 운항과 새 규칙의 호환 검증 결과를 대조하고 현재 운영 ruleset을 보관한다.
2. `npm ci --prefix server/cloud`와 `node scripts/prepare-cloud.mjs` 후 필요한 함수·인덱스를 배포한다. 인덱스가 준비됐는지 확인한다. 이 단계의 실제 배포는 이번 턴에서 수행하지 않았다.
3. v2 rules와 Functions를 같은 호환 묶음으로 확인한다. 웹을 먼저 공개해 존재하지 않는 서버에 새 교역을 만들게 하지 않는다.
4. 운영 테스트 계정에서 `freight` capabilities/인증 거부/함대·교역 생성/참여/오피서 승인/최종 정산 거부/중복 요청/revision 충돌을 확인한다. 실제 원장 대신 시험 교역을 사용한다.
5. 공식 소유자가 STAM을 개설한다. `STAM_OWNER_UID`를 넣는 것만으로 함대 문서가 자동 생성되는 것은 아니다. 임의 일반 이용자는 공식 이름을 선점할 수 없다.
6. 선택형 푸시는 본인 시험 기기로 허용/해제/브라우저 종료 후 수신·클릭·계정 경계를 확인한다. UEX는 명시적으로 승인된 테스트 제출부터 확인하고 실제 공개 자료에 시험 가격을 올리지 않는다.
7. Windows 앱1.5의 오버레이/단축키와 설치/업데이트/제거는 검증 서버에서 통과했다. [근거·다운로드 제한](operational-review/WINDOWS.md)을 확인하고 운영 서버 연결 후 웹·로그 앱 공개 배포를 마감한다. 실제 마이크·게임은 미검증이다.

알림 조건은 최대50개, 한 실행당 최대10계정×2품목, 조회 동시성4와 요청8초 제한이다. 연결에 실패하면 기존 장부/관측값을 변경하지 않는다. 이용자가 가격 조건을 바꾸면 ‘현재 조건으로 서버 알림 갱신’을 다시 눌러 서버 사본을 갱신한다. 예약 작업/푸시는 장부를 수정하거나 게임 거래를 실행하지 않는다.
